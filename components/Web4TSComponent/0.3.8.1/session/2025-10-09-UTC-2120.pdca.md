**2. Implemented findProjectRootFrom() Method**
```typescript
private findProjectRootFrom(startDir: string): string {
  let currentDir = path.resolve(startDir);
  
  // First priority: package.json + components/ directory
  // This is MORE SPECIFIC and correctly identifies test/data or project root
  while (currentDir !== path.dirname(currentDir)) {
    if (existsSync(path.join(currentDir, 'package.json')) &&
        existsSync(path.join(currentDir, 'components'))) {
      return currentDir;
    }
    currentDir = path.dirname(currentDir);
  }
  
  // Fallback: Look for .git
  currentDir = path.resolve(startDir);
  while (currentDir !== path.dirname(currentDir)) {
    if (existsSync(path.join(currentDir, '.git'))) {
      return currentDir;
    }
    currentDir = path.dirname(currentDir);
  }
  
  return path.resolve(startDir);
}
```

**Discovered Issue:**
The test is now working correctly and exposing a REAL bug: The generated CLI script's bash symlink resolution logic resolves to the `scripts/` directory instead of the component directory. The script uses `$(dirname "$SCRIPT_FILE")` after following symlinks, but relative symlinks confuse the resolution.

**Bug Details:**
```bash
# Current behavior (WRONG):
SCRIPT_DIR=/Users/.../test/data/scripts
COMPONENT_PATH=/Users/.../test/data/scripts  # Should be .../AutoPromoTest/0.1.0.0

# Root cause: After following symlink chain, final SCRIPT_FILE is "./autopromotest.sh"
# which is still relative to scripts/, so dirname gives "." = scripts/ directory
```
