### Phase 1.5: Radical OOP vs Functional Pattern Analysis

**Reference**: `components/Web4TSComponent/0.3.18.1/session/2025-11-06-UTC-0030.functional-vs-radical-oop-analysis.pdca.md`

#### Radical OOP Principles (The Web4 Way)

1. **Empty Constructor**: No logic in constructor, all initialization in `init()`
2. **Scenario Initialization**: All config via `init(scenario)`, model-driven
3. **Model-Driven State**: All state in `this.model`, not passed as parameters
4. **Method Chaining**: All methods return `this` for fluent API
5. **Context as Model State**: `this.model.context`, not parameters
6. **Path Authority**: Paths from model or CLI back-reference, not `process.cwd()`
7. **CLI Back-Reference**: Component has `this.cli` for path authority
8. **No Helper Functions**: Encapsulate logic in methods, not standalone functions
9. **Single Source of Truth**: Derive values, don't store duplicates
10. **DRY Methods**: Encapsulate repeated patterns in methods (e.g., `getTarget()`)

#### "Functional Shit" Patterns (What to Eliminate)

1. ❌ **State as Parameters**: Passing `componentRoot`, `projectRoot`, etc. as params
2. ❌ **`process.cwd()`**: Using current working directory for path resolution
3. ❌ **Standalone Helper Functions**: Functions outside classes
4. ❌ **No Method Chaining**: Methods return `void` instead of `this`
5. ❌ **Logic in Constructor**: Initialization logic in constructor
6. ❌ **Global State**: Using environment variables or process state
7. ❌ **Imperative Loops**: `for` loops instead of declarative methods
8. ❌ **No CLI Back-Reference**: Component doesn't know its CLI
