## PLAN

### Problem Statement

**Current Behavior**:
- Components have `toScenario()` method that returns Scenario object in memory
- No automatic file generation
- No persistent scenario files in component directories
- **No explicit dependency tracking** - generated components don't record which Web4TSComponent version created them
- Manual work required to save component scenarios

**Desired Behavior**:
- After component creation, automatically generate scenario file in component root
- **CRITICAL**: Filename is `{GeneratedComponentName}.component.json` (e.g., `IdealMinimalComponent.component.json`)
- **CRITICAL**: File content is **Web4TSComponent's scenario**, NOT the generated component's scenario
- **CRITICAL**: File is a **symlink** to Web4TSComponent's `{uuid}.scenario.json` in central storage
- Records which Web4TSComponent version created this component
- Can be used for:
  - **Dependency tracking** - know which Web4TSComponent version is required
  - **Compatibility verification** - check if regeneration needed
  - **Delegation context** - provides the "via Web4TSComponent vX.Y.Z.W" information
  - Build/upgrade decisions

**Example**: `IdealMinimalComponent 0.3.19.1` should have:
```
/Users/Shared/Workspaces/temp/Web4Articles/components/IdealMinimalComponent/0.3.19.1/IdealMinimalComponent.component.json
  → symlink to ../../Web4TSComponent/0.3.19.1/{uuid}.scenario.json
```

**Architecture**:
1. **Filename**: `IdealMinimalComponent.component.json` (matches generated component name)
2. **Content**: Web4TSComponent scenario JSON (dependency/creator info)
3. **Storage**: Central scenario in Web4TSComponent directory (`{uuid}.scenario.json`)
4. **Link**: Symlink from generated component to central storage

**Why Symlink (not copy)**:
1. **Single Source of Truth**: Web4TSComponent scenario stored once
2. **Automatic Updates**: If Web4TSComponent scenario changes, all links reflect it
3. **Storage Efficiency**: No duplication of scenario data
4. **Linked Data Pattern**: Web4 principle - link, don't copy

**Why Web4TSComponent Scenario (not IdealMinimalComponent)**:
1. **Dependency Documentation**: Generated component DEPENDS on Web4TSComponent that created it
2. **Version Compatibility**: `idealminimalcomponent info` shows "via Web4TSComponent v0.3.19.1" - this comes from dependency
3. **Regeneration Decision**: If Web4TSComponent upgrades, need to know which components to regenerate
4. **Delegation Contract**: Generated component delegates to Web4TSComponent - scenario IS the contract

### Design Decision

**Goal**: Simple, non-invasive scenario file generation for component metadata

**Requirements**:
1. Generate `ComponentName.component.json` in component root
2. Called automatically after component creation
3. Does NOT require storage service (too complex for infrastructure)
4. Uses direct file write (like User pattern)
5. No symlinks (component root IS the authoritative location)
6. Filename format: `{ComponentName}.component.json`

**Selected Pattern**: **User Component Pattern** (simple file write)

**Why NOT Unit Pattern**:
- Too complex for Web4TSComponent (infrastructure component)
- Central storage not needed for component metadata
- UUID folders overkill for single component identity
- Symlinks add unnecessary complexity

### Implementation Plan

#### Step 1: Add `saveWeb4TSComponentScenario()` Method
**Location**: `DefaultWeb4TSComponent.ts`

**CRITICAL**: 
1. Save **Web4TSComponent's** scenario to **Web4TSComponent's directory** as `{uuid}.scenario.json`
2. Create **symlink** from generated component directory with name `{ComponentName}.component.json`

```typescript
/**
 * Save Web4TSComponent scenario and create symlink in generated component
 * Records which Web4TSComponent version created this component (dependency tracking)
 * Provides "via Web4TSComponent vX.Y.Z.W" information for delegation context
 * @pdca 2025-11-10-UTC-2349.component-scenario-file-generation.pdca.md
 * @cliHide
 */
private async saveWeb4TSComponentScenario(componentName: string, targetComponentRoot: string): Promise<void> {
  const fs = await import('fs/promises');
  
  // Generate Web4TSComponent's own scenario (NOT the generated component's)
  const scenario = await this.toScenario();
  const scenarioJson = JSON.stringify(scenario, null, 2);
  
  // Save to Web4TSComponent's directory (central storage)
  const scenarioFilename = `${this.model.uuid}.scenario.json`;
  const scenarioPath = path.join(this.model.componentRoot, scenarioFilename);
  await fs.writeFile(scenarioPath, scenarioJson, 'utf8');
  
  // Create symlink in generated component's directory
  const linkFilename = `${componentName}.component.json`;
  const linkPath = path.join(targetComponentRoot, linkFilename);
  
  // Calculate relative path from link to scenario
  const relativePath = path.relative(path.dirname(linkPath), scenarioPath);
  
  // Create symlink
  await fs.symlink(relativePath, linkPath);
  
  console.log(`   📄 Created dependency: ${linkFilename} → ${scenarioFilename}`);
  console.log(`      Component created by: Web4TSComponent v${this.model.version.toString()}`);
}
```

**Key Points**:
- Generates **Web4TSComponent's scenario** (via `this.toScenario()`)
- Saves to **Web4TSComponent's directory** as `{uuid}.scenario.json`
- Creates **symlink** in generated component directory
- Link filename: `{ComponentName}.component.json` (e.g., `IdealMinimalComponent.component.json`)
- Link target: Relative path to Web4TSComponent's scenario file
- Documents the dependency/creator relationship via symlink

### File Structure

**Central Storage** (Web4TSComponent's scenario):
```
components/Web4TSComponent/0.3.19.1/{uuid}.scenario.json
```

**Symlink** (in generated component directory):
```
components/IdealMinimalComponent/0.3.19.1/IdealMinimalComponent.component.json
  → ../../Web4TSComponent/0.3.19.1/{uuid}.scenario.json
```


**File Architecture**:
```
components/
├── Web4TSComponent/
│   └── 0.3.19.1/
│       └── a1b2c3d4-e5f6-7890-abcd-ef1234567890.scenario.json  ← CENTRAL STORAGE
│
└── IdealMinimalComponent/
    └── 0.3.19.1/
        └── IdealMinimalComponent.component.json  ← SYMLINK
            → ../../Web4TSComponent/0.3.19.1/a1b2c3d4-e5f6-7890-abcd-ef1234567890.scenario.json
```

**Key Insight**: 
- **Filename**: Matches generated component (`IdealMinimalComponent.component.json`)
- **Content**: Web4TSComponent scenario (via symlink)
- **Storage**: Single source of truth in Web4TSComponent directory
- **Pattern**: Linked Data - link, don't copy!

### Benefits

1. **Explicit Dependency Tracking**: Every generated component records its creator via symlink
2. **Single Source of Truth**: Web4TSComponent scenario stored once, linked many times
3. **Linked Data Pattern**: Web4 principle - link, don't copy
4. **Version Compatibility**: Can check if Web4TSComponent upgrade requires regeneration
5. **Delegation Source**: Provides the "via Web4TSComponent vX.Y.Z.W" information
6. **Build Requirements**: Know which Web4TSComponent version is needed for builds
7. **Reproducibility**: Can recreate component with exact same infrastructure version
8. **Upgrade Decision**: Compare scenario version with current Web4TSComponent to decide if regeneration needed
9. **Storage Efficiency**: No duplication - one scenario, many links
10. **Automatic Updates**: If Web4TSComponent scenario updates, all links reflect it

### Risks

1. **File Pollution**: Every component gets extra file
   - **Mitigation**: Single file per component, clear naming convention
2. **Stale Data**: File might not reflect runtime state
   - **Mitigation**: Generated at creation time only, read-only after
3. **Duplicate Info**: Version already in directory name
   - **Mitigation**: Scenario contains MORE than just version (UUID, model, owner)
