## 🎯 Problem Statement

**Context**: The `on` command dynamically loads components (e.g., `web4tscomponent on Unit latest links`).

**Current Behavior**:
- ✅ Works for IdealMinimalComponent (no CLI back-reference needed)
- ❌ **FAILS** for Unit 0.3.19.1 with error:
  ```
  ❌ CLI Error: Unit: CLI back-reference not set. Call setCLI() from UnitCLI.
  ```

**Root Cause Analysis**:

The `DefaultCLI.loadComponent()` method (lines 324-369) creates and initializes components dynamically:

```typescript
const instance = new ComponentClass().init({ model: { ... } });
```

**Missing Step**: Does NOT call `.setCLI(this)` before `.init()`.

**Why This Breaks**:
1. Unit 0.3.19.1 migrated to Radical OOP with CLI back-reference for path authority
2. Methods like `from()`, `link()`, `definition()` call `this.getCLI().model.projectRoot`
3. `getCLI()` throws error if CLI not set
4. When loaded via `on`, no CLI is set → error

**Impact**:
- 🔴 **Critical**: ALL components using CLI back-reference fail with `on` command
- 🔴 **Scope**: Unit 0.3.19.1, future components with path authority pattern
- 🔴 **Blocking**: PDCA 2025-11-10-UTC-2349 (component scenario file generation)

**Goal**: Fix `loadComponent()` to set CLI back-reference for all dynamically loaded components.

**Success Criteria**:
- [ ] `web4tscomponent on Unit latest links` works (no CLI back-reference error)
- [ ] `web4tscomponent on Unit latest from <file>` works (path authority functional)
- [ ] IdealMinimalComponent still works (backward compatibility)
- [ ] All delegated methods accessible via `on` command

### Phase 2: Solution Design

**Fix Location**: `components/Web4TSComponent/0.3.19.1/src/ts/layer2/DefaultCLI.ts`

**Target Method**: `loadComponent()` (lines 324-369)

**Current Code** (line 345):
```typescript

  model: { ... }
});
```

**Proposed Fix** (insert after line 342, before init):
```typescript
// ✅ STEP 1: Create component instance
const instance = new ComponentClass();

// ✅ STEP 2: Set CLI back-reference BEFORE init() (if component supports it)
// @pdca 2025-11-11-UTC-1000.cli-backref-on-command.pdca.md - CLI back-reference for path authority
// CRITICAL: Must be set before init() calls updateModelPaths()
// Components without setCLI() safely ignore this (duck typing)
if (typeof instance.setCLI === 'function') {
  instance.setCLI(this);
}

// ✅ STEP 3: Initialize component (will use CLI for path authority if needed)
await instance.init({
  model: { ... }
});
```

**Why This Works**:
1. ✅ Duck typing: Only calls `setCLI()` if method exists
2. ✅ Backward compatible: IdealMinimalComponent (no setCLI) works unchanged
3. ✅ Forward compatible: Unit 0.3.19.1 gets CLI back-reference
4. ✅ Follows UnitCLI pattern: `setCLI()` before `init()`
5. ✅ Path authority: Component can call `this.getCLI().model.projectRoot`

**Safety Considerations**:
- ⚠️ Must check if `setCLI` exists (not all components have it)
- ⚠️ Must be called BEFORE `init()` (components may need CLI in init)
- ⚠️ Must build Web4TSComponent after fix
- ⚠️ Must test with BOTH Unit and IdealMinimalComponent

### Lessons Learned

**1. Duck Typing for Graceful Degradation** ✅
- **Pattern**: Check if method exists before calling: `if (typeof instance.setCLI === 'function')`
- **Benefit**: New features work immediately, old components unaffected
- **Application**: Perfect for gradual migration strategies

**2. CLI as Path Authority** ✅
- **Principle**: CLI calculates ALL paths, components never use `process.cwd()`
- **Implementation**: Pass `projectRoot`, `targetDirectory` via model AND set CLI back-reference
- **Result**: Components work correctly regardless of where CLI is invoked

**3. Initialization Order Matters** ✅
- **Critical**: `setCLI()` must be called BEFORE `init()`
- **Reason**: `init()` may call `updateModelPaths()` which needs CLI
- **Pattern**: Create → Set Back-Reference → Initialize

**4. Multi-Component Development Workflow** ✅
- **Question**: "Is it a CLI Framework Issue?"
- **Answer**: YES - Fix in `DefaultCLI.ts` (base class)
- **Result**: Build infrastructure only, target components inherit automatically
- **Time Saved**: No need to rebuild Unit, IdealMinimalComponent, or any other component

**5. Test Strategy for Infrastructure Changes** ✅
- **Always test**: Direct CLI + Delegated CLI + Control
- **Catches**: Direct execution bugs, delegation bugs, regressions
- **Example**: Unit (new pattern) + IdealMinimalComponent (old pattern) + Web4TSComponent (control)
