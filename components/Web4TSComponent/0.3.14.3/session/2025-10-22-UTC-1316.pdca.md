**Found in:** `components/Unit/0.3.0.5/src/ts/layer2/DefaultUnit.ts` (lines 882-906)

```typescript
async toScenario(): Promise<Scenario<UnitModel>> {
  // ✅ DYNAMIC VERSION: Use getComponentVersion() instead of hardcoded
  const componentVersion = await this.getComponentVersion();
  const componentName = await this.getComponentName();
  
  const scenario: Scenario = {
    ior: {
      uuid: this.model.uuid,  // ← UUID from model
      component: componentName,  // ← Dynamic component name
      version: componentVersion  // ← Dynamic version
    },
    owner: ownerData,
    model: this.model
  };
  
  return scenario;
}
```

**KEY INSIGHT:** UUID is created in constructor and stored in `model.uuid`, NOT generated in `toScenario()`!

### **Step 2: Research Scenario Initialization**

**Found in:** `components/Web4TSComponent/0.3.14.3/src/ts/layer2/DefaultWeb4TSComponent.ts` (lines 177-188)

```typescript
/**
 * Initialize component with scenario data (Web4 pattern)
 * @param scenario Scenario containing component model and context
 * @returns this component instance for method chaining
 * @cliHide
 */
init(scenario: Scenario<Web4TSComponentModel>): this {
  if (scenario.model) {
    this.model = { ...this.model, ...scenario.model };  // ← Merge pattern
  }
  return this;
}
```

**KEY INSIGHT:** 
- `init(scenario)` already exists!
- Uses spread operator to merge incoming model with existing model
- Returns `this` for method chaining
- Hidden from CLI with `@cliHide`

### **Step 3: Research stdin Alternatives**

**NO STDIN FOUND!** Components receive data via:

1. **`init(scenario)`** - Primary Web4 pattern for initialization
2. **Constructor parameters** - For simple cases  
3. **Method parameters** - For CLI commands
4. **File system** - Via `storage.saveScenario()` / `storage.loadScenario()`

**KEY INSIGHT:** stdin is NOT used in Web4 architecture. The spec proposed stdin incorrectly!

### **Step 4: Research Naming Conventions**

**Found:** `@cliHide` annotation is used, NOT `__` prefix!

Evidence from all components:
- `init(scenario)` uses `@cliHide` (DefaultWeb4TSComponent line 181)
- No `__` prefixed public methods found
- `@cliHide` is the standard Web4 pattern

**KEY INSIGHT:** The spec proposed `__complete` and `__getCompletionScenario` incorrectly. Should be:
- `complete()` with `@cliHide`
- `getCompletionScenario()` with `@cliHide`
