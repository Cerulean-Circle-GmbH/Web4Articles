# Test Refactoring: Remove setTargetDirectory(), Use Model-Driven Init

**Status**: 🔴 TODO  
**Created**: 2025-11-07 UTC 00:30

**Type**: CMM3 Technical Debt Cleanup

## **🎯 Problem**

**Discovery**: During [2025-11-07-UTC-0000.eliminate-path-duplication-all-cases.pdca.md](./2025-11-07-UTC-0000.eliminate-path-duplication-all-cases.pdca.md) Phase 4 implementation, we discovered `setTargetDirectory()` is a CMM1 functional hack that violates Radical OOP principles.

**Current (CMM1 Functional)**:
```typescript
// ❌ Tests manually set directory after creation
const component = new DefaultWeb4TSComponent();
component.setTargetDirectory(testDir);
```

**Should Be (Radical OOP Model-Driven)**:
```typescript
// ✅ Tests pass all context in init scenario
const component = new DefaultWeb4TSComponent().init({
  ior: { uuid: randomUUID(), component: 'Web4TSComponent', version: '0.3.18.3' },
  owner: 'test',
  model: {
    isTestIsolation: true,
    projectRoot: testDir,
    componentsDirectory: path.join(testDir, 'components'),
  }
});
```

**Why This Matters**:
- `setTargetDirectory()` is functional parameter thinking
- Violates "empty constructor + init(scenario)" pattern
- Creates two ways to configure component (confusion!)
- Tests should use `web4tscomponent test file X` command (not `npx vitest`)
- The `test` command handles setting `isTestIsolation: true` internally

---

## **🔍 Root Cause**

Tests were written before Radical OOP refactoring when functional patterns were still used.
