### **Implementation Strategy**

**Option 1: Wrapper Script (RECOMMENDED)**
Create a temporary wrapper that sources component's source.env + sets PS1:
```bash
#!/bin/bash
# Temporary init file for test isolation shell
source "${COMPONENT_ROOT}/source.env"
PS1="\[\033[1;36m\][TEST ISOLATION ${COMPONENT} ${VERSION}]\[\033[0m\] \[\033[1;32m\]\u@\h\[\033[0m\] \[\033[1;34m\]\w\[\033[0m\] > "
```

**Option 2: Append to Existing (NOT RECOMMENDED)**
Modify component's source.env to add PS1 - violates separation of concerns.

**Option 3: PS1 via Environment Variable (BEST)**
Pass PS1 via environment, bash --init-file sources component's source.env:
```typescript
execSync(`bash --norc --init-file "${componentSourceEnv}"`, {
  cwd: testDataDir,
  env: {
    ...process.env,
    PROJECT_ROOT: testDataDir,
    PS1: `\\[\\033[1;36m\\][TEST ISOLATION ...]\\[\\033[0m\\] ...`,
  }
});
```

**Decision:** Use **Option 3** - cleanest, no file creation, respects DRY.

**BUT WAIT:** bash --init-file doesn't read PS1 from env before sourcing init file!

**Revised Decision:** Use **Option 1** - Create temporary wrapper in test/data/.bash_test_init that:
1. Sources component's source.env
2. Sets PS1 for test isolation
3. Gets deleted after shell exits
