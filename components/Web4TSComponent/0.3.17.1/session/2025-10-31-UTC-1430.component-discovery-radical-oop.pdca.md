### Analysis: How 0.3.13.2 Worked (Functional Benchmark)

**0.3.13.2 Architecture (WORKING):**

```typescript
// components/Web4TSComponent/0.3.13.2/src/ts/layer2/DefaultCLI.ts
export abstract class DefaultCLI implements CLI {
  protected componentClass: any;  // ✅ STORES COMPONENT CLASS
  protected componentName: string = '';
  protected componentVersion: string = '';
  protected componentInstance: Component | null = null;
  // ...
  
  initWithComponentClass(componentClass: any, name: string, version: string): this {
    this.componentClass = componentClass;  // ✅ STORES CLASS
    this.componentName = name;
    this.componentVersion = version;
    this.discoverMethods();  // ✅ Calls discovery with class available
    return this;
  }
  
  protected discoverMethods(): void {
    // ... discover CLI methods ...
    
    // ✅ CRITICAL: Discover component methods from CLASS
    if (this.componentClass) {
      const prototype = this.componentClass.prototype;
      const methodNames = Object.getOwnPropertyNames(prototype)
        .filter(name => typeof prototype[name] === 'function')
        .filter(name => !name.startsWith('_') && name !== 'constructor')
        .filter(name => !['init', 'toScenario', 'validateModel', 'getModel'].includes(name));

      for (const methodName of methodNames) {
        const method = prototype[methodName];
        this.methodSignatures.set(methodName, {
          name: methodName,
          paramCount: method.length,
          isAsync: method.constructor.name === 'AsyncFunction'
        });
      }
    }
  }
}
```

### Proposed Solution: Instance-Based Discovery

**Architecture Decision:**

Instead of storing component CLASS (0.3.13.2 pattern), discover from component INSTANCE:

```typescript
// NEW ARCHITECTURE:
export abstract class DefaultCLI implements CLI, Component<CLIModel> {
  protected model!: CLIModel;
  protected methodSignatures: Map<string, MethodSignature> = new Map();
  protected colors: Colors = DefaultColors.getInstance();
  
  // ✅ Instances belong in class, not model
  protected component?: DefaultWeb4TSComponent;  // Component INSTANCE
  protected context?: DefaultWeb4TSComponent;    // Loaded via on()
  protected user?: User;
  
  // ✅ NEW: Discover methods from component INSTANCE (not class)
  protected discoverMethods(): void {
    // 1. Discover CLI methods (existing logic - works!)
    this.discoverCLIMethods();
    
    // 2. Discover component methods from INSTANCE
    if (this.component) {
      this.discoverComponentMethods(this.component);
    }
  }
  
  private discoverCLIMethods(): void {
    // Walk up CLI prototype chain (existing logic)
    let currentPrototype = Object.getPrototypeOf(this);
    while (currentPrototype && currentPrototype !== Object.prototype) {
      // ... existing discovery logic ...
      currentPrototype = Object.getPrototypeOf(currentPrototype);
    }
  }
  
  private discoverComponentMethods(component: any): void {
    // ✅ NEW: Discover from INSTANCE prototype (same as 0.3.13.2, but using instance)
    const prototype = Object.getPrototypeOf(component);
    const methodNames = Object.getOwnPropertyNames(prototype)
      .filter(name => typeof prototype[name] === 'function')
      .filter(name => !name.startsWith('_') && name !== 'constructor')
      .filter(name => !['init', 'toScenario', 'validateModel', 'getModel'].includes(name));

    for (const methodName of methodNames) {
      const method = prototype[methodName];
      this.methodSignatures.set(methodName, {
        name: methodName,
        paramCount: method.length,
        isAsync: method.constructor.name === 'AsyncFunction'
      });
    }
  }
}
```

### QA Decisions

**Decision 1: Discovery Timing**

When should component methods be discovered?

- [x] a) During CLI construction (before any execute()) ← **PREFERRED (matches 0.3.13.2)**
- [ ] b) Lazy discovery (first execute() call) ❌ Breaks tab completion
- [ ] c) Explicit discovery() call ❌ Not Radical OOP (requires manual action)

**Rationale:** Tab completion and usage display need methods discovered BEFORE any command execution.

**Decision 2: Component Instance Lifecycle**

When should component instance be created?

- [x] a) During construction (for discovery) ← **PREFERRED**
- [ ] b) Lazy (on first use) ❌ Too late for discovery
- [ ] c) Both (temp for discovery, real for execution) ❌ Wasteful

**Rationale:** Discovery requires instance, so create it during construction. Reuse same instance for execution.

**Decision 3: Radical OOP Compliance**

How to maintain Models = Data ONLY?

- [x] a) Store component in `this.component` (class field) ← **PREFERRED**
- [ ] b) Store in `this.model.component` ❌ Violates Radical OOP
- [ ] c) Don't store, recreate on demand ❌ Breaks discovery

**Rationale:** Instances belong in class fields, not model. This maintains serializability.
