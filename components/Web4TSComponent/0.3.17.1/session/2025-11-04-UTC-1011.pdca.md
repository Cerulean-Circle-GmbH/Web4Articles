### **1. createPDCA - Cross-Component PDCA Creation**

**Purpose:** Create new PDCAs programmatically with auto-populated metadata

```bash
# Syntax
pdca createPDCA "<title>" "<objective>" [sessionDirectory] [dryRun]

# Example 1: Create in default PDCA component session
pdca createPDCA "Fix Bug" "Resolve test failure in component X"

# Example 2: Create in ANY component directory (cross-component)
pdca createPDCA "Demo" "Show PDCA commands" \
  /Users/Shared/Workspaces/2cuGitHub/Web4Articles/components/Web4TSComponent/0.3.17.1/session

# Example 3: Dry run to preview
pdca createPDCA "Title" "Objective" ./custom/session true
```

**What It Does:**
- ✅ Reads official template from `scrum.pmo/roles/_shared/PDCA/template.md`
- ✅ Generates UTC timestamp filename: `YYYY-MM-DD-UTC-HHMM.pdca.md`
- ✅ Auto-populates ALL metadata placeholders: CMM_STATUS, AGENT_NAME, BRANCH, UTC_TIMESTAMP, etc.
- ✅ Establishes bidirectional chain: Updates previous PDCA's "Next PDCA:" link
- ✅ Creates session directory if it doesn't exist
- ✅ **NEW**: AI immediately populates content sections (AI Content Population Mandate)

**Use Cases:**
- Starting new feature/task documentation from scratch
- Creating PDCAs in any component (not just PDCA component)
- Ensuring consistent PDCA structure across all sessions

**Source:** PDCA 0726 (cross-component feature), PDCA 0957 (AI content population)

### **2. rename - File Renaming with 4 Strategies**

**Purpose:** Rename PDCA files with atomic git commit/push

```bash
# Syntax
pdca rename <file> <case> [dryRun]

# Case 1: now - Update to current UTC timestamp
pdca rename 2025-10-28-UTC-1632.pdca.md now
# Result: 2025-11-04-UTC-1011.pdca.md (current time)
# Use case: Update stale PDCA timestamp to current time

# Case 2: creationDate - Restore git creation timestamp
pdca rename 2025-11-04-UTC-1011.pdca.md creationDate
# Result: 2025-11-04-UTC-0906.pdca.md (git creation date)
# Use case: Fix manually renamed file to match original git timestamp

# Case 3: strip - Remove descriptive text
pdca rename 2025-10-28-UTC-1632.test-hang-investigation.pdca.md strip
# Result: 2025-10-28-UTC-1632.pdca.md
# Use case: Clean filename for archival or final version

# Case 4: feature - Add .feature. marker
pdca rename 2025-11-04-UTC-1011.pdca.md feature
# Result: 2025-11-04-UTC-1011.feature.pdca.md
# Use case: Mark PDCA as feature development (vs bug fix)
```

**What It Does:**
- ✅ Performs `git mv` with fallback to `fs.rename`
- ✅ Updates all bidirectional links in other PDCAs automatically
- ✅ **CRITICAL**: Atomic commit and push (bug fix from PDCA 0829)
- ✅ Creates target directories if needed
- ✅ Dry run mode to preview changes

**Source:** PDCA 0829 (atomic commit bug fix)

### **4. cmm3check - CMM3 Compliance Validation**

**Purpose:** Validate PDCA compliance with CMM3 requirements

```bash
# Syntax
pdca cmm3check <file> [dryRun]

# Example
pdca cmm3check components/Web4TSComponent/0.3.17.1/session/2025-11-04-UTC-1011.pdca.md

# Auto-fix mode (fixes some violations automatically)
pdca cmm3check <file> false
```

**What It Checks (11 Violation Types):**
- **1a-1j**: Required sections (SUMMARY, PLAN, DO, CHECK, ACT, EMOTIONAL REFLECTION, etc.)
- **1k**: Unpopulated `{{}}` placeholders (metadata must be filled)
- **1l**: Missing DoR/DoD sections (mandatory as of 2025-11-04)
- **3a-3c**: Dual link format validation
- **4a-4d**: Timestamp format validation
- **5a/5c, 6a, 7a/7b**: Additional compliance checks

**What It Does:**
- ✅ Reports all violations with descriptive error messages
- ✅ Auto-fix available for some violations (dual link format, etc.)
- ✅ Returns exit code 0 if compliant, non-zero if violations found
- ✅ Dry run mode to preview fixes without applying

**Source:** PDCA 0829 (DoR/DoD enforcement - violation 1l)

### **5. rewritePDCA - Fix Corrupted PDCAs**

**Purpose:** Replace corrupted PDCAs with fresh template while preserving timestamp

```bash

# Example

# Dry run to preview
pdca rewritePDCA <file> true
```

**What It Does:**
- ✅ **Preserves timestamp**: Filename stays the same (true in-place rewrite)
- ✅ **Auto-extracts title**: From line 1 (`# 📋 **PDCA Cycle: TITLE - ...**`)
- ✅ **Auto-extracts objective**: From header (`**🎯 Objective:** ...`)
- ✅ **Auto-populates ALL metadata**: Uses shared `populateBoilerplateInternal()` helper
- ✅ Reads fresh template from `scrum.pmo/roles/_shared/PDCA/template.md`
- ✅ Writes to SAME filename (not create-new-delete-old)

**Use Cases:**
- PDCA is corrupted (missing sections, invalid structure)
- PDCA fails cmm3check validation
- PDCA has unpopulated metadata placeholders

**Source:** PDCA 1507 (in-place design), PDCA 0923 (auto-population)
