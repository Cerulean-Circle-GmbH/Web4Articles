**ARCHITECTURAL VIOLATION: Component Calculating Paths (Path Authority Violation)**

The issue is NOT just about `process.cwd()` - it's about **WHO calculates paths**.

**Web4 Path Authority Principle:**

```
┌─────────────────────────────────────────────────────┐
│ DefaultCLI (PATH AUTHORITY)                         │
│ ✅ Calculates ALL paths ONCE in init()             │
│ ✅ Stores in this.model.projectRoot                │
│ ✅ Passes to component via setTargetDirectory()    │
└─────────────────────────────────────────────────────┘
                        │
                        │ setTargetDirectory(projectRoot)
                        ▼
┌─────────────────────────────────────────────────────┐
│ DefaultWeb4TSComponent (PATH CONSUMER)              │

│ ✅ ONLY receives targetDirectory from CLI          │

└─────────────────────────────────────────────────────┘
```

**Why This Matters:**

1. **Test Isolation:** CLI detects test/data and sets correct path
2. **Production:** CLI finds project root, component just uses it
3. **Cross-Component:** CLI can redirect ANY component to ANY location
4. **Single Source of Truth:** Only ONE place calculates paths (CLI)

**From Phase 5 Work (2025-10-29-UTC-1323.path-separation-violation-fix.pdca.md):**
> DefaultCLI is the Path Authority - calculates ALL paths
> DefaultWeb4TSComponent is the Component Authority - NEVER calculates paths

**The Problem Chain:**

1. **Tests run from:** `/Users/.../Web4Articles/components/Web4TSComponent/0.3.17.1`
2. **process.cwd() returns:** `/Users/.../Web4Articles/components/Web4TSComponent/0.3.17.1`
3. **Component creates at:** `resolveComponentPath()` uses `this.model.targetDirectory + '/components/...'`
4. **Result:** `/Users/.../Web4Articles/components/Web4TSComponent/0.3.17.1/components/...` ❌

**Test Isolation Principle (Violated):**

From spec (line 260-267):
