Added auto-source logic after COMPONENT_PATH calculation:
```bash
SOURCE_ENV_PATH="$COMPONENT_PATH/source.env"
if [ -f "$SOURCE_ENV_PATH" ]; then
    SOURCE_ENV_MTIME=$(stat -f %m "$SOURCE_ENV_PATH" 2>/dev/null || stat -c %Y "$SOURCE_ENV_PATH" 2>/dev/null)
    NEEDS_SOURCE=false
    
    if [ -z "$WEB4TSCOMPONENT_VERSION" ]; then
        NEEDS_SOURCE=true
    elif [ -n "$SOURCE_ENV_MTIME" ] && [ -n "$WEB4_SOURCE_ENV_MTIME" ]; then
        if [ "$SOURCE_ENV_MTIME" -gt "$WEB4_SOURCE_ENV_MTIME" ]; then
            NEEDS_SOURCE=true
        fi
    fi
    
    if [ "$NEEDS_SOURCE" = true ]; then
        source "$SOURCE_ENV_PATH"
        export WEB4_SOURCE_ENV_MTIME="$SOURCE_ENV_MTIME"
    fi
fi
```

### **Critical Discovery: Environment Variables Don't Persist Across Process Invocations**

**What I Learned:**
1. ❌ Variables set by first `web4tscomponent` call (like `WEB4_SOURCED_COMPONENT`) don't persist to next invocation
2. ❌ Each `./web4tscomponent` call is a SEPARATE bash process - doesn't inherit exports from previous calls
3. ❌ My earlier test passed because it was all in ONE bash session (false positive)
4. ✅ Real usage: Each CLI call is isolated - can't track "already sourced" with custom exports

**TRON Teaching:**
```quote
correct, you must use e.g. use env | grep to see if the functions are there.
do you know an even better method?
```

### **Discovery Journey: What CAN Be Detected Across Subshells?**

#### **Attempt 1: Bash Functions** ❌
```bash
# Check if source.env defined bash functions
if ! declare -F _web4_generic_completion >/dev/null 2>&1; then
    source "$SOURCE_ENV_PATH"
fi
```

**Problem:** Bash functions DON'T inherit to subshells (unless `export -f`)

**Test:**
```bash
bash -c "source source.env && bash -c 'declare -F _web4_generic_completion'"
# Returns: (empty) - function not inherited to nested bash!
```

#### **Attempt 2: PATH Commands** ❌
```bash
# Check if pdca command is available
if ! command -v pdca >/dev/null 2>&1; then
    source "$SOURCE_ENV_PATH"
fi
```

**Problem:** `pdca` was ALREADY in PATH globally (from user's ~/.bashrc)

**Test Result:** Always found `pdca`, so never sourced!

#### **Attempt 3: Exported Variables** ✅
```bash
# Check if WEB4_PROJECT_ROOT is set
if [ -z "$WEB4_PROJECT_ROOT" ]; then
    source "$SOURCE_ENV_PATH"
fi
```

**Why This Works:**
- `source.env` exports `WEB4_PROJECT_ROOT` (line 20/23)
- Exported variables DO inherit to subshells automatically
- Simple, reliable, CMM3-compliant detection

**Final Implementation:**
```bash
# Auto-source component's environment if needed
# Check if environment is loaded by testing for exported variables from source.env
SOURCE_ENV_PATH="$COMPONENT_PATH/source.env"
if [ -f "$SOURCE_ENV_PATH" ]; then
    # Check if source.env was already sourced by testing for WEB4_PROJECT_ROOT
    # This variable is exported by source.env and inherits to subshells
    if [ -z "$WEB4_PROJECT_ROOT" ]; then
        # Variable not set - need to source
        source "$SOURCE_ENV_PATH"
    fi
    # Silent when already loaded (no message spam on repeated calls)
fi
```

```bash
# Test 1: Truly fresh shell (env -i) - should auto-source
env -i bash -c "cd $COMPONENT_PATH && PATH=/usr/bin:/bin:/usr/sbin:/sbin ./web4tscomponent links 2>&1 | grep -c 'Web4 environment loaded'" > /tmp/test1.txt
```

**Why `env -i` Required:**
- Normal `bash -c` inherits parent's environment
- User's shell already had `WEB4_PROJECT_ROOT` set globally
- Without `env -i`, test always thinks environment is already sourced!
