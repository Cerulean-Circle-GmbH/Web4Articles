## **📋 PLAN**

### **Problem Statement:**

**USER REPORT:**
```

EXPECTED OUTPUT:
📁 Tree structure for Web4TSComponent 0.3.17.1:

```

**Root Cause Analysis:**

Previous PDCA (2025-10-30-UTC-1011) fixed Path Authority architecture by:
1. Moving `on()` to DefaultCLI ✅
2. CLI calculates paths ONCE in `init()` ✅
3. Component receives path via `setTargetDirectory()` ✅

**BUT:** The commands (tree, test, build, clean, start) still used `resolveComponentPath()` which ALWAYS adds `components/` prefix:

```typescript
// WRONG (from previous implementation):
protected resolveComponentPath(componentName: string, version: string): string {
  return path.join(this.model.targetDirectory, 'components', componentName, version);
}

// In tree():
const componentPath = this.resolveComponentPath(target.model.component, target.model.version.toString());
// Result: /project/root/components/ComponentName/0.1.0.0
```

When using `on()`:
- CLI calculates: `/project/root/components/ComponentName/0.1.0.0` ✅
- Sets via `setTargetDirectory(componentPath)` ✅
- BUT: `setTargetDirectory()` only set `model.targetDirectory`, NOT `model.origin` ❌
- Commands checked `target.model.origin` (undefined!) and fell back to `resolveComponentPath()` ❌
- `resolveComponentPath()` added `components/` AGAIN → PATH DOUBLING ❌

**Impact:**
- CRITICAL production bug affecting ALL context-aware commands
- `web4tscomponent on <component> <version> tree` → wrong path
- `web4tscomponent on <component> <version> test` → wrong path (tests won't run)
- `web4tscomponent on <component> <version> build` → wrong path (build fails)
- ALL commands broken when using `on()` context switching

### **Execution Plan:**

**Step 1:** Fix `setTargetDirectory()` to set BOTH `targetDirectory` AND `origin`
- When CLI calls `setTargetDirectory(componentPath)`, component must remember its absolute path
- `origin` field is checked by commands to avoid path doubling

**Step 2:** Verify all commands use `target.model.origin` correctly
- tree(), test(), build(), clean(), start(), testSelective() already fixed
- All use pattern: `target.model.origin || this.resolveComponentPath(...)`

**Step 3:** Rebuild and verify with `on()` context
- Test: `web4tscomponent on Web4TSComponent 0.3.17.1 tree 2`
- Expected: Correct path without doubling

## **🔧 DO**

**Step 1: Fix setTargetDirectory() ✅**

```typescript
// BEFORE:
setTargetDirectory(directory: string): void {
  // ✅ ONLY store the value - no calculation
  this.model.targetDirectory = directory;
}

// AFTER:
setTargetDirectory(directory: string): void {
  // ✅ PATH AUTHORITY: Store both targetDirectory (project root) and origin (component path)
  // When called from CLI.on(), directory is the full component path
  // origin is used by commands (tree, test, build, etc.) to avoid path doubling
  this.model.targetDirectory = directory;
  this.model.origin = directory;
}
```

**Benefits:**
- Zero path doubling bugs

- Single source of truth (CLI is Path Authority)

### **Lessons Learned:**

**When refactoring path logic:**
1. Update ALL code paths that set path-related fields
2. Verify both "set" and "get" sides of data flow
3. Test with context switching (`on()`) to catch relative vs absolute path issues
4. Don't assume field names match semantics (`targetDirectory` vs `origin`)
