### **2. Root Cause Analysis**

**NOT missing `encoding: 'utf-8'`** - Both v0.3.14.4 and v0.3.17.0 lack this parameter but v0.3.14.4 works!

**REAL ROOT CAUSE: EPIPE Error in Vitest Worker Processes**

The error `Error: write EPIPE` means:
- Vitest spawns worker processes to run tests
- Tests complete successfully (25/25 GREEN)
- Worker processes try to send results back to parent
- Parent process pipe is closed/broken
- Worker hangs trying to write to closed pipe
- Process never exits

**Why v0.3.13.2 works:**
- Old test structure in `test/` directory
- Simpler test files (consolidated story tests)
- No worker process issues

**Why v0.3.14.4 works:**
- Has `encoding: 'utf-8'` in execSync
- Transitional structure (test/ but incomplete)
- Error exits cleanly

**Why v0.3.17.0 hangs:**
- New test structure `test/ts/layer2/` with baseline tests
- Missing `encoding: 'utf-8'` in execSync
- Vitest worker process cleanup issue
- EPIPE error causes hang

### **3. Reading v0.3.14.4 test() Implementation**

Key difference at line 2276-2280:
```typescript
execSync('npx vitest run --bail=false', {
  cwd: componentPath,
  stdio: 'inherit',
  encoding: 'utf-8',  // ✅ CRITICAL: Forces proper stream handling
});
```

### **4. Reading v0.3.17.0 test() Implementation**

Line 2195-2198:
```typescript
execSync('npx vitest run --bail=false', { 
  cwd: componentPath,
  stdio: 'inherit',  // ❌ NO encoding parameter!
});
```

### **5. Fix Applied**

Adding `encoding: 'utf-8'` forces Node.js to properly handle process streams and ensures clean exit.

### **Critical Discovery: Test File Isolation**

**ROOT CAUSE IDENTIFIED:**

```bash
# ✅ Individual test files WORK:
$ npx vitest run test/ts/layer2/DefaultWeb4TSComponent.baseline.test.ts
✓ test/ts/layer2/DefaultWeb4TSComponent.baseline.test.ts (11 tests) 12ms
Test Files  1 passed (1), Tests  11 passed (11)

# ❌ CLI test file HANGS:
$ npx vitest run test/ts/layer5/Web4TSComponentCLI.baseline.test.ts
RUN  v3.2.4 ... 
# HANGS - Never completes, timeout required
```

**The hang is NOT caused by:**
- ❌ Missing `encoding: 'utf-8'` (added, didn't help)
- ❌ Vitest worker configuration (added `singleFork: true`, didn't help)  
- ❌ EPIPE errors (those appear AFTER tests complete, this hangs BEFORE)

**The hang IS caused by:**
- ✅ `Web4TSComponentCLI.baseline.test.ts` file specifically
- ✅ Happens during test file loading/initialization (before any tests run)
- ✅ Likely the `new Web4TSComponentCLI()` constructor call in `beforeEach()`
- ✅ Constructor might be executing `execSync` or other blocking operations

### **Next Steps**

1. Read `Web4TSComponentCLI.ts` constructor
2. Identify what's hanging (likely `discoverMethods()` or file system operations)
3. Fix the hanging operation
4. Re-test all files together

### **CRITICAL FINDING: Usage Dialog Performance**

```bash
$ time web4tscomponent
# Shows usage...

real    0m38,874s  # ⚠️ 38.8 SECONDS!!!
user    0m39,655s
sys     0m1,744s
```

**Root cause:** `TSCompletion.extractCliValues()` is called for EVERY parameter during usage generation!

- Line 1105: `const enumValues = this.enumParameterCompletion(paramName);`
- Line 1571: `TSCompletion.extractCliValues(this.componentClass.name, "", paramName)`
- This happens in `deriveExamplesFromConventions()` which is called for EVERY parameter
- With ~20 parameters × multiple methods, this becomes hundreds of expensive TSCompletion calls
- Each call likely reads and parses TypeScript source files

**Impact:**
- Usage dialog takes 38.8 seconds
- CLI test hangs because `beforeEach(() => new Web4TSComponentCLI())` triggers usage generation
- When run with other tests, this causes vitest timeout/hang

**Solution needed:** Cache TSCompletion results or lazy-load parameter values only when needed.
