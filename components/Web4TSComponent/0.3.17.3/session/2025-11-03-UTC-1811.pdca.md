## Objective

**Problem**: `web4tscomponent initProject § force` initializes the project at the **component directory** instead of the **project root**.

**User Experience**:
```bash
[web4 donges@McDonges] /Users/Shared/Workspaces/temp/Web4Articles > web4tscomponent initProject § force
🚀 Initializing Web4 project at: /Users/Shared/Workspaces/temp/Web4Articles/components/Web4TSComponent/0.3.17.3
   ✅ Force updated tsconfig.json
   ✅ Force updated package.json
   ✅ Ensured node_modules directory exists
   ✅ Force updated source.env
```

**Expected**: Initialize at `/Users/Shared/Workspaces/temp/Web4Articles` (project root)  
**Actual**: Initialize at `/Users/Shared/Workspaces/temp/Web4Articles/components/Web4TSComponent/0.3.17.3` (component directory)

**Root Cause**: 
```typescript
// Line 842-846 of DefaultWeb4TSComponent.ts
async initProject(targetDir: string = '§', force: boolean = false): Promise<this> {
  const projectRoot = targetDir === '§' 
    ? this.model.targetDirectory  // ← BUG: Uses CLI-initialized value
    : targetDir;
```

When the `web4tscomponent` CLI wrapper runs, it changes `cwd` to the component directory, so `this.model.targetDirectory` (calculated during CLI init) is the **component directory**, not the **project root** where the user invoked the command.

**Solution**: When `targetDir === '§'`, use `findProjectRoot()` to calculate the project root **dynamically** based on CURRENT working directory, not the stored value from CLI initialization.

**Key Insight**: The `§` symbol means "calculate project root NOW" (dynamic), not "use stored targetDirectory" (static). Test isolation explicitly passes a path, so it will continue to work correctly.

```typescript
  // ✅ BASELINE COMPLIANCE: Use targetDirectory as-is (set by CLI or test via setTargetDirectory)
```

```typescript
async initProject(targetDir: string = '§', force: boolean = false): Promise<this> {
  // @pdca 2025-11-03-UTC-1811.pdca.md - Fix § to dynamically calculate project root
  // § means "calculate project root NOW from current working directory"
  // Explicit paths (like test/data) bypass calculation and use the provided path
  const projectRoot = targetDir === '§' 
    ? this.findProjectRoot()  // ← FIX: Dynamically calculate from cwd
    : targetDir; // Explicit path (test isolation or user-provided)
```

**Key Change**: Replace `this.model.targetDirectory` with `this.findProjectRoot()`

**Why This Works**:
- **Production**: `findProjectRoot()` walks up from `cwd` to find `.git` + `package.json` + `components/` → Project root ✅
- **Test Isolation**: Tests pass explicit path (NOT `§`) → Uses explicit path ✅
- **Component Directory**: `findProjectRoot()` walks up from component dir → Project root ✅
