## Plan

### Objective
Analyze how a new agent spent 10+ hours debugging an ESM violation that could have been prevented in 5 minutes by reading `trainAI tech-stack`. Document the systematic failure pattern and create forcing functions to prevent recurrence.

### Context

**What Happened**:
A new agent joined a session to fix a test execution issue (`web4tscomponent test file` was failing). After extensive debugging involving:
- Creating systematic test tables
- Updating 4 test files with complete model initialization
- Adding debug logging throughout the codebase
- Investigating CLI initialization, bash wrappers, environment variables
- Multiple theories about Path Authority violations
- 10+ iterations of debugging and hypothesis testing

The root cause was finally discovered: **A single line using CommonJS `require()` in an ESM module**.

```typescript
// ❌ Line 161 in DefaultCLI.ts - ESM VIOLATION
const { execSync } = require('child_process');
// Error: "require is not defined" in ESM modules
```

**The Impact**:
- Git check failed silently (try/catch swallowed error)
- Fell through to directory traversal fallback
- Returned component root instead of project root
- Broke ALL CLI operations
- Required 10+ hours to diagnose

**The Prevention**:
This was documented in `trainAI tech-stack` topic #11:
> ✅ Module System: Pure ESM - NO CommonJS (require, module.exports)

**Time Cost**:
- **Actual debugging**: 10+ hours
- **Reading trainAI tech-stack**: 5 minutes
- **Waste multiplier**: 120x

### Lessons for Future Agents

1. **trainAI Is Not Optional**

   - Don't spend 10 hours debugging
