## Check

### Root Cause Analysis

**ROOT CAUSE**: The **PROJECT** `source.env` (`/Users/Shared/Workspaces/temp/Web4Articles/source.env`) is outdated at version 0.3.13.2, while the **COMPONENT** templates and source files are correctly updated to 0.3.17.3.

**Why This Happens**:
1. User sources **PROJECT** `source.env` in their bash session
2. PROJECT source.env defines OLD completion functions like `_idealminimalcomponent_completion`
3. These OLD functions use the `completeParameter` callback pattern
4. When user types `idealminimalcomponent <TAB>`, bash calls OLD completion function
5. OLD function eventually delegates to NEW CLI, which produces NEW output
6. Result: Mixed behavior showing OLD callback pattern with NEW output format

**Component Analysis**:
- ✅ All 0.3.17.3 templates are NEW (247 lines, Scenario-based)
- ✅ Component source.env is NEW (created correctly from template)
- ✅ DefaultCLI is 1:1 copy (as designed)
- ❌ **PROJECT source.env is OLD** (0.3.13.2, 523 lines)

### Why Component source.env Doesn't Help

The component source.env at `components/IdealMinimalComponent/0.1.0.0/source.env` is correct but **NOT SOURCED** because:
1. Component source.env is meant for component-local development
2. User sources PROJECT source.env (at workspace root)
3. PROJECT source.env is the active environment

## Learnings

### 1. Project vs Component source.env

**Key Insight**: There are TWO separate source.env files:
- **PROJECT** source.env: `/Users/Shared/Workspaces/temp/Web4Articles/source.env`
  - User sources this in their shell
  - Defines completion functions for ALL components
  - Managed by `web4tscomponent initProject`
- **COMPONENT** source.env: `components/{Name}/{Version}/source.env`
  - Created during component creation
  - Meant for component-local development
  - NOT sourced by default

### 2. Template vs Reality Gap

**Key Insight**: Templates can be updated (0.3.17.3) but existing installations remain old (0.3.13.2) until explicitly updated via `initProject`.

**CMM3 Principle**: Always verify BOTH:
1. Template correctness (what WILL be generated)
2. Installation state (what IS currently active)

### 3. Completion Registration Authority

**Key Insight**: Bash completion functions are defined in PROJECT source.env, NOT component source.env. This is by design for auto-discovery:
- PROJECT source.env scans `scripts/` directory
- Registers completion for all symlinked CLIs with `TSCompletion.ts`
- Uses ONE generic function for ALL components (DRY)

### 4. Version Migration Path

**Key Insight**: When upgrading Web4TSComponent versions:
1. ✅ Update component source files (automatic during development)
2. ✅ Update component templates (automatic during development)
3. ❌ **MANUAL**: Must run `web4tscomponent initProject` to update PROJECT files
4. ❌ **MANUAL**: Must `source source.env` to reload bash environment

**Action Item**: Document this in README.md upgrade guide.
