## Objective

**Revert Crime**: Remove 48 lines of `process.cwd()` path calculation from `DefaultWeb4TSComponent.initProject()` (commit `850a533e9`)

**Fix Architecture**: Restore model-driven program flow where **DefaultCLI is Path Authority**

**Key Understanding**:
1. **Path Authority**: DefaultCLI calculates ALL paths in `init()`, stores in `this.model`
2. **Model-Driven Flow**: Component behavior determined by model state, NOT by method (test, create, build)
3. **Test Isolation**: 
   - **Location**: `componentRoot/test/data` (e.g., `.../Web4TSComponent/0.3.17.3/test/data`)
   - **Structure**: `projectRoot + componentRoot + /test/data`
   - **Behaves like project root**: Has `components/`, `tsconfig.json`, `package.json`, `source.env`
   - **CLI calculates ONCE**: When `test` method runs, CLI calculates `componentRoot + /test/data`, passes to component
   - **Component NEVER calculates**: Component receives `testDataDir` from CLI via model
4. **Environment Agnostic**: Web4 NEVER relies on `process.cwd()` or environment variables

**The Correct Pattern**:
```typescript
// DefaultCLI.init() - Path Authority calculates ONCE
this.model.projectRoot = this.calculateProjectRootInternal();

// CLI sets component's model
this.component.model.targetDirectory = this.model.projectRoot;

// Component uses model state - NO calculation
const projectRoot = this.model.targetDirectory;
```

**Why Model State Determines Flow**:
- **Production**: CLI calculates projectRoot → sets targetDirectory → component uses it
- **Test Isolation**: Test explicitly passes `test/data` path → component detects `/test/data` pattern → operates in test mode
- **Shell Wrapper**: Irrelevant! DefaultCLI calculates from wherever IT starts, component receives result
