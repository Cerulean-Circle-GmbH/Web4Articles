## Hard Rules (To Prevent This Forever)

### Rule 1: NEVER TOUCH WORKING CONFIG WITHOUT ASKING

**Files That Require Permission**:
- `tsconfig.json`
- `package.json`
- `.gitignore`
- `build.sh` and other scripts
- Any file that's been stable for 3+ versions

**Process**:
1. **STOP** - Do NOT edit the file
2. **ASK** - "Should I change [file]? I think [reason]. Original has been working for X versions."
3. **WAIT** - Do NOT proceed until user approves
4. **IF APPROVED** - Make change, test, commit
5. **IF REJECTED** - DO NOT CHANGE

---

### Rule 2: REVERT FIRST, DEBUG LATER

**When User Reports "It's broken"**:
1. **IMMEDIATELY** check `git log` for MY recent changes
2. **IF I CHANGED ANYTHING** → Assume it's MY fault
3. **REVERT IMMEDIATELY** → Restore known-good state
4. **THEN** investigate if revert fixed it
5. **ONLY THEN** consider other causes

**Time Limit**: 1 minute to revert, NOT hours of debugging

---

### Rule 3: Build MUST Pass Before Commit

**Pre-Commit Checklist** (MANDATORY):
```bash
# 1. Full build
./src/sh/build.sh || { echo "❌ BUILD BROKEN - DO NOT COMMIT"; exit 1; }

# 2. Verify CLI exists
[ -f "dist/ts/layer5/Web4TSComponentCLI.js" ] || { echo "❌ CLI MISSING - DO NOT COMMIT"; exit 1; }

# 3. Test CLI works
./web4tscomponent --help || { echo "❌ CLI BROKEN - DO NOT COMMIT"; exit 1; }

# 4. Run key tests (if applicable)
npm test || { echo "❌ TESTS BROKEN - DO NOT COMMIT"; exit 1; }
```

**Result**: If ANY step fails → DO NOT COMMIT → FIX OR REVERT

---

### Rule 4: ONE Change Per Commit

**Atomic Commits**:
- ✅ GOOD: "Change module from ES2022 to NodeNext" (one setting)
- ❌ BAD: "Update tsconfig" (changed 6 things)

**Why**: If something breaks, you know EXACTLY which change caused it

---

### Rule 5: Configuration Changes Require PDCA First

**For Critical Files** (`tsconfig.json`, `package.json`, build scripts):

1. **PDCA FIRST** - Write analysis BEFORE changing
   - Current configuration
   - Proposed changes
   - Reason for each change

   - Rollback plan

2. **USER APPROVAL** - Get explicit "go ahead"

3. **THEN CHANGE** - Make the change

4. **VERIFY** - Full build + test
