## Objective

**Problem**: Completion behavior differs based on which `source.env` is sourced, making it hard to verify correct operation and causing confusion during development.

**Root Cause**: Relying on `WEB4_PROJECT_ROOT` env var or `process.cwd()` makes behavior dependent on where `source.env` was sourced.

**Solution**: 
1. **Use DefaultCLI's `findProjectRoot()` method consistently** - Already implements smart project root detection independent of environment
2. Define clear test scenarios that should ALL produce identical completion results
3. Add `web4tscomponent initProject force` to fully overwrite project files when needed

**Key Insight**: DefaultCLI should be **truly environment-agnostic**:
- ❌ NEVER rely on environment variables directly (e.g., `WEB4_PROJECT_ROOT`, `USER`, `HOSTNAME`)
- ✅ ONLY use scenarios and models for configuration
- ✅ Traverse filesystem to find project root: `.git` + `package.json` + `components/` directory
- ✅ **EXCEPTION**: User component MAY read environment - everyone else gets data THROUGH User
- **Zero Knowledge, Zero Config, Just Scenarios and Models!**

**Radical OOP Pattern**: 
- **User component** = Single source of truth for user/environment data
- **All other components** = Get user data via `User.toScenario()`, NEVER directly from `process.env`
