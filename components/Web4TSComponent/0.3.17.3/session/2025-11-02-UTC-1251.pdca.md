### 4. New Section Content Plan

**🗺️ Path Authority Principle & Path Calculations**

This section will explain:

1. **Overview:** What is Path Authority Principle?
   - CLI is single source of truth for ALL path calculations
   - Components store and use paths, never calculate them
   - Calculated once in `DefaultCLI.init()`, stored in `this.model`

2. **Path Fields Reference:**
   - `projectRoot` - Overall project root (Web4Articles)
   - `componentsDir` - {projectRoot}/components
   - `componentRoot` - Component's own version directory
   - `scriptsDir` - {projectRoot}/scripts
   - `scriptsVersionDir` - {projectRoot}/scripts/versions
   - `testDataDir` - {componentRoot}/test/data

3. **How findProjectRoot() Works:**
   - Checks WEB4_PROJECT_ROOT environment variable first
   - Traverses up from cwd looking for `.git` + `package.json` + `components/` directory
   - Critical: Must distinguish project root from component directory

4. **How on() Command Works:**
   - Loads target component with `loadComponent()`
   - Passes ALL path fields in scenario
   - Sets context fields for legacy compatibility
   - Enables commands to work on ANY component version

5. **Code Examples:**
   - Show `DefaultCLI.init()` path calculation
   - Show `loadComponent()` path transfer
   - Show component using paths from model

6. **Radical OOP Principles Applied:**
   - No functional wrappers for paths
   - No recalculation
   - Direct model access internally
   - Public getters only for inter-component communication
