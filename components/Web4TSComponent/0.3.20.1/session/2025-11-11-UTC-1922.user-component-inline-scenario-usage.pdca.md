### Phase 3: Scenario Pattern in User 0.3.0.4

**User 0.3.0.4 Implementation** (commented version):

```typescript:10:61:components/User/0.3.0.4/src/ts/layer2/DefaultUser.ts
export class DefaultUser implements User {
  private data: UserModel;

  constructor() {
    // Empty constructor - Web4 pattern
    this.data = {
      uuid: crypto.randomUUID(),
      username: 'system',
      hostname: 'localhost',
      createdAt: new Date().toISOString(),
      updatedAt: new Date().toISOString()
    };
  }

  init(scenario: Scenario): this {
    if (scenario.model) {
      this.data = scenario.model;
    }
    return this;
  }

  async generateOwnerData(params: OwnerParams): Promise<string> {
    // Generate owner data following ONCE pattern
    return JSON.stringify({
      user: params.user || 'system',
      hostname: params.hostname || 'localhost',
      uuid: params.uuid || this.data.uuid,
      timestamp: new Date().toISOString(),
      component: 'User',
      version: '0.3.0.4'
    });
  }

  async toScenario(): Promise<Scenario> {
    // Generate proper owner data for scenario
    const ownerData = await this.generateOwnerData({
      user: this.data.username,
      hostname: this.data.hostname,
      uuid: this.data.uuid
    });

    return {
      ior: {
        uuid: this.data.uuid,
        component: 'User',
        version: '0.3.0.4'
      },
      owner: ownerData,
      model: this.data
    };
  }
}
```

**Scenario Pattern Analysis**:
1. ✅ **Empty Constructor**: Minimal default state (system/localhost)
2. ✅ **init(scenario)**: Hydrates from scenario.model
3. ✅ **toScenario()**: Dehydrates to scenario for hibernation
4. ✅ **Model-Driven**: All state in `this.data` (UserModel)
5. ⚠️ **Hardcoded Version**: Version string hardcoded in methods

### Phase 5: Inline Component Pattern

**Pattern**: Web4TSComponent includes User inline as optional dependency
- **NOT** a peer dependency in package.json
- **Dynamic import** with try/catch for optional loading
- **Relative path** `../../User/latest/` (sibling component)
- **Semantic link** usage allows version flexibility

**Benefits**:
1. Optional dependency - Web4TSComponent works without User
2. Version flexibility - `latest` link means automatic updates
3. Graceful degradation - try/catch handles missing component
4. No build-time coupling - dynamic ESM import

**Risks**:
1. Runtime discovery - errors only at execution time
2. Documentation drift - comments vs actual imports
3. Version uncertainty - `latest` can change unexpectedly

### Lessons Learned

**Scenario Pattern as Radical OOP**:
1. **Scenarios are the hibernation/hydration mechanism** for Radical OOP models
2. **init(scenario)** replaces complex constructors
3. **toScenario()** enables state serialization without coupling
4. **Model-driven**: All state in model, methods read/write model

**Inline Component Pattern**:
1. **Semantic links enable version flexibility** without code changes
2. **Dynamic imports allow optional dependencies** without build coupling
3. **Documentation must reference semantic links** not hardcoded versions
4. **Comments drift** when implementation changes but comments don't

**CMM3 Implications**:
1. **Reproducibility requires version tracking** - `latest` is not reproducible
2. **Documentation must match reality** - outdated comments = CMM2
3. **Interface contracts must be verified** at runtime for dynamic loading
