**What I Misunderstood:**

2. ❌ Thought it should call `./{{COMPONENT_LOWER}} test`
3. ❌ Created infinite recursion loop

**The REAL Intention:**
1. ✅ `npm test` should call `web4tscomponent test` (or component's test command)
2. ✅ This FORCES developers to use the proper test workflow
3. ✅ Prevents direct `npx vitest` calls (which bypass web4tscomponent features)
4. ✅ `web4tscomponent test` and `idealminimalcomponent test` are THE GOOD DEFAULTS

**Why This Architecture:**
- **web4tscomponent test** provides: recursion prevention, promotion workflow, hierarchical testing
- **Direct vitest** bypasses all these features
- **npm test** forces the good path

### **The Architecture Challenge**

**For Web4TSComponent itself:**
```bash
# test.sh calls:
./web4tscomponent test  # ✅ Works - file exists in same directory
```

**For created components (IdealMinimalComponent):**
```bash
# test.sh calls:
./web4tscomponent test  # ❌ FAILS - file doesn't exist
./idealminimalcomponent test  # ❌ LOOPS - calls npm test → test.sh → itself
```

**The Recursion Problem:**
- `idealminimalcomponent test` → delegates to web4tscomponent
- web4tscomponent sees context → calls `npm test`
- `npm test` → calls `test.sh`
- `test.sh` → calls `./idealminimalcomponent test`
- LOOP!

### **The Solution Strategy**

**Option A: Environment Variable for Recursion Detection**
```bash
# test.sh:
if [ -z "$WEB4_TEST_RUNNING" ]; then
    export WEB4_TEST_RUNNING=1
    ./idealminimalcomponent test
else
    npx vitest run --bail=false
fi
```

**Option B: Use npx to find web4tscomponent**
```bash
# test.sh:
npx --yes web4tscomponent test
```
- ✅ Works from any component
- ❌ Still has context recursion issue

**Option C: Direct vitest call from test.sh**
```bash
# test.sh:
npx vitest run --bail=false
```
- ✅ No recursion
- ❌ Bypasses web4tscomponent features (BAD)

**Option D: Check if test.sh is running before delegating**
```typescript
// In DefaultWeb4TSComponent.test():
const calledFromNpmTest = process.env.npm_lifecycle_event === 'test';
if (calledFromNpmTest && this.model.context) {
    // Don't call npm test again - call vitest directly
    execSync('npx vitest run --bail=false', ...);
} else {
    execSync('npm test', ...);
}
```

### **Proposed Solution: Option D (Smart Delegation)**

**Change in DefaultWeb4TSComponent.test():**
- Detect if already in `npm test` via `process.env.npm_lifecycle_event`
- If yes: call vitest directly (break recursion)
- If no: call `npm test` (use good default)

**Keep test.sh template:**
```bash
./{{COMPONENT_LOWER}} test  # or npx web4tscomponent test
```

**This achieves:**
- ✅ `npm test` → `idealminimalcomponent test` (GOOD DEFAULT enforced)
- ✅ No recursion (smart detection)
- ✅ All web4tscomponent features work
- ✅ Developers can't easily bypass to direct vitest
