# PDCA: Version Directory as Single Source of Truth

**File**: `2025-11-10-UTC-2314.version-directory-single-source-of-truth.pdca.md`  
**Component**: Web4TSComponent v0.3.19.0  
**Type**: Critical Architecture Violation Fix  
**Severity**: 🔴 CRITICAL - Violates fundamental Web4 multi-component principle

## PLAN

### Problem Statement

**CRITICAL ARCHITECTURAL VIOLATION DISCOVERED**:

The version information is being **manually set** in `model.version` instead of **derived from the directory path**, violating the fundamental Web4 principle:

> **"The version directory IS the single source of truth, NOTHING ELSE."**

### Current Violations

#### Violation 1: `updateModelPaths()` copies version from context

```typescript:270:276:src/ts/layer2/DefaultWeb4TSComponent.ts
private updateModelPaths(): void {
  // ✅ TRUE Radical OOP: Copy context data to THIS model (single source of truth)
  if (this.model.context) {
    this.model.component = this.model.context.model.component;
    this.model.version = this.model.context.model.version;  // ❌ WRONG!
  }
  // If no context, component/version already set in init()
```

**Problem**: Copying version from `context.model.version` violates single source of truth. Version should be derived from `componentRoot` path.

#### Violation 2: Building path FROM version (backward logic)

```typescript:294:298:src/ts/layer2/DefaultWeb4TSComponent.ts
this.model.targetComponentRoot = path.join(
  cli.model.componentsDirectory,
  this.model.component,
  this.model.version.toString()  // ❌ Using version to BUILD path
);
```

**Problem**: This builds the path FROM the version, but the version should be derived FROM the path.

#### Violation 3: Manual version assignment in `testShell()`

```typescript:1893:1894:src/ts/layer2/DefaultWeb4TSComponent.ts
const context = new DefaultWeb4TSComponent().init();
context.model.version = targetVersion;  // ❌ MANUAL OVERRIDE!
```

**Problem**: Manually setting `model.version` after `init()` violates single source of truth.

#### Violation 4: Scenario override in `init()`

```typescript:202:213:src/ts/layer2/DefaultWeb4TSComponent.ts

  }
}
```

**Problem**: Scenario can override the version discovered from directory. This is acceptable ONLY if the scenario also provides `componentRoot` or `targetComponentRoot` that matches the version.

### Root Cause Analysis

**The Correct Web4 Architecture**:

```
Directory Structure (File System)
       ↓
   (SINGLE SOURCE OF TRUTH)
       ↓
  componentRoot path
       ↓
  path.basename(componentRoot)
       ↓
   model.version
```

**Current Broken Flow**:

```
init() discovers version from directory  ✅
      ↓
scenario.model.version overrides it     ❌
      ↓
updateModelPaths() copies from context  ❌
      ↓
targetComponentRoot built from version  ❌ (backward!)
```

###

 Correct Architecture Principles

1. **Version is ALWAYS derived from directory path** (componentRoot or targetComponentRoot)
2. **Never store version separately** - it's a computed property from path
3. **Never copy version between objects** - each object derives from ITS OWN path
4. **Scenario CAN provide componentRoot** - but version is derived from it, not stored separately
5. **Path builds FROM component+version are only for TARGET operations** (like `on()`, `create()`)

### Solution Design

#### Option A: Version as Computed Property (Pure)

**Concept**: `model.version` is a getter that ALWAYS derives from `model.componentRoot`:

```typescript
get version(): SemanticVersion {
  const versionString = path.basename(this.model.componentRoot);
  return SemanticVersion.fromString(versionString);
}
```

**Pros**:
- True single source of truth
- Impossible to violate
- No synchronization issues

**Cons**:
- Breaking change (model.version becomes getter)
- Performance overhead (parsing on every access)
- SemanticVersion needs to be instantiated repeatedly

#### Option B: Version Derived in updateModelPaths() (Pragmatic)

**Concept**: `model.version` is stored, but ALWAYS recalculated from `componentRoot` in `updateModelPaths()`:

```typescript
private updateModelPaths(): void {
  // ✅ ALWAYS derive version from componentRoot (single source of truth)
  const versionString = path.basename(this.model.componentRoot);
  this.model.version = SemanticVersion.fromString(versionString);
  
  // ✅ Derive component name from parent directory
  this.model.component = path.basename(path.dirname(this.model.componentRoot));
  
  // ... rest of path calculations
}
```

**Pros**:
- No breaking changes
- Clear enforcement point
- Performance (version cached)

**Cons**:
- Still allows temporary violations (between init and updateModelPaths)
- Requires discipline to call updateModelPaths()

#### Option C: Hybrid - Derive from componentRoot, Allow targetComponentRoot Override

**Concept**: 
- `model.componentRoot` = THIS component's directory (where code runs from)
- `model.targetComponentRoot` = TARGET component's directory (for delegation/on)
- `model.version` = derived from `targetComponentRoot || componentRoot`

```typescript
private updateModelPaths(): void {
  // ✅ If we have a target (delegation/on), derive from targetComponentRoot
  // ✅ Otherwise, derive from componentRoot (direct mode)
  const sourcePath = this.model.targetComponentRoot || this.model.componentRoot;
  const versionString = path.basename(sourcePath);
  this.model.version = SemanticVersion.fromString(versionString);
  
  const componentName = path.basename(path.dirname(sourcePath));
  this.model.component = componentName;
  
  // ... rest
}
```

**Pros**:
- Handles both direct and delegation modes
- Clear precedence (target > self)
- Single source of truth maintained

**Cons**:
- More complex logic
- Need to ensure targetComponentRoot is set correctly

### Decision

**CHOOSE: Option C - Hybrid**

**Rationale**:
1. Supports multi-component architecture (self vs. target)
2. Maintains single source of truth (directory path)
3. Clear precedence rules
4. Backward compatible with delegation patterns

### Implementation Plan

1. **Update `updateModelPaths()`**:
   - ALWAYS derive `version` and `component` from path
   - Use `targetComponentRoot || componentRoot` as source
   - Remove version copying from context

2. **Update `init()`**:
   - Keep version discovery from directory
   - If scenario provides `componentRoot`, re-derive version after merge
   - Never trust `scenario.model.version` directly

3. **Update `testShell()` and similar methods**:
   - Set `targetComponentRoot` instead of `version`
   - Let `updateModelPaths()` derive version from path

4. **Add validation**:
   - Assert that `basename(componentRoot)` matches `version.toString()`
   - Throw error on mismatch

5. **Update templates**:
   - Ensure generated components follow same pattern
   - Document single source of truth in comments
