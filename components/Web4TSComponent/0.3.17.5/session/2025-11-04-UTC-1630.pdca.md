**Key Learnings:**

1. **Command Difference:**
   - `nextBuild` = upgrade existing version binaries
   - `create` = create new version directory structure

2. **DRY Delegation Pattern:**
   - PDCA (and all components) import `Web4TSComponent/latest` for delegation (line 80 in DefaultPDCA.ts)
   - This means PDCA always uses the current `latest` version for its operations
   - Even if loaded by an older Web4TSComponent CLI (e.g., `web4tscomponent-v0.3.17.4 on PDCA links`), PDCA 0.3.17.5 will still delegate to `Web4TSComponent/latest` (currently 0.3.17.5)
   - **Result:** `web4tscomponent-v0.3.17.4 on PDCA links` correctly shows `(via Web4TSComponent v0.3.17.5)` because PDCA itself uses `latest`

**Critical Dependency Discovery:**
The fix requires **BOTH** components to be fixed:
1. ✅ PDCA 0.3.17.5 must have `projectRoot` in delegation init
2. ✅ **Web4TSComponent `latest` must point to 0.3.17.5** (with the hardcoded version fix)

**Why:** PDCA imports `Web4TSComponent/latest` (line 80), NOT a specific version. If `latest` → buggy 0.3.17.4, PDCA will use buggy code!
