**10. Root Cause Analysis**

After thorough investigation, the root cause appears to be:

**HYPOTHESIS:** PDCA 0.3.17.4 was built/compiled when Web4TSComponent `latest` symlink pointed to 0.3.17.3. The version information got baked into the compiled JavaScript during the build process, and even though `latest` now points to 0.3.17.4, the compiled code still contains the old version reference.

**Evidence:**
- PDCA 0.3.17.4 imports from `Web4TSComponent/latest` (symlink)
- At build time, `latest` → 0.3.17.3
- Compiled code embedded version "0.3.17.3"
- Later, `latest` → 0.3.17.4  
- But compiled code still shows "0.3.17.3"

**11. The Real Bug: Build-Time Version Capture**

Looking more closely at the static import in DefaultPDCA.ts:

```typescript:14:14:components/PDCA/0.3.17.4/src/ts/layer2/DefaultPDCA.ts
import { DefaultWeb4TSComponent } from '../../../../../Web4TSComponent/latest/dist/ts/layer2/DefaultWeb4TSComponent.js';
```

When TypeScript compiles this, it:
1. Resolves `latest` symlink (to 0.3.17.3 at build time)
2. May capture version metadata from the resolved module
3. Embeds this in the compiled output

The version string "(via Web4TSComponent v0.3.17.3)" is likely:
- Either embedded in the compiled JavaScript during build
- Or read from the statically imported module's metadata
- Or displayed by a parent CLI framework that checks Web4TSComponent version
