## **📋 PLAN**

**Objective:** Fix parameter completion crash and add proper error handling for empty/null cases

**Requirements Traceability:** User feedback 2025-11-04-UTC-1450, continuation of 2025-11-04-UTC-1244

**Root Cause Analysis:**
1. **Crash**: `highlightParameter(signature, paramIndex)` calls `signature.match()` but signature can be null
2. **Missing signature**: `getMethodSignature()` returns simplified name, not full signature with `<parameters>`
3. **No fallback**: When signature parsing fails, no "(no completions available)" + prompt output

**Implementation Strategy:**
- **Fix 1: Null-safe highlighting**: Add null check in `highlightParameter()` before calling `.match()`
- **Fix 2: Better signature extraction**: Improve `getMethodSignature()` to find full formatted signature
- **Fix 3: Graceful degradation**: If signature not found, show method name without highlighting
- **Fix 4: Error handling**: Wrap signature/highlighting in try-catch, output proper feedback on failure

**🔵 Entry Criteria (Definition of Ready):**
- Parameter completion crashes with null error
- No feedback when signature extraction fails
- User sees hanging completion (no prompt)

**🟢 Definition of Done (DoD):**
- `highlightParameter()` handles null signatures gracefully
- `getMethodSignature()` returns full formatted signature
- On any error: outputs "(no completions available)" + prompt
- Test: `web4tscomponent cliSignature 2 web4tscomponent setCICDVersion ""` works
- No crashes, proper feedback
- Git committed
