# PDCA: Fix Delegated Method Completion (Radical OOP)

**Date**: 2025-11-10 UTC 22:00  
**Component**: Web4TSComponent 0.3.18.9  
**Type**: Architecture Fix  
**Severity**: High (violates Radical OOP principles)

## PLAN

### Problem Statement

**Observed Behavior**:
- `idealminimalcomponent upgrade n<TAB>` shows "(no completions available)"
- `idealminimalcomponent` (no args) does NOT list delegated methods
- Only shows 3 component-specific methods: `create`, `process`, `completion`

**Root Cause - ARCHITECTURAL VIOLATION**:

**❌ Current (WRONG)**: DelegationProxy **aggregates/merges** methods
```typescript
// DelegationProxy.listMethods() - WRONG!
listMethods(): string[] {
  const targetMethods = this.model.target.listMethods();
  const web4tsMethods = this.model.web4ts ? this.model.web4ts.listMethods() : [];
  return Array.from(new Set([...targetMethods, ...web4tsMethods])); // ❌ MERGING!
}
```

**Problem**: Wrapped component **claims to have methods it doesn't own**
- `IdealMinimalComponent.listMethods()` returns 123 methods
- But `IdealMinimalComponent` only HAS 3 methods: `create`, `process`, `completion`
- The other 120 methods belong to `Web4TSComponent`
- **This violates Radical OOP**: Component should know ONLY its own methods

### Correct Radical OOP Architecture

**Principle**: Delegated methods are **transparent implementation**, not advertised interface

1. **DelegationProxy should NOT aggregate/merge** ✅
   - `listMethods()` returns ONLY `this.model.target.listMethods()` (own methods)
   - Proxy does NOT claim to have delegated methods

2. **Wrapped component knows only its own methods** ✅
   - `IdealMinimalComponent` knows: `create`, `process`, `completion` (3)
   - Does NOT claim to have `upgrade`, `test`, `build` (120)

3. **CLI discovers delegated methods through metadata** ✅
   - New: `component.getDelegationTarget()` → returns Web4TSComponent instance
   - New: `component.hasDelegation()` → boolean indicating delegation exists
   - CLI queries delegation target **separately** for its methods

4. **Separate method lists maintained** ✅
   - CLI maintains TWO lists: own methods + delegated methods
   - MethodSignature gets new flag: `isDelegated: boolean`
   - Help display shows sections: "Own Methods" vs "Delegated Methods"

5. **Delegation is transparent at call-time** ✅
   - Proxy's `get` trap intercepts missing methods
   - Delegation happens when method is **called**, not when it's **listed**

### Solution Design

**Architecture**:
```
CLI.initComponent():
├─ 1. Create component (knows its OWN methods)
│     const component = await new DefaultComponent().init();
│     component.listMethods() → ['create', 'process', 'completion']
│
├─ 2. Pre-load Web4TSComponent (knows ITS methods)
│     await component.getWeb4TSComponent();
│     web4ts.listMethods() → ['upgrade', 'test', 'build', ...]
│
├─ 3. Wrap with DelegationProxy (transparent delegation)
│     const proxy = DelegationProxy.start(component);
│     proxy.listMethods() → ['create', 'process', 'completion'] ← ONLY own!
│
├─ 4. Discover CLI's own methods
│     this.discoverMethods();
│
└─ 5. Discover component + delegated methods (SEPARATELY)
      ├─ Own: proxy.listMethods() → add to methodSignatures
      └─ IF proxy.hasDelegation():
           ├─ Delegated: proxy.getDelegationTarget().listMethods()
           └─ Mark as delegated (signature.isDelegated = true)
```
