# PDCA: Fix Upgrade Delegation and Completion Issues

**Date**: 2025-11-10 UTC 20:30  
**Component**: Web4TSComponent  
**Version**: 0.3.18.9  
**Type**: BUG FIX - Critical delegation issues in upgrade and completion

## Context

Two critical bugs were discovered in test isolation:

1. **Upgrade Delegation Bug**: When calling `idealminimalcomponent upgrade`, it upgraded `Web4TSComponent` instead of `IdealMinimalComponent`
2. **Completion Initialization Bug**: Parameter completion showed "(no completions available)" because `shCompletion` didn't call `initComponent()`

These bugs were discovered during interactive testing in test isolation.

## PLAN

### Root Cause Analysis

**Bug 1: Upgrade Delegation**
- The `upgrade()` method used `this.model.component` directly
- In delegation context, `this` is `Web4TSComponent`, so it upgraded itself
- Should use `getTarget()` pattern to get the correct component (IdealMinimalComponent)

**Bug 2: Completion Initialization**
- Generated component CLIs have asynchronous `initComponent()` method
- Bash completion calls CLI → `shCompletion()` directly (not via `static start()`)
- `shCompletion()` in base `DefaultCLI` doesn't know about `initComponent()`
- Without initialization, dynamic method discovery hasn't run → no method signatures → no completions

### Solution Design

**Fix 1: Use getTarget() in upgrade()**
- Update `upgrade()` method to call `getTarget()` for correct component identity
- Use target's component name and version for all operations
- When delegated (`target !== this`), temporarily set `this.model.component` and `this.model.version` for `createVersionFromExisting()`

**Fix 2: Override shCompletion in generated CLIs**
- Add `shCompletion()` override in `ComponentCLI.ts.template`
- Check if `this.component` is initialized
- If not, call `await this.initComponent()` before delegating to parent
- This ensures dynamic method discovery runs before completion

### Test Strategy

Add two new test cases to `idealminimalcomponent-creation-isolation.test.ts`:
1. `should initialize component automatically in shCompletion for method discovery` - Verifies auto-initialization
2. `should upgrade correct component when delegated` - Verifies upgrade creates IdealMinimalComponent, not Web4TSComponent

#### Step 1: Fix upgrade() delegation ✅
**File**: `src/ts/layer2/DefaultWeb4TSComponent.ts`

```typescript
async upgrade(versionPromotion: string = 'nextPatch'): Promise<this> {
  this.printQuickHeader();
  
  // @pdca 2025-11-10-UTC-2030.fix-upgrade-delegation.pdca.md - Use getTarget() for correct component
  const target = this.getTarget();
  const targetComponent = target.model.component || this.model.component;
  const targetVersion = target.model.version || this.model.version;
  
  const nextVersion = await SemanticVersion.promote(targetVersion.toString(), versionPromotion);
  console.log(`🔧 Upgrading ${targetComponent}: ${targetVersion.toString()} → ${nextVersion}`);
  
  this.model.toVersion = nextVersion;
  
  // Ensure we're operating on the correct component
  if (target !== this) {
    // Delegated call: set target's component info in our model
    this.model.component = targetComponent;
    this.model.version = targetVersion;
  }
  
  await this.createVersionFromExisting();
  await this.updateSymlinks();
  
  console.log(`✅ ${targetComponent} ${nextVersion} created successfully`);
  console.log(`   Location: components/${targetComponent}/${nextVersion}`);
  
  if (this.model.context) {
    this.model.context.model.version = SemanticVersion.fromString(nextVersion);
    this.model.context.model.origin = `components/${targetComponent}/${nextVersion}`;
  }
  
  return this;
}
```

async shCompletion(cword: string, ...words: string[]): Promise<void> {
  // CRITICAL: Initialize component before completion (dynamic method discovery)
