# PDCA: Fix Delegated Method Completion

**Date**: 2025-11-10 UTC 22:00  
**Component**: Web4TSComponent 0.3.18.9  
**Type**: Bug Fix  
**Severity**: High (breaks UX for delegated components)

## PLAN

### Problem Statement

**Observed Behavior**:
- `idealminimalcomponent upgrade n<TAB>` shows "(no completions available)"
- `idealminimalcomponent` (no args) does NOT list delegated methods like `upgrade`, `test`, `build`, etc.
- Only shows component-specific methods: `create`, `process`, `completion`

**Root Cause**:
DelegationProxy successfully proxies method **calls** but does NOT expose delegated methods for **discovery/listing**. The CLI's help output and bash completion rely on method listing, which only sees the component's own methods, not the proxied ones.

**Evidence**:
```bash
# web4tscomponent (direct) - shows upgrade ✅
web4tscomponent upgrade <versionPromotion>
  Possible Values: 'nextPatch', 'nextMinor', 'nextMajor', 'nextBuild'

# idealminimalcomponent (delegated) - NO upgrade shown ❌
idealminimalcomponent
Commands:
  create, process, completion
  # ← upgrade is missing!
```

### Root Cause Analysis (DETAILED)

**The Radical OOP Architecture**:

```
┌─────────────────────────────────────────────────────────────┐
│ CLI (IdealMinimalComponentCLI)                              │
│ - Knows: CLI methods (execute, showUsage, etc.)            │
│ - Has: this.component (DelegationProxy wrapper)            │
│ - Needs: Component methods for help/completion             │
└───────────────────┬─────────────────────────────────────────┘
                    │ asks via this.component.listMethods()
                    ▼
┌─────────────────────────────────────────────────────────────┐
│ DelegationProxy                                             │
│ - Wraps: IdealMinimalComponent (this.model.target)         │
│ - Has: Web4TSComponent (this.model.web4ts)                 │
│ - listMethods() SHOULD return: target + web4ts methods     │
│ - PROBLEM: web4ts not loaded when listMethods() called!    │
└───────────┬────────────────────────┬────────────────────────┘
            │                        │
            ▼                        ▼
┌─────────────────────┐    ┌─────────────────────────────┐
│ IdealMinimalComp    │    │ Web4TSComponent             │
│ - create()          │    │ - upgrade()                 │
│ - process()         │    │ - test()                    │
│ - listMethods()     │    │ - build()                   │
│   returns own only  │    │ - listMethods()             │
└─────────────────────┘    │   returns own only          │
                           └─────────────────────────────┘
```

**The Problem**:
1. `DelegationProxy.setTarget()` fires `this.getWeb4TS()` asynchronously (fire-and-forget)
2. `CLI.initComponent()` immediately calls `this.component.listMethods()`
3. At this moment, `this.model.web4ts` is still `undefined` (loading not finished)
4. `DelegationProxy.listMethods()` returns only target methods (web4ts array is empty)
5. CLI only sees `create`, `process` - NOT `upgrade`, `test`, etc.

**Radical OOP Violation**:
- We're trying to ask the DelegationProxy for methods BEFORE it's fully initialized
- The async loading of web4ts breaks the synchronous discovery contract
- This violates "single source of truth" - the Proxy doesn't yet know what it can do!

### Solution Design (Radical OOP) - CORRECTED

**❌ INITIAL APPROACH WAS WRONG**:
- DelegationProxy was **aggregating/merging** methods from target + web4ts
- This violates Radical OOP: component claims to have methods it doesn't own
- Delegated methods should be **transparent implementation**, not advertised interface

**✅ CORRECT RADICAL OOP APPROACH**:

**Principle**: Delegated methods are transparent at **call-time**, NOT at **discovery-time**

1. **DelegationProxy should NOT aggregate/merge**
   - `listMethods()` returns ONLY `this.model.target.listMethods()` (own methods)
   - Proxy does NOT claim to have delegated methods

2. **Wrapped component knows only its own methods**
   - `IdealMinimalComponent` knows: `create`, `process`, `completion`
   - Does NOT claim to have `upgrade`, `test`, `build`

3. **CLI discovers delegated methods through metadata**
   - New: `component.getDelegationTarget()` → returns Web4TSComponent instance
   - New: `component.hasDelegation()` → boolean indicating delegation exists
   - CLI queries delegation target **separately** for its methods

4. **Separate method lists maintained**
   - CLI maintains TWO lists: own methods + delegated methods
   - MethodSignature gets new flag: `isDelegated: boolean`
   - Help display can show sections: "Own Methods" vs "Delegated Methods"

**Architecture**:
```
CLI.initComponent():
├─ 1. Discover CLI's own methods (execute, showUsage, etc.)
├─ 2. Get component's own methods (component.listMethods())
└─ 3. IF component.hasDelegation():
      ├─ Get delegation target (component.getDelegationTarget())
      └─ Get delegated methods (target.listMethods())
         └─ Mark as delegated (signature.isDelegated = true)
```

**Implementation**:
- `DelegationProxy.listMethods()`: Remove aggregation, return ONLY target methods
- `DelegationProxy.getDelegationTarget()`: NEW - returns web4ts instance
- `DelegationProxy.hasDelegation()`: NEW - returns !!this.model.web4ts
- `ComponentCLI.initComponent()`: Separate discovery of own vs delegated
- `MethodSignature.interface`: Add `isDelegated?: boolean` flag
- Con: Breaks all existing code

**Decision**: **Option 1** - Pre-load in CLI, keep interfaces clean

### Implementation Plan (Radical OOP)

1. **Update ComponentCLI.ts.template**:
   ```typescript
   async initComponent(): Promise<void> {
     // 1. Create component (knows its OWN methods)
     const component = await new DefaultComponent().init();
     
     // 2. Pre-load Web4TSComponent (knows ITS methods)
     await component.getWeb4TSComponent();
     
     // 3. Wrap with DelegationProxy (NOW knows BOTH)
     this.component = DelegationProxy.start(component);
     
     // 4. Discover CLI methods (CLI knows ITS methods)
     this.discoverMethods();
     
     // 5. Copy component methods (merged list) to methodSignatures
     const componentMethods = this.component.listMethods(); // ← This works now!
     for (const methodName of componentMethods) {
       const signature = this.component.getMethodSignature(methodName);
       if (signature) {
         this.methodSignatures.set(methodName, signature);
       }
     }
   }
   ```

2. **Update DelegationProxy.setTarget()**:
   - Keep fire-and-forget, but document it's a fallback
   - Primary initialization happens in CLI

3. **Verify separation of concerns**:
   - CLI: Aggregates for display, but doesn't OWN component methods
   - Component: Knows own methods
   - Web4TSComponent: Knows own methods
   - DelegationProxy: Knows both by asking each instance
