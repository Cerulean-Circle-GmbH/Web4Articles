### **Architecture Analysis**

**THREE COMMAND SOURCES:**

1. **`this.cliMethods` (Map<string, MethodSignature>)**
   - **What:** CLI's OWN methods: `on`, `test`, `completion`, `completeParameter`, `shCompletion`
   - **When Set:** During CLI's own `discoverMethods()` (lines 687-712)
   - **Lifecycle:** Set once in constructor, persists for CLI lifetime
   - **Purpose:** CLI coordination methods, not component methods

2. **`this.component` (Reference<DefaultWeb4TSComponent>)**
   - **What:** PRIMARY component instance (DefaultWeb4TSComponent)
   - **When Set:** In Web4TSComponentCLI constructor (line 31): `this.component = new DefaultWeb4TSComponent().init();`
   - **Lifecycle:** Set once, always available
   - **Methods:** `build`, `version`, `tree`, `listResources`, etc.
   - **Discovery:** Component self-discovers in its `init()` method (PDCA 2025-11-05-UTC-1158)
   - **Storage:** Private `this.methods` Map inside DefaultWeb4TSComponent
   - **Access:** Via Component interface: `hasMethod()`, `getMethodSignature()`, `listMethods()`

3. **`this.context` (Reference<Component>)**
   - **What:** DELEGATED component (loaded by `on()` command)
   - **When Set:** In `on()` method (DefaultCLI line 262): `this.context = targetComponent;`
   - **Lifecycle:** Null initially, set after `on()` is called
   - **Example:** `web4tscomponent on PDCA 0.3.17.9` → loads PDCA component as context
   - **Methods:** Context-specific methods like `links`, `trainAI`, `cmm3check` (PDCA)
   - **Discovery:** Context component self-discovers in its `init()` method
   - **Storage:** Private `this.methods` Map inside context component
   - **Access:** Via Component interface: `hasMethod()`, `getMethodSignature()`, `listMethods()`

  let signature: MethodSignature | null = null;

#### **Q1: Should CLI remove batch discovery of component/context methods?**

**Options:**
- **2a**: REMOVE lines 714-755 completely (each object discovers itself)
- 2b: KEEP batch discovery, ignore self-discovery (continue functional approach)
- 2c: Hybrid - batch for usage display, self-discovery for routing

**Decision: 2a** - Remove lines 714-755

**Rationale:**
- **Radical OOP:** Each object knows its own methods, CLI should not discover them
- **DRY:** Component already discovers itself in `init()`, no need to rediscover
- **Clear Ownership:** Component owns its methods, not CLI
- **Type Safety:** Routing uses Component interface (`hasMethod()`), not batch discovery
- **Self-Discovery Pattern:** Completing pattern from PDCA 2025-11-05-UTC-1158
- **Event-Driven:** Components discover themselves when created, not batch-discovered by CLI

**Options:**
- **2a**: CLI → Context → Component (matches current execution priority)
- 2b: Component → Context → CLI (component-first)

**Rationale:**
