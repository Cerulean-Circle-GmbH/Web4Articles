## 1. Problem Statement

**Observable Behavior:**
- `web4tscomponent test itCase <Tab>` shows hierarchical display correctly
- But when bash extracts WORD completions, it shows FILENAMES (e.g., `web4tscomponent.template-sync.test.ts`) instead of test case references (e.g., `18a12`)
- This forces users to type filenames instead of test case tokens

**Expected Behavior:**
- `web4tscomponent test itCase <Tab>` should complete with test case references like `18a12`, `18a13`, `5a1`, etc.
- User should be able to type: `web4tscomponent test itCase 18a12` to run ONLY that specific test case

**Root Cause:**
The word extraction logic in `formatCompletionOutput()` (lines 2234-2245) does not understand itCase token format. When processing hierarchical display lines like `"18:  web4tscomponent.template-sync.test.ts"`, it extracts the filename instead of skipping file header lines and extracting tokens from it case lines like `"         18a12) should work"`.

**Impact:**
- User experience regression: Cannot use Tab completion to discover and complete test case references
- Forces manual lookup of test case numbers in test files
- Inconsistent with expected hierarchical completion behavior

---

## 2. Root Cause Analysis (5 Whys)

**Why 1:** Why does `test itCase <Tab>` show filenames instead of case references?  
→ Because `formatCompletionOutput()` extracts the filename from file header lines like `"18: web4tscomponent.template-sync.test.ts"`.

**Why 2:** Why does formatCompletionOutput extract filenames from header lines?  
→ Because the word extraction regex `^\d+:\s*(\S+)` matches `"18: filename"` and captures the filename as the completion word.

**Why 3:** Why doesn't it extract itCase tokens instead?  
→ Because the extraction logic doesn't distinguish between different hierarchical scopes (file, describe, itCase) and doesn't understand the `\d+[a-z]\d+)` token format.

**Why 4:** Why doesn't the logic understand itCase token format?  
→ Because `formatCompletionOutput()` is scope-agnostic and processes all hierarchical displays the same way, without knowledge of which scope (file/describe/itCase) is being completed.

**Why 5:** Why is formatCompletionOutput scope-agnostic?  
→ Because it was designed as a generic formatter for all completion types. The hierarchical completion refactoring added file/describe/itCase scopes, but the word extraction logic wasn't updated to handle itCase token patterns.

**Root Cause:**
`formatCompletionOutput()` needs to be aware of the completion scope to extract the correct tokens. For itCase scope, it should:
1. Skip file header lines (format: `\d+:\t.*`)
2. Extract tokens matching the itCase pattern: `(\d+[a-z]\d+)\)` from lines with proper indentation
3. Return ONLY the token (e.g., `18a12`) not the entire line

### Investigation: Current Token Extraction Logic

Reading `DefaultCLI.ts` lines 2234-2254:
```typescript
// Extract word: "1: methodName <params>" -> "methodName" OR "1:\tfilename" -> "1"
// @pdca 2025-11-05-UTC-1616 - Extract token (number) for hierarchical completions
// Check if this is a hierarchical token (number followed by tab or colon-space-tab)
const hierarchicalMatch = cleanLine.match(/^(\d+):\t/);
let word;
if (hierarchicalMatch) {
  // Hierarchical format: "1:\tfilename" -> extract "1"
  word = hierarchicalMatch[1];
} else {
  // Method format: "1: methodName <params>" -> extract "methodName"
  const methodMatch = cleanLine.match(/^\d+:\s*(\S+)/);
  word = methodMatch ? methodMatch[1] : cleanLine.split(" ")[0];
}
```

**Problem Identified:**
- For file scope, line format is: `"18:\tfilename.test.ts"` → extracts "18" ✅ correct
- For itCase scope, file header is: `"18:  filename.test.ts"` (spaces, not tab) → matches `^\d+:\s*(\S+)` → extracts "filename.test.ts" ❌ wrong!
- Should extract from itCase lines: `"         18a12) should work"` → should extract "18a12" ✅ correct

**Solution:**
Make word extraction scope-aware:
1. Check `this.model.completionCompWords[2]` for scope (file/describe/itCase)
2. For itCase, use pattern: `(\d+[a-z]\d+)\)` to extract tokens
3. For describe, use pattern: `(\d+[a-z])\)` to extract tokens
4. For file, keep existing logic (extract number from `\d+:\t`)

### Implementation: Scope-Aware Token Extraction

**Modified:** `DefaultCLI.ts` lines 2227-2290

**Change:** Made word extraction scope-aware to handle itCase and describe token patterns.

**Key Implementation Details:**

1. **Extract scope from model state:** `const scope = this.model.completionCompWords[2]`
2. **For itCase/describe: Process ALL lines** (not just first line)
3. **Scope-specific token patterns:**
   - `itCase`: `/(\d+[a-z]\d+)\)/` extracts "18a12" from "         18a12) should work"
   - `describe`: `/(\d+[a-z])\)/` extracts "18a" from "    18a) Test Cases"  
   - `file` (default): `/^(\d+):\t/` extracts "18" from "18:\tfilename.test.ts"

**Code:**
```typescript
// Get scope from model (format: ['web4tscomponent', 'test', 'file|describe|itCase', ...])
const scope = this.model.completionCompWords[2];

values.forEach((value: string) => {
  // For itCase/describe scopes, extract ALL tokens from ALL lines
  // For other scopes, extract word from FIRST LINE only
  const linesToProcess = (scope === 'itCase' || scope === 'describe') 
    ? value.split("\n") 
    : [value.split("\n")[0]];
  
  linesToProcess.forEach((line: string) => {
    const cleanLine = line.replace(/\x1b\[[0-9;]*m/g, "");
    let word: string | undefined;
    
    if (scope === 'itCase') {
      const itCaseMatch = cleanLine.match(/(\d+[a-z]\d+)\)/);
      if (itCaseMatch) word = itCaseMatch[1]; // "18a12"
    } else if (scope === 'describe') {
      const describeMatch = cleanLine.match(/(\d+[a-z])\)/);
      if (describeMatch) word = describeMatch[1]; // "18a"
    } else {
      // file scope / methods (existing logic)
      const hierarchicalMatch = cleanLine.match(/^(\d+):\t/);
      if (hierarchicalMatch) {
        word = hierarchicalMatch[1];
      } else {
        const methodMatch = cleanLine.match(/^\d+:\s*(\S+)/);
        word = methodMatch ? methodMatch[1] : cleanLine.split(" ")[0];
      }
    }
    
    if (!word) return; // Skip lines without tokens
    
    // Strip parameter syntax if present
    const paramMatch = word.match(/^<\??([^>:'"]+)/);
    if (paramMatch) word = paramMatch[1];
    
    lines.push(`WORD: ${word}`);
  });
});
```
