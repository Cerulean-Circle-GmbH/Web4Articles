## 1. PLAN (Problem Statement & Root Cause)

### Problem Statement

The component violates **Path Authority Principle** by calculating paths instead of using model values. This creates:
- Semantic confusion about `targetDirectory`
- Path inspection instead of semantic flags
- Functional programming patterns instead of Radical OOP
- Test isolation failures

### Observable Behavior

```typescript
// ❌ CURRENT: Component calculates paths
resolveComponentPath(name, version) {
  return join(this.model.targetDirectory, 'components', name, version);
}

// ❌ CURRENT: Component inspects path structure
isTestEnvironment() {
  return this.model.targetDirectory.includes('/test/data');
}
```

### Root Cause Analysis

**Violation Type:** Path Authority + Radical OOP violations

**Affected Methods:**
1. `resolveComponentPath()` - Calculates from `targetDirectory`
2. `resolveProjectRoot()` - Returns `targetDirectory` (semantic confusion)
3. `resolveComponentDirectory()` - Calculates from `targetDirectory`
4. `isTestEnvironment()` - Inspects path structure
5. ALL methods using these helpers inherit the violation

**Why This Matters:**
- **Semantic**: `targetDirectory` conflates "workspace root" and "operation context"
- **Test Isolation**: Can't properly set test/data context
- **OOP**: Component shouldn't calculate, only USE model

### CMM3 Compliance

✅ **Objective:** Path calculations are observable in code  
✅ **Reproducible:** Same violations exist across all operations  
✅ **Verifiable:** Can trace all path calculations

## 2. PLAN (Solution Design)

### Radical OOP Model Design

```typescript
interface Web4TSComponentModel {
  // === IDENTITY (Component discovers these itself) ===
  component: string;              // 'Web4TSComponent'
  version: SemanticVersion;       // 0.3.17.9
  componentRoot: string;          // Where THIS component lives
  
  // === CONTEXT (CLI provides these) ===
  projectRoot: string;            // Workspace root (always)
  targetDirectory: string;        // WHERE TO CREATE/OPERATE
  componentsDirectory: string;    // Pre-calculated: targetDirectory + '/components'
  
  // === FLAGS (Semantic, not path inspection) ===
  isTestIsolation: boolean;       // True if in test/data mode
  testDataDirectory?: string;     // Only set if isTestIsolation
  
  // === CONTEXT LOADING (for delegation) ===
  context: Web4TSComponent | null; // Loaded component for "on" commands
}
```

### Path Responsibility Matrix

**Legend:** `§` = device-dependent projectRoot (e.g., `/Users/Shared/Workspaces/temp/Web4Articles`)

| Path Type | Calculated By | Used By | Example |
|-----------|---------------|---------|---------|
| `projectRoot` | CLI (once, from cwd) | Component (read-only) | `§` |
| `componentRoot` | Component (self-discovery from `import.meta.url`) | Component (read-only) | `§/components/Web4TSComponent/0.3.17.9` |
| `targetDirectory` | CLI (per operation context) | Component (read-only) | **Prod:** `§`<br>**Test Isolation:** `§/components/Web4TSComponent/0.3.17.9/test/data` |
| `componentsDirectory` | CLI (pre-calculated once) | Component (read-only) | **Prod:** `§/components`<br>**Test Isolation:** `§/components/Web4TSComponent/0.3.17.9/test/data/components` |

### Phase 3: Remove Path Calculations

**Methods to REMOVE:**
1. `resolveComponentPath(name, version)` - Users should use `model.componentsDirectory`
2. `resolveProjectRoot()` - Users should use `model.projectRoot` directly
3. `resolveComponentDirectory(name)` - Users should use `model.componentsDirectory`
4. `isTestEnvironment()` - Users should use `model.isTestIsolation` flag

**Pattern for replacement:**

```typescript
// ❌ BEFORE (component calculates):
const componentPath = this.resolveComponentPath(name, version);
// internally does: path.join(this.model.targetDirectory, 'components', name, version)

// ✅ AFTER (component uses model):
const componentPath = path.join(this.model.componentsDirectory, name, version);
// CLI already calculated componentsDirectory = targetDirectory + '/components'
```
