### **ROOT CAUSE ANALYSIS - RESOLVED:**

**PDCA 2025-11-05-UTC-1809.pdca.md identified the root cause:**

**Context Persistence Bug:** Commands route to `this.context || this.component`, but context-aware methods (like `updateBuildSystem`) run on the WRONG instance:
- `on()` sets `this.component.model.context = targetComponent` ✅
- But routing sends command to `this.context` (which has NO context set) ❌
- Method checks `if (!this.model.context)` and fails ❌

**Solution (Option D - Self-Reference):**
```typescript
// In DefaultCLI.ts on() method, add one line:
(this.context.model as any).context = targetComponent;
```

This sets context on BOTH instances, fixing context-aware methods.

- **0.3.17.9:** OLD templates ❌ (46 lines, no clean-local.sh, PDCA context artifact)

**Critical Finding:** BOTH 0.3.17.8 AND 0.3.17.9 have OLD templates!

**Why this happened:**
- 0.3.17.7 shell scripts improved DIRECTLY in src/sh
- Improvements NOT propagated to templates/ directory
- Subsequent versions (0.3.17.8, 0.3.17.9) created from OLD templates
- Template sync test EXISTS but not enforced during upgrade workflow

**Where templates come from (updateBuildSystem):**
```
Calling Component's templates/ directory
  ↓ (loadWeb4TSComponentTemplate)
Web4TSComponent templates/sh/*.template
  ↓ (updateBuildSystem)
Target component's src/sh/*.sh
```

**The break:** 0.3.17.7 improvements stayed local, never updated templates/ → all subsequent versions have OLD scripts

**Version Chain Impact:**
- Using `latest` (0.3.17.8) would propagate OLD templates to 0.3.17.9 (no fix)
- Using 0.3.17.9 itself would self-reference OLD templates (no fix)
- MUST use 0.3.17.7 explicitly OR fix chain 0.3.17.8 → 0.3.17.9
