### Part 4: printQuickHeader() Should Read from Model, Not Environment

**Lines in `DefaultWeb4TSComponent.ts`** (buildTestIsolationLine):
```typescript
private buildTestIsolationLine(): string | null {
  const target = this.getTarget();
  
  // ❌ VIOLATES WEB4 PRINCIPLES: Checking environment variable!

  if (target.model.isTestIsolation || process.env.IS_TEST_ISOLATION === 'true') {

  return null;
}
```

**Web4 Principle Violation**:
- ❌ Checking `process.env.IS_TEST_ISOLATION` violates environment-agnostic principle
- ❌ State should come from MODEL (scenario), not environment
- ❌ Functional programming (checking external state) not Radical OOP

**Radical OOP Fix**:
```typescript
private buildTestIsolationLine(): string | null {
  const target = this.getTarget();
  
  // @pdca 2025-11-10-UTC-1230.test-isolation-path-pollution-analysis.pdca.md
  // Web4 Principle: State comes from MODEL, not environment (environment-agnostic)
  if (target.model.isTestIsolation) {
    const context = this.getTestIsolationContext();
    return `🔬 ${this.colors.yellow}TEST ISOLATION MODE${this.colors.reset} - ${context}`;
  }
  
  return null;
}
```

**How It Should Work**:
1. Component detects test isolation from its calculated paths
2. Sets `this.model.isTestIsolation = true` in its model
3. Delegates to Web4TSComponent with `context: this`
4. Web4TSComponent reads `target.model.isTestIsolation` via `getTarget()`
5. No environment variables needed!

## Check: Why Production Scripts Are Still Found

**The Smoking Gun**:
```bash
$ web4tscomponent test shell 0.3.18.5
[TEST ISOLATION] > which idealminimalcomponent
/Users/Shared/Workspaces/temp/Web4Articles/scripts/idealminimalcomponent  # PRODUCTION!
```

**Why?**:
1. `source "${componentSourceEnv}"` sources `/Users/Shared/Workspaces/temp/Web4Articles/components/Web4TSComponent/0.3.18.5/source.env`

### Fix 4: Propagate isTestIsolation Flag to Components ✅ REQUIRED

**Web4 Principle**: NO environment variables! Use Radical OOP model-based detection.

**Where**: Components detect test isolation from their own paths at initialization

**Radical OOP Approach**:
```typescript
// In DefaultIdealMinimalComponent.getWeb4TSComponent():
// Path Authority: Calculate paths from file system
const componentRoot = ...; // Current component's root
const projectRoot = ...; // Project root

// @pdca 2025-11-10-UTC-1230.test-isolation-path-pollution-analysis.pdca.md
// Web4 Principle: Detect test isolation from model paths, NOT environment variables
const isTestIsolation = projectRoot.includes('/test/data') || 
                        componentRoot.includes('/test/data');

// Store in THIS component's model (single source of truth)
this.model.isTestIsolation = isTestIsolation;
this.model.projectRoot = projectRoot;
this.model.componentRoot = componentRoot;
this.model.targetDirectory = projectRoot;
this.model.targetComponentRoot = componentRoot;

// Delegate to Web4TSComponent with context
const web4ts = new DefaultWeb4TSComponent().init({
  model: {
    version: await SemanticVersion.fromString('0.3.18.4'),
    componentRoot: componentRoot,
    targetDirectory: projectRoot,
    context: this,  // Context carries isTestIsolation in ITS model
  },
});
```

**Key: Context Delegation Pattern**
- Delegating component detects test isolation from its paths
- Stores `isTestIsolation` in its own model
- Passes itself as `context` to Web4TSComponent
- Web4TSComponent reads `context.model.isTestIsolation` via `getTarget()`
