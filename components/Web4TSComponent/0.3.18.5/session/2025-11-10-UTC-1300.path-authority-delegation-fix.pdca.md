### Part 1: How CLI Calculates Project Root

**From `DefaultCLI.ts` (lines 149-169)**:

```typescript
private calculateProjectRootInternal(): string {
  const cwd = process.cwd();
  
  // 1. Check for test isolation FIRST (highest priority)
  // Example: .../Web4Articles/components/Web4TSComponent/0.3.18.5/test/data/components/TestComponent/0.1.0.0
  // Result: .../Web4Articles/components/Web4TSComponent/0.3.18.5/test/data
  if (cwd.includes('/test/data')) {
    const parts = cwd.split('/');
    const testIndex = parts.indexOf('test');
    if (testIndex !== -1 && testIndex + 1 < parts.length && parts[testIndex + 1] === 'data') {
      // Return path UP TO AND INCLUDING test/data
      return parts.slice(0, testIndex + 2).join('/');
    }
  }
  
  // 2. Use git root (NOT environment variable)
  try {
    const gitRoot = execSync('git rev-parse --show-toplevel', { 
      encoding: 'utf-8',
      stdio: ['pipe', 'pipe', 'ignore']
    }).trim();
    return gitRoot;
  } catch {
    // Fallback: Find components/ directory by walking up
    let current = cwd;
    while (current !== '/') {
      if (existsSync(path.join(current, 'components'))) {
        return current;
      }
      current = path.dirname(current);
    }
    return cwd;
  }
}
```

**Key Insights**:
1. ✅ **Test isolation detection is built-in** - Checks `cwd.includes('/test/data')`
2. ✅ **Correctly finds test/data boundary** - Uses `indexOf('test')` not `split()`
3. ✅ **Fallback logic** - Uses git root, then walks up filesystem
4. ✅ **Already perfect** - No need to reimplement this!

### Part 4: Solution - Bootstrap from Component Root

**Key Insight**: We CAN calculate `componentRoot` from `__filename` (that's correct Path Authority - component knows its own location). Then derive Web4TSComponent location from that:

```typescript
private async getWeb4TSComponent(): Promise<any> {
  if (this.web4ts) return this.web4ts;

  const path = await import('path');
  const url = new URL(import.meta.url);
  const __filename = url.pathname;
  
  // ✅ Path Authority: Component knows its OWN location
  const componentRoot = path.resolve(path.dirname(__filename), '../../..');
  
  // ✅ Path Authority: Derive infrastructure location from component location
  // Component is at: .../projectRoot/components/IdealMinimalComponent/0.1.0.0
  // Web4TS is at:    .../projectRoot/components/Web4TSComponent/latest
  // Both share the SAME components/ directory
  const componentsDir = path.dirname(path.dirname(componentRoot)); // Up to components/
  const web4tsPath = path.join(componentsDir, 'Web4TSComponent', 'latest');
  
  // ✅ Create CLI (which will calculate projectRoot correctly)
  const { Web4TSComponentCLI } = await import(
    `${web4tsPath}/dist/ts/layer5/Web4TSComponentCLI.js`
  );
  
  const cli = new Web4TSComponentCLI();
  // CLI.init() called projectRoot = calculateProjectRootInternal()
  // CLI correctly detected test isolation!
  
  // ✅ Set delegation context (not component identity override!)
  cli.component.model.context = this;
  
  // ✅ Store component's own paths in its model
  this.model.componentRoot = componentRoot;
  this.model.projectRoot = cli.model.projectRoot;  // ✅ From CLI!
  this.model.isTestIsolation = cli.model.projectRoot.includes('/test/data');  // ✅ Detected by CLI!
  
  this.web4ts = cli.component;
  return this.web4ts;
}
```

**Why This Works**:
1. ✅ Component calculates its OWN location (allowed)
2. ✅ Derives Web4TSComponent location from shared parent (no path calculation)
3. ✅ Creates CLI which does proper path calculation via `calculateProjectRootInternal()`
4. ✅ Gets correct `projectRoot` from CLI
5. ✅ Test isolation automatically detected by CLI
6. ✅ Component has back-reference via `cli.component.cli = this` (set in CLI constructor)

## Summary: Key Decisions

### Decision 1: Who Calculates Paths?

**ONLY the CLI calculates projectRoot** via `calculateProjectRootInternal()`

Components:
- ✅ CAN calculate their own `componentRoot` (from `__filename`)
- ✅ CAN derive infrastructure location (shared parent directory)
- ❌ MUST NOT calculate `projectRoot` (Path Authority violation)
- ✅ MUST get `projectRoot` from CLI

### Decision 2: How to Bootstrap?

**Component → componentsDir → Web4TSComponentCLI → projectRoot**

1. Component calculates its location
2. Derives components/ directory (shared parent)
3. Imports Web4TSComponentCLI from that directory
4. CLI calculates projectRoot correctly
5. Component reads projectRoot from CLI

### Decision 3: Delegation Pattern

**Create CLI, not component directly**

```typescript
// ❌ OLD: Create component directly
const web4ts = new DefaultWeb4TSComponent().init({...});

// ✅ NEW: Create CLI (which creates component with back-reference)
const cli = new Web4TSComponentCLI();
cli.component.model.context = this;
const web4ts = cli.component;
```
