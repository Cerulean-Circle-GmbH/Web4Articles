## Plan

### Context
The retroactive isolation architecture (v0.3.14.4) successfully prevents old CLI versions from modifying production state by forcing them into isolated `test/data` environments. However, users have no visual indication when they're running in:
1. Test isolation mode (old version in test/data)
2. Cursor agent mode (special shell handling to prevent hangs)

### Goal
Add clear visual indicators to the `source.env` welcome message that show:
- 🧪 Test Isolation status with component name and version
- 🤖 Cursor Agent Mode status

### Approach
1. Update `source.env` template with detection logic
2. Update test/data `source.env` with same logic
3. Document the architecture in testing spec
4. Test both indicators display correctly
5. Create CMM3 PDCA and follow git protocol

## Do

### 1. Added Test Isolation Detection to Template

Updated `templates/project/source.env.template` to detect when running in test/data:

```bash
# Check if running in test isolation mode
if [[ "$PWD" =~ /test/data$ ]]; then
    # Extract version from path: /components/{Name}/{Version}/test/data
    if [[ "$PWD" =~ /components/([^/]+)/([0-9]+\.[0-9]+\.[0-9]+\.[0-9]+)/test/data$ ]]; then
        test_component="${BASH_REMATCH[1]}"
        test_version="${BASH_REMATCH[2]}"
        echo "    🧪 Test Isolation: ${test_component} ${test_version}"
    fi
fi

# Check if running in Cursor agent mode
if [[ -n "$CURSOR_AGENT" ]] || pgrep -f "cursor.*agent" > /dev/null 2>&1; then
    echo "    🤖 Cursor Agent Mode: Shell commands execute in current context"
fi
```

### Lessons Learned

**Template vs. Reality:**
- Templates define structure, but must be deployed to take effect
- Test/data environments need manual sync until next `initProject`
- Always test in actual execution context (Cursor mode matters!)

**Bash Variable Scope:**
- Cannot use `local` in sourced files (wrong context)
- Regular variables work fine for display logic
- Regex extraction via `BASH_REMATCH` is reliable

**User Experience:**

**What Didn't Work:**
