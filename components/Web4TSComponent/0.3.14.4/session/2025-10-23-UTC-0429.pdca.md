## **🎯 PLAN**

### Critical Finding: Component Directories Look Like Project Roots

**The Problem:**
```
/Users/Shared/Workspaces/temp/Web4Articles/
  ├── package.json ← REAL project root marker
  ├── components/ ← REAL project root marker
  ├── .git/ ← REAL project root marker
  └── components/Web4TSComponent/0.3.14.4/
      ├── package.json ← FAKE project root marker!
      ├── components/ ← FAKE project root marker!
      └── test/data/ ← Should mirror REAL project, not component
```

**Current `findProjectRoot()` Logic:**
1. Walk up looking for `package.json` + `components/` ← STOPS at component directory!
2. Fallback: Walk up looking for `.git/`

**What Happens:**
- When CLI runs from component directory (`0.3.14.4`)
- `findProjectRoot()` finds `package.json` + `components/` right there
- Sets `this.model.projectRoot = /path/to/0.3.14.4` ← WRONG!
- Should be `this.model.projectRoot = /Users/Shared/Workspaces/temp/Web4Articles`

### Research: How targetDirectory Works

From code analysis:

**Line 41:** `targetDirectory: discoveredRoot // Can be overridden for test isolation`
- Initially set to discovered project root
- Can be changed via `setTargetDirectory(directory)`

**Lines 335-341:** `setTargetDirectory(directory)`
```typescript
setTargetDirectory(directory: string) {
  this.model.targetDirectory = directory;
  // Discover project root from the target directory for absolute path operations
  // In production: discovers actual project root
  // In test/data: discovers test/data as the "project root" for isolation
  this.model.projectRoot = this.findProjectRootFrom(directory);
}
```

**Line 351:** `isTestEnvironment()`
```typescript
return this.model.targetDirectory.includes('/test/data');
```

**Line 404:** `resolveComponentPath()`
```typescript
return path.join(this.model.targetDirectory, 'components', componentName, version);
```

**Key Insight:** All component operations use `targetDirectory`, which is supposed to point to the project root!

### The Core Issue

When `initTestIsolationEnvironment` runs:
1. CLI was instantiated from `/path/to/component/0.3.14.4`
2. Constructor called `findProjectRoot()` → found `0.3.14.4` as "project root"
3. Set `this.model.projectRoot = /path/to/component/0.3.14.4` ← WRONG!
4. Now `initTestIsolationEnvironment` uses this WRONG root

**What I tried:**
- Using `this.model.projectRoot` directly → Uses component directory
- Using `findProjectRootFrom(componentPath)` → Finds component directory again
- Manual path calculation → Worked, but paths still wrong

**What I should do:**
Need a way to find the ACTUAL main project root, skipping component directories.

### Design Options

**Option A: Walk up until finding `.git`**
```typescript
const realProjectRoot = this.findGitRoot(componentPath);
```
- ✅ Most reliable (`.git` only exists at main project root)
- ✅ Simple to implement
- ❌ Fails if no `.git` (but this is rare)

**Option B: Walk up until finding `source.env`**
```typescript
const realProjectRoot = this.findSourceEnvRoot(componentPath);
```
- ✅ Project-specific marker
- ✅ Works even without `.git`
- ❌ Less standard than `.git`

**Option C: Check for BOTH markers**
```typescript
// Only consider it a "real" project root if it has BOTH:
// - package.json + components/
// - AND (.git OR source.env)
```
- ✅ Most specific
- ✅ Distinguishes main project from component
- ✅ Handles edge cases
- ❌ More complex logic

**Option D: User provides explicit path**
```typescript
initProject(targetDir, { realProjectRoot: '/explicit/path' })
```
- ✅ No ambiguity
- ❌ User burden
- ❌ Not Web4 auto-discovery philosophy
