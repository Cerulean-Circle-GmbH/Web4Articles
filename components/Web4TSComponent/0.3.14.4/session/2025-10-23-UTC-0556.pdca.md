## **📋 PLAN**

### **TRON Context (Verbatim)**

> "yes. and but older versions won't regress it. is now the problem. what about running older versions always in their test/data isolation. pdca about how to achieve that even if the components have not been designed for that from the beginning."

### **Objective**

Design a mechanism where:
1. **Latest version** → Runs in production (normal behavior)
2. **Older versions** → Automatically run in isolated test/data
3. **Works retroactively** → Even for components not designed for isolation
4. **Zero user friction** → Automatic detection and setup

### **Problem Analysis**

**Current State:**
- Timestamp-based sync in `initProject`: newer templates update source.env
- If older version has newer template (edge case), it could regress production
- No automatic isolation for testing older versions

**Desired State:**
- Older versions automatically create/use their test/data environment
- Production always uses `latest` version's environment
- Safe to test any historical version without risk

**Key Challenge:**
Components from before test isolation was invented don't have `test/data` support in their code!

### **Design Options**

**Option: Delegation via `test shell <version>` (Web4 Proxy Pattern)** ✅ SELECTED

**The Challenge:**
`web4tscomponent-v0.3.13.2` doesn't have isolation code. How to add it retroactively?

**The Solution: Proxy through Latest's `test shell` Command**

```bash
# scripts/versions/web4tscomponent/0.3.13.2 (generated by latest)
#!/bin/bash
# Auto-generated proxy wrapper for web4tscomponent 0.3.13.2
# Delegates to latest version with test shell isolation

PROJECT_ROOT="$(git rev-parse --show-toplevel 2>/dev/null || pwd)"

# Delegate to latest: web4tscomponent test shell 0.3.13.2 [original args]
# This starts a shell in 0.3.13.2's test/data, then runs the command
exec "$PROJECT_ROOT/scripts/web4tscomponent" test shell "0.3.13.2" "$@"
```

```typescript
// In DefaultWeb4TSComponent (latest) - enhance existing testShell
/**
 * Start interactive shell in test/data environment
 * Optionally for a specific version (for retroactive isolation)
 * 
 * @param version Optional version to test (defaults to current)
 * @param command Optional command to run in test shell
 */
async testShell(version?: string, ...command: string[]): Promise<this> {
  // If version provided, use that version's test/data
  // Otherwise use current version (this.model.version)
  const targetVersion = version || this.model.version;
  
  const componentPath = this.resolveComponentPath(this.model.component, targetVersion);
  const testDataPath = path.join(componentPath, 'test', 'data');
  
  // Ensure test/data exists
  if (!existsSync(testDataPath)) {
    console.log(`🔧 Creating isolation environment for version ${targetVersion}...`);
    await this.initTestIsolationEnvironment(testDataPath);
  }
  
  console.log(`🧪 Test Shell for ${this.model.component} ${targetVersion}`);
  console.log(`📂 Environment: ${testDataPath}`);
  
  if (command.length > 0) {
    // Run command in test shell
    const cmd = command.join(' ');
    console.log(`▶️  Running: ${cmd}`);
    execSync(`cd "${testDataPath}" && source source.env && ${cmd}`, { 
      stdio: 'inherit' 
    });
  } else {
    // Interactive shell
    console.log(`💡 Type 'exit' to return to main project`);
    execSync(`cd "${testDataPath}" && source source.env && bash`, { 
      stdio: 'inherit' 
    });
  }
  
  return this;
}
```

✅ **Pros:**
- NO underscores anywhere!
- Uses existing `test shell` command pattern
- Just adds optional version parameter
- Versioned scripts are thin proxies (3 lines of logic)
- All intelligence in TypeScript
- Command passthrough: `web4tscomponent-v0.3.13.2 initProject` works!

✅ **Why This Works:**
1. `web4tscomponent-v0.3.13.2` is a PROXY script (not symlink)
2. It calls `web4tscomponent test shell 0.3.13.2 [original args]`
3. Latest's `testShell()` creates 0.3.13.2's test/data
4. Sources that version's source.env
5. Runs the command in isolation

✅ **Backward Compatible:**
- Even 0.3.10.0 (ancient) can work
- No code in old versions needed
- Latest retroactively adds safety

✅ **Command Flow Example:**
```bash

# Proxy translates to:

# Latest executes:

source source.env
initProject  # runs 0.3.13.2's code in isolation
```

**Web4 Principle Followed:**
- TypeScript is single source of truth for version comparison
- Bash wrappers are thin proxies (no logic)
- No underscores (proper Web4 naming)
- Reuses existing command pattern

### **New Template Required**

```bash
#!/bin/bash
# Auto-generated version wrapper for {{COMPONENT_NAME}} {{VERSION}}
# Generated by: web4tscomponent initProject
# Purpose: Delegates to latest version with test shell isolation
# 
# This ensures old versions CANNOT modify production state.
# All commands execute in isolated test/data environment.

# Find project root (Web4 standard pattern)
find_project_root() {
    # Try git first (most reliable for Web4 projects)
    local git_root=$(git rev-parse --show-toplevel 2>/dev/null)
    if [ -n "$git_root" ] && [ -d "$git_root" ]; then
        echo "$git_root"
        return 0
    fi
    
    # Fallback: directory traversal
    local current_dir="$PWD"
    while [ "$current_dir" != "/" ]; do
        if [ -d "$current_dir/.git" ] && [ -f "$current_dir/package.json" ]; then
            echo "$current_dir"
            return 0
        fi
        current_dir="$(dirname "$current_dir")"
    done
    
    # Last resort
    echo "$PWD"
}

PROJECT_ROOT=$(find_project_root)

if [ -z "$PROJECT_ROOT" ]; then
    echo "❌ Error: Not in a Web4 project directory"
    echo "💡 Run this from within a Web4 project"
    exit 1
fi

# Delegate to latest version with test shell isolation
# Format: web4tscomponent test shell <version> <original args...>
exec "$PROJECT_ROOT/scripts/{{CLI_NAME}}" test shell "{{VERSION}}" "$@"
```

**Template Variables:**
- `{{COMPONENT_NAME}}`: Component name (e.g., "Web4TSComponent")
- `{{VERSION}}`: Specific version (e.g., "0.3.13.2")
- `{{CLI_NAME}}`: CLI command name (e.g., "web4tscomponent")

**Generation Location:**
- Target: `scripts/versions/{{CLI_NAME}}/{{VERSION}}`
- Generated by: `initProject()` during scripts directory setup
- Regenerated: On any `initProject` run (ensures latest template)

**Integration with initProject:**

```typescript
// In DefaultWeb4TSComponent.initProject()
async generateVersionWrappers(): Promise<void> {
  const componentDir = this.resolveComponentDirectory(this.model.component);
  const versions = await fs.readdir(componentDir);
  const cliName = this.model.component.toLowerCase().replace(/[^a-z0-9]/g, '');
  
  for (const version of versions) {
    // Skip non-version entries (symlinks, etc.)
    if (!/^\d+\.\d+\.\d+\.\d+$/.test(version)) continue;
    
    // Generate wrapper for this version
    const templatePath = path.join(
      this.model.projectRoot,
      'components/Web4TSComponent/latest/templates/sh/version-wrapper.sh.template'
    );
    
    const wrapperContent = (await fs.readFile(templatePath, 'utf-8'))
      .replace(/\{\{COMPONENT_NAME\}\}/g, this.model.component)
      .replace(/\{\{VERSION\}\}/g, version)
      .replace(/\{\{CLI_NAME\}\}/g, cliName);
    
    const wrapperPath = path.join(
      this.model.projectRoot,
      `scripts/versions/${cliName}/${version}`
    );
    
    await fs.mkdir(path.dirname(wrapperPath), { recursive: true });
    await fs.writeFile(wrapperPath, wrapperContent, { mode: 0o755 });
  }
}
```

**Benefits:**
- ✅ Standardized thin wrapper
- ✅ Self-documenting (comments explain purpose)
- ✅ Regenerated on initProject (stays current)
- ✅ No hardcoded paths (finds project root)
- ✅ Works for ANY component (template-based)

## **✅ CHECK**

### **CRITICAL DISCOVERY: Symlinks Create Recursive Hell! (2025-10-23-UTC-10:04)**

**Problem Identified:**
- Initial design used symlinks: `test/data/components/Web4TSComponent/0.3.13.2 → ../../../../../components/...`
- Result: **Infinite loops and recursive path failures**
- Node.js error: "cannot copy to subdirectory of self"
- PATH resolution created doubled paths like `.../test/data/components/.../test/data/...`

**Root Cause:**
Symlinks in test isolation create circular references because:
1. `test/data/components/Web4TSComponent/0.3.13.2` symlinks to real component
2. Real component CONTAINS `test/data` directory
3. Symlink creates path loop: `test/data → component → test/data → component → ...`

**Solution: COPY Files Instead of Symlink** ✅

```typescript
// In initTestIsolationEnvironment():

// ❌ OLD (DANGEROUS): Symlink approach
await fs.symlink(componentPath, versionLink, 'dir');

// ✅ NEW (SAFE): Copy approach with exclusions
const entries = await fs.readdir(componentPath, { withFileTypes: true });
for (const entry of entries) {
  // Skip test directory entirely (avoid recursion)
  if (entry.name === 'test') {
    await fs.mkdir(destPath, { recursive: true });
    continue;
  }
  
  // Skip node_modules (symlink, can't copy)
  if (entry.name === 'node_modules') {
    continue;
  }
  
  if (entry.isDirectory()) {
    await fs.cp(srcPath, destPath, { recursive: true });
  } else {
    await fs.copyFile(srcPath, destPath);
  }
}
```

**Additional Critical Fix: Direct Node Wrapper**

The `web4tscomponent` file in old versions might itself be a wrapper (from previous `initProject`)!

```typescript
// ❌ OLD: Copy existing wrapper (might be recursive!)

```

**Results:**
- ✅ No recursive loops
- ✅ No path doubling  
- ✅ Commands complete successfully
- ✅ Test isolation works for ANY version
- ⚠️ Trade-off: Disk space (copy vs symlink)
- ✅ Safety: Far more important than disk space for test isolation!
