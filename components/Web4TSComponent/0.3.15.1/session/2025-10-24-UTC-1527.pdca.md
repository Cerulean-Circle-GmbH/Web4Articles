### **Architecture Understanding**

**Class Hierarchy:**
```
DefaultCLI (base class - layer2)
    ↓ extends
Web4TSComponentCLI (CLI implementation - layer5)
    ↓ HAS-A
DefaultWeb4TSComponent (component impl - layer2, implements Web4TSComponent interface)
```

**Key Findings:**
1. **DefaultCLI** = Base class providing CLI capabilities (line 13 in Web4TSComponentCLI)
2. **DefaultWeb4TSComponent** = Standalone component (implements Web4TSComponent, NOT CLI)
3. **Web4TSComponentCLI** = CLI wrapper that extends DefaultCLI and uses DefaultWeb4TSComponent

**Methods Found:**
| Method | Location | Purpose |
|--------|----------|---------|
| `getCompletionScenario()` | DefaultCLI:1492 | Template method in base class |
| `getCompletionScenario()` | DefaultWeb4TSComponent:78 | Standalone component method (NOT CLI) |
| `complete(scenarioJson)` | Web4TSComponentCLI:283 | Receives Scenario from bash, populates model |

**NOT a DRY Violation:**
- DefaultCLI.getCompletionScenario() = Template for CLI hierarchy
- DefaultWeb4TSComponent.getCompletionScenario() = Separate class (not in CLI hierarchy)
- These are different hierarchies, not duplication!

**Bash Flow (from source.env:58-101):**
```bash
1. scenario=$($cli getCompletionScenario)      # Get default Scenario JSON
2. # Bash modifies completionCompWords and completionCompCword using sed
3. result=$($cli complete "$updated_scenario") # Send back to TypeScript
4. # Parse DISPLAY/WORD output
```

**Where to Add shCompletion:**
→ **DefaultCLI** (base class)
→ All component CLIs will inherit it automatically
→ Bypass Scenario JSON serialization
