### **Root Cause Analysis**

**Why does old version work from test/data?**
```typescript
// Old version testSelective method (0.3.13.2)
const testDir = path.join(process.cwd(), 'test');
// When in test/data, process.cwd() = .../test/data
// testDir = .../test/data/test → symlink to actual tests ✅
```

**Why does new version fail from project root?**
```typescript
// New version testSelective method (0.3.15.1) - SAME CODE
const testDir = path.join(process.cwd(), 'test');
// When in project root, process.cwd() = .../Web4Articles
// testDir = .../Web4Articles/test → doesn't exist ❌
```

**The Issue:**
- Both versions use `process.cwd() + '/test'`
- Old version works because in isolation, `process.cwd()` is `test/data`
- New version expects to be run from component directory
- This is NOT a regression - it's **expected behavior** for component-centric commands

### **Behavioral Insights**

**Old Version (0.3.13.2) Isolation Success:**
1. ✅ Symlink trick: `test/data/test` → copied component's test directory
2. ✅ This makes old code (`process.cwd() + '/test'`) work perfectly
3. ✅ The piggy hack solved a real architectural challenge!

**New Version (0.3.15.1) Design:**
1. 🎯 Component-centric: Commands assume you're in component context
2. 🎯 This is actually **correct** for component commands
3. 🤔 But less flexible than auto-discovery approach

### **UX Comparison**

**Old UX (0.3.13.2 in isolation):**
```bash
[ISOLATED] .../test/data > web4tscomponent test file
✅ Works! (because test/data/test symlink exists)
```

**New UX (0.3.15.1):**
```bash
# From project root:
/Web4Articles > web4tscomponent test file
❌ No test files found

# From component directory:
/components/Web4TSComponent/0.3.15.1 > web4tscomponent test file
✅ Works!
```

### **Web4 Architecture Principle Violation?**

**Question:** Should component commands work from **any** directory?

**Web4 Answer:** Components should **self-discover** their context!
- ✅ Component should find its own location via `findProjectRoot()` + introspection
- ✅ Component should NOT require user to `cd` to specific directory
- ❌ Current implementation violates "empty constructor + self-discovery" principle

## **🎯 ACT**

### **Recommended Action**

**Fix the path resolution in current version to support:**
1. Auto-discovery from any directory
2. Use `this.model.targetDirectory` (already available in component model)
3. Maintain backward compatibility with component directory execution

### **Proposed Implementation**

```typescript
// In testSelective method
async testSelective(scope: string, ...references: string[]): Promise<this> {
  // Auto-discover test directory based on component context
  let testDir: string;
  
  if (this.model.targetDirectory) {
    // Use component's target directory (set during init)
    testDir = path.join(this.model.targetDirectory, 'test');
  } else {
    // Fallback: Try current directory
    testDir = path.join(process.cwd(), 'test');
    
    // If not found, try to discover component root
    if (!fs.existsSync(testDir)) {
      const componentRoot = this.findComponentRoot();
      if (componentRoot) {
        testDir = path.join(componentRoot, 'test');
      }
    }
  }
  
  // ... rest of method
}
```

### **Benefits**

1. ✅ Works from any directory
2. ✅ Maintains backward compatibility
3. ✅ Follows Web4 self-discovery principle
4. ✅ Better UX (no `cd` required)

### **Trade-offs**

- 🤔 Slightly more complex logic
- 🤔 Need to add `findComponentRoot()` helper method
- ✅ But much better user experience!
