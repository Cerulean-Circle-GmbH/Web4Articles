```typescript
async getCompletionScenario(): Promise<void> {
  const componentName = this.componentName;
  const componentVersion = this.componentVersion;
  
  // Manual owner generation (no User service)
  const ownerData = JSON.stringify({
    user: process.env.USER || 'system',
    hostname: process.env.HOSTNAME || 'localhost',
    uuid: this.model.uuid,
    timestamp: new Date().toISOString(),
    component: componentName,
    version: componentVersion
  });
  
  // Create FULL CLIModel Scenario
```

**DefaultWeb4TSComponent.getCompletionScenario() (lines 78-123):**
```typescript
async getCompletionScenario(): Promise<void> {
  const componentVersion = this.model.version;
  const componentName = this.model.component;
  
  // Try User service with fallback
  let ownerData: string;
  try {
    const user = await this.getUser();
    ownerData = await user.generateOwnerData({...});
  } catch (error) {
    console.warn('⚠️  User service unavailable, using manual owner generation');
    ownerData = JSON.stringify({
      user: process.env.USER || 'system',
      hostname: process.env.HOSTNAME || 'localhost',
      uuid: this.model.uuid,
      timestamp: new Date().toISOString(),
      component: componentName,
      version: componentVersion
    });
  }
  
  // Create MINIMAL Scenario (only 3 model fields!)
  const scenario = {
    ior: { uuid, component, version },
    owner: ownerData,
    model: {
      uuid,
      name: `${componentName}-cli-completion`,
      origin: "bash-completion",
      definition: "CLI completion context"
      // MISSING: All 20+ completion fields!
    }
  };
  
  console.log(JSON.stringify(scenario, null, 2));
}
```

###  **🔥 THE PROBLEM**

**Duplication:**
- Both create `ior` object (identical code)
- Both create `ownerData` (nearly identical, one has User service)
- Both have `console.log(JSON.stringify(scenario, null, 2))`

**Inconsistency:**
- DefaultCLI: FULL CLIModel (20+ fields)
- DefaultWeb4TSComponent: MINIMAL model (3 fields only!)

**Which one does bash actually call?**
```bash
# source.env line 60:
local scenario=$(timeout 30s "$cli" getCompletionScenario 2>>"$logfile" || true)

# $cli = web4tscomponent (the CLI binary)
# web4tscomponent = Web4TSComponentCLI (extends DefaultCLI)
# Web4TSComponentCLI does NOT override getCompletionScenario
# Therefore: Calls DefaultCLI.getCompletionScenario() ← THE ONE WITH FULL CLIMODEL
```

**So why does DefaultWeb4TSComponent.getCompletionScenario() exist?**
→ **DEAD CODE or used elsewhere?**
→ Need to check if it's actually called anywhere
