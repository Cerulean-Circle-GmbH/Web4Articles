   - Pro: Old bash completion scripts continue to work

   - Pro: No API changes at all

1. **Option A (RECOMMENDED):** Two positional args: `COMP_CWORD` then space-separated words
   ```bash
   $cli shCompletion "$COMP_CWORD" "${COMP_WORDS[@]}"
   ```
   - Pro: Simple, minimal bash logic
   - Pro: No JSON serialization needed
   - Pro: TypeScript receives native bash array
2. **Option B:** Single JSON arg (compact)
   ```bash
   $cli shCompletion '{"cword":2,"words":["cmd","arg1","arg2"]}'
   ```
   - Pro: More structured
   - Con: Still requires JSON serialization in bash
   - Con: Defeats simplification purpose
3. **Option C:** Environment variables
   ```bash
   WEB4_COMP_CWORD=2 WEB4_COMP_WORDS="cmd arg1 arg2" $cli shCompletion
   ```
   - Pro: Clean command line
   - Con: Environment pollution
   - Con: Not idiomatic for function calls

## **📋 PLAN**

### **Problem Statement**

**Current Flow (Scenario-based):**
```bash
# Bash completion function (_web4_generic_completion)
1. Get default Scenario JSON from TS:  scenario=$($cli getCompletionScenario)
2. Parse and modify 2 fields with sed:  updated=$(echo "$scenario" | sed ...)
3. Send modified Scenario back to TS:  result=$($cli complete "$updated_scenario")
4. Parse DISPLAY/WORD protocol:        COMPREPLY=(...)
```

**Issues:**
1. **Serialization Overhead:** 2x JSON serialization (TS→JSON→Bash→JSON→TS)
2. **Bash Complexity:** sed/awk required to modify JSON (fragile, error-prone)
3. **Unnecessary Roundtrip:** Get empty Scenario just to populate 2 fields
4. **Code Duplication:** Scenario model duplicated in bash (as JSON manipulation)

**Proposed Flow (Direct Parameters):**
```bash
# Bash completion function (_web4_generic_completion_v2)
1. Call TS directly with bash vars:    result=$($cli shCompletion "$COMP_CWORD" "${COMP_WORDS[@]}")
2. Parse DISPLAY/WORD protocol:        COMPREPLY=(...)
```

**Benefits:**
1. **50% Less IPC:** 1 call instead of 2 (no getCompletionScenario)
2. **Zero Serialization:** Bash passes primitives, not JSON
3. **Simpler Bash:** 10 lines instead of 80 (no sed/awk logic)
4. **More Robust:** No JSON parsing errors in bash

### **Architecture Analysis**

**Current: Scenario as "God Object" Pattern**
```typescript
// Step 1: Bash calls getCompletionScenario()
cli.getCompletionScenario() 
  → Returns CLIModel as JSON with empty completion fields
  
// Step 2: Bash modifies JSON and calls complete(scenario)
cli.complete(scenario: string)
  → Parses JSON
  → Populates model from scenario
  → Calls getCompletionValues()
  → Returns DISPLAY/WORD output
```

**Proposed: Direct Parameter API**
```typescript
// Single call: Bash passes raw parameters
cli.shCompletion(cword: string, ...words: string[])
  → Populates model.completionCompCword = parseInt(cword)
  → Populates model.completionCompWords = words
  → Calls getCompletionValues()
  → Returns DISPLAY/WORD output
```

**Code Comparison:**

**Before (Bash):**
```bash
_web4_generic_completion() {
    local cur="${COMP_WORDS[COMP_CWORD]}"
    local cli="${COMP_WORDS[0]}"
    
    # Step 1: Get scenario (30-50ms)
    local scenario=$(timeout 30s "$cli" getCompletionScenario 2>>"$logfile" || true)
    
    if [ -z "$scenario" ]; then
        COMPREPLY=()
        return 1
    fi
    
    # Step 2: Build JSON array from COMP_WORDS (20 lines of code)
    local words_json="["
    for word in "${COMP_WORDS[@]}"; do
        word="${word//\"/\\\"}"
        words_json+="\"$word\","
    done
    words_json="${words_json%,}]"
    
    # Step 3: Update scenario with sed (complex regex)
    local updated_scenario=$(echo "$scenario" | \
        sed 's/"completionCompWords":\[.*\]/"completionCompWords":'"$words_json"'/' | \
        sed 's/"completionCompCword":[0-9]*/"completionCompCword":'"$COMP_CWORD"'/')
    
    # Step 4: Get completions (50-100ms)
    local result=$(timeout 30s "$cli" complete "$updated_scenario" 2>>"$logfile" || true)
    
    # ... parse DISPLAY/WORD ...
}
# Total: ~80 lines, 80-150ms latency
```

**After (Bash):**
```bash
_web4_generic_completion() {
    local cli="${COMP_WORDS[0]}"
    
    # Single call with raw parameters (50-100ms)
    local result=$(timeout 30s "$cli" shCompletion "$COMP_CWORD" "${COMP_WORDS[@]}" 2>>"$logfile" || true)
    
    # ... parse DISPLAY/WORD ...
}
# Total: ~10 lines, 50-100ms latency (50% faster!)
```

**Before (TypeScript):**
```typescript
// Method 1: getCompletionScenario()
public getCompletionScenario(): string {
  const scenario = this.createEmptyModel();
  return JSON.stringify(scenario);
}

// Method 2: complete(scenario)
public async complete(scenarioJson: string): Promise<void> {
  try {
    const scenario = JSON.parse(scenarioJson);
    
    // Populate model from scenario
    this.model.completionCompWords = scenario.completionCompWords || [];
    this.model.completionCompCword = scenario.completionCompCword || 0;
    
    // Derive state
    this.model.completionCurrentWord = this.model.completionCompWords[this.model.completionCompCword] || '';
    // ... more derivation ...
    
    // Get completions
    const values = await this.getCompletionValues();
    this.formatCompletionOutput(values);
  } catch (error) {
    console.error('Failed to parse scenario:', error);
  }
}
```

**After (TypeScript):**
```typescript
// Single method: shCompletion()
public async shCompletion(cword: string, ...words: string[]): Promise<void> {
  // Populate model directly from bash primitives
  this.model.completionCompCword = parseInt(cword, 10);
  this.model.completionCompWords = words;
  
  // Derive state (same as before)
  this.model.completionCurrentWord = words[parseInt(cword, 10)] || '';
  // ... more derivation ...
  
  // Get completions (reuse existing logic)
  const values = await this.getCompletionValues();
  this.formatCompletionOutput(values);
}
```

### **Performance Analysis**

| **Metric** | **Current (Scenario)** | **Proposed (shCompletion)** | **Improvement** |
|------------|------------------------|--------------------------------|-----------------|
| **Bash→TS Calls** | 2 (getScenario + complete) | 1 (shCompletion) | **50% reduction** |
| **JSON Operations** | 4 (TS→JSON, JSON→Bash, Bash→JSON, JSON→TS) | 0 | **100% reduction** |
| **Bash LOC** | ~80 lines | ~10 lines | **87% reduction** |
| **Bash Complexity** | sed/awk regex, JSON escaping | Simple parameter passing | **Massive simplification** |
| **Error Vectors** | 3 (JSON parse in TS, sed in bash, JSON escape) | 1 (TS parse int) | **66% reduction** |
| **Latency** | 80-150ms | 50-100ms | **30-50ms faster** |

### **Web4 Principle Alignment**

| **Principle** | **Scenario Approach** | **shCompletion Approach** | **Winner** |
|---------------|------------------------|----------------------------|------------|
| **Simplicity** | ❌ Complex (Scenario JSON dance, sed manipulation) | ✅ Simple (direct parameter passing) | **shCompletion** |
| **DRY** | 🟡 Partial (TypeScript logic DRY, bash duplicates model structure) | ✅ Full (Bash only passes, TS handles all logic) | **shCompletion** |
| **Separation of Concerns** | ❌ Bash knows about Scenario structure (completionCompWords field names) | ✅ Bash only knows about COMP_WORDS/COMP_CWORD | **shCompletion** |
| **Robustness** | ❌ Fragile (JSON escaping, sed regex can break) | ✅ Robust (simple string passing) | **shCompletion** |
| **Backward Compatibility** | N/A | ✅ Can coexist (add new method, deprecate old) | **shCompletion** |
