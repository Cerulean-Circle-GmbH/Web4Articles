### QA Decisions
**Status:** Bug Fix - Partial value completion not working  
**Priority:** High - Breaks user experience  
**Approach:** Invoke callback for partial matches, filter results

### TRON Feedback
User discovered: `web4tscomponent links f<Tab>` returns nothing, should return `fix`.

**Root Cause:** TSCompletion only returns callbacks when `currentWord === ''`, not when filtering with partial input.

---

## 🔍 PLAN: The Gap in Filtering

### Current Behavior

```bash
# ✅ Empty current word → callback invoked
$ web4tscomponent links <Tab><Tab>
→ Shows:  fix verify show list

# ❌ Partial current word → NO callback, returns empty
$ web4tscomponent links f<Tab>
→ Shows: (nothing)
→ Debug log: TSCompletion raw output: ''
```

### Expected Behavior

```bash
$ web4tscomponent links f<Tab>
→ Should show: fix
→ Should invoke callback, then filter results starting with 'f'
```

### Root Cause Code

**File:** `src/ts/layer4/TSCompletion.ts` (lines 327-361)

```typescript
if (args.length === 3) {
  const [className, methodPrefix, currentWord] = args;
  
  // ✅ Empty currentWord → callback
  if (currentWord === '') {
    // ... returns __CALLBACK__:actionParameterCompletion
  }
  
  // ❌ Non-empty currentWord → OLD logic for method chaining
  const values = TSCompletion.getMethodParameters(className, methodPrefix, currentWord);
  // ... this doesn't invoke callbacks!
  return [];
}
```

**The Issue:** Non-empty `currentWord` path was designed for **method chaining** (e.g., `createNextPatch`), not **parameter value filtering**.

---

## 📊 DO: Implementation Plan

### Strategy: Callback with Filtering

When `currentWord !== ''`:
1. Check if method has optional parameter
2. If yes, return special hint: `__CALLBACK_FILTER__:actionParameterCompletion:f`
3. Bash script detects this and calls: `web4tscomponent completeParameter actionParameterCompletion`
4. Bash filters results with `compgen -W "$values" -- "f"`

**OR simpler:** Return callback for non-empty `currentWord` too, let bash's `compgen` do the filtering!

### Implementation: Option 2 (Simpler)

**Change:** Allow callback return for non-empty `currentWord`

```typescript
if (args.length === 3) {
  const [className, methodPrefix, currentWord] = args;
  
  // Check if method has optional parameter (regardless of currentWord)
  const methods = TSCompletion.getClassMethods(className);
  if (methods.includes(methodPrefix)) {
    const enhancedParams = TSCompletion.getEnhancedMethodParameters(className, methodPrefix);
    const firstParam = enhancedParams[0];
    
    if (firstParam && !firstParam.required && firstParam.default !== undefined) {
      // Optional param - return callback hint
      // Bash compgen will filter values based on currentWord
      const params = TSCompletion.getMethodParameters(className, methodPrefix);
      return [`__CALLBACK__:${params[0]}ParameterCompletion`];
    }
    
    // Required param - return parameter names
    if (currentWord === '') {
      return TSCompletion.getMethodParameters(className, methodPrefix);
    }
  }
  
  // Fallback: method chaining logic (existing)
  const values = TSCompletion.getMethodParameters(className, methodPrefix, currentWord);
  if (values.length > 0) return values;
  
  const fullMethod = methodPrefix + (currentWord.charAt(0).toUpperCase() + currentWord.slice(1));
  if (methods.includes(fullMethod)) {
    return TSCompletion.getMethodParameters(className, fullMethod);
  }
  
  return [];
}
```
