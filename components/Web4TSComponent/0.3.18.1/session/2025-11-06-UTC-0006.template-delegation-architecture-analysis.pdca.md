## Do: Delegation Flow Analysis

### Step 1: How Template Delegates

**File**: `templates/ts/DefaultComponent.ts.template`

```typescript
// 1. Template component calls delegated method
async test(scope: string = 'all', ...references: string[]): Promise<this> {
  return this.delegateToWeb4TS('test', scope, ...references);
}

// 2. DRY helper loads Web4TSComponent and sets context
private async delegateToWeb4TS<T extends (...args: any[]) => any>(
  method: string,
  ...args: Parameters<T>
): Promise<this> {
  const web4ts = await this.getWeb4TSComponent();  // ← Load singleton
  web4ts.model.context = this;                      // ← Set SELF as context
  await (web4ts as any)[method](...args);          // ← Call method
  return this;                                      // ← Return SELF (chaining)
}

// 3. Lazy-load Web4TSComponent
private async getWeb4TSComponent(): Promise<any> {
  if (this.web4ts) return this.web4ts;

  // Dynamic import from LATEST version
  const projectRoot = componentRoot.split('/components/')[0];
  const web4tscomponentModule = await import(
    `${projectRoot}/components/Web4TSComponent/latest/dist/ts/layer2/DefaultWeb4TSComponent.js`
  );
  const { DefaultWeb4TSComponent } = web4tscomponentModule;

  // ✅ CRITICAL: Initialize with THIS component's identity
  this.web4ts = new DefaultWeb4TSComponent().init({
    model: {
      component: this.model.component,           // THIS component's name
      version: await SemanticVersion.fromString(this.model.version || '0.0.0.0'),
      componentRoot: componentRoot,              // THIS component's root
      projectRoot: projectRoot,
      targetDirectory: projectRoot
    }
  });

  return this.web4ts;
}
```

**Key Observations**:
1. ✅ Template imports Web4TSComponent **dynamically** from `latest/`
2. ✅ Sets `web4ts.model.context = this` (the delegating component)
3. ⚠️  Uses `(web4ts as any)[method]` - NO type safety
4. ✅ Returns `this` for method chaining on the delegating component

### Step 4: Critical Sync Points Identified

#### ✅ SYNC POINT 1: Method Discovery Interface
**What**: `hasMethod()`, `getMethodSignature()`, `listMethods()`, `discoverMethods()`  
**Status**: ✅ **IN SYNC** (after 2025-11-05 fixes)  
**Why Critical**: CLI and completion system depend on this  
**Failure Mode**: "method not found" errors, broken tab completion

#### ⚠️ SYNC POINT 2: Context Type
**What**: `model.context` type  
**Template**: Doesn't declare it (delegates set it dynamically)  
**Web4TSComponent**: Declares as `any`  
**Status**: ⚠️ **WEAK TYPING**  
**Why Critical**: Type safety lost, runtime errors possible  
**Failure Mode**: Accessing non-existent properties on context

#### ❌ SYNC POINT 3: Return Value Semantics
**What**: Delegated method return value  
**Template Expectation**: `return this` (delegator) for chaining  
**Web4TSComponent Reality**: `return this` (Web4TSComponent instance)  
**Status**: ❌ **SEMANTIC MISMATCH**  
**Why Critical**: Method chaining broken for template components  
**Failure Mode**: Can't chain methods on generated components

#### ⚠️ SYNC POINT 4: Model Property Assumptions
**What**: Properties Web4TSComponent assumes exist on context  
**Web4TSComponent Assumes**: `target.model.componentRoot`, `target.model.version`, etc.  
**Template Provides**: Via init scenario, but not enforced by type  
**Status**: ⚠️ **IMPLICIT CONTRACT**  
**Why Critical**: Runtime errors if template doesn't provide expected properties  
**Failure Mode**: `undefined` errors when accessing context properties

## Check: Critical Issues Found

### Issue 1: Return Value Breaks Method Chaining ❌

**Current Behavior**:
```typescript
// Template component
const result = await myComponent.test();  
// result === Web4TSComponent instance (NOT myComponent!)

// Chaining breaks
await myComponent.test().info();  
// ❌ Calls info() on Web4TSComponent, not myComponent!
```

**Expected Behavior**:
```typescript
await myComponent.test().info();  
// ✅ Should call info() on myComponent
```

**Root Cause**: Template's `delegateToWeb4TS()` correctly `return this`, but Web4TSComponent's delegated methods also `return this` (their own instance, not the context).

**Fix Options**:
1. Web4TSComponent should `return this.model.context || this`
2. Template should ignore return value from Web4TSComponent call
3. Document that delegation breaks chaining (current state)

### Issue 2: Context Type Safety Lost ⚠️

**Current**:
```typescript
// Web4TSComponentModel.interface.ts
context?: any;  // ← NO type safety

// Usage in Web4TSComponent
const target = this.model.context || this;
await someOperation(target.model.componentRoot);  // ← What if componentRoot doesn't exist?
```

**Risk**: Runtime errors if context doesn't have expected properties

**Mitigation Options**:
1. Define `ComponentContext` interface with required properties
2. Use `Reference<Component>` type (but circular import issue)
3. Runtime validation in delegated methods
4. Keep `any` but document contract clearly

### Issue 3: Implicit Property Contract ⚠️

Web4TSComponent assumes context has:
- `model.componentRoot`
- `model.version`
- `model.component`
- `model.projectRoot`
- `model.targetDirectory`

But this is NOT enforced by TypeScript.

**Template Compliance**: ✅ Template's `getWeb4TSComponent()` initializes Web4TSComponent with all required properties, so they exist on `this.model` of the template component.

**Risk**: If template init changes, Web4TSComponent breaks.

## Act: Recommendations

### Recommendation 1: Document Delegation Contract

Create `DELEGATION-CONTRACT.md`:
```markdown
# Web4 Component Delegation Contract

## Required Model Properties
Components delegating to Web4TSComponent MUST provide:
- `model.component: string` - Component name
- `model.version: string` - Component version  
- `model.componentRoot: string` - Component root directory
- `model.projectRoot: string` - Project root directory
- `model.targetDirectory: string` - Target directory for operations

## Method Chaining Limitation
⚠️  Delegated methods return Web4TSComponent instance, NOT delegating component.
Do NOT chain methods after delegation:
```typescript
// ❌ DON'T
await myComponent.test().info();  // Breaks - info() called on wrong instance

// ✅ DO  
await myComponent.test();
await myComponent.info();
```

## Type Safety
Context is typed as `any` to avoid circular imports.
Delegating components must ensure they provide all required model properties.
```
