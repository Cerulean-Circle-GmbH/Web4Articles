# PDCA: DRY Shell Libraries - Eliminate find_project_root Duplication

**Date**: 2025-11-05 UTC 23:01  
**Component**: Web4TSComponent 0.3.18.1  
**Issue**: `find_project_root()` function duplicated in multiple shell scripts  
**Priority**: 🟡 IMPORTANT (DRY violation, maintenance nightmare)  
**Status**: 🔄 IN PROGRESS

## Problem

**BUG**: The `find_project_root()` function is duplicated in:
1. Bash CLI wrappers (generated from template)
2. `source.env` files
3. `clean-global.sh` script (FIXED)
4. Potentially other shell scripts

**ROOT CAUSE**: No DRY shell library - each script reimplements project root discovery

**IMPACT**:
- 🔴 Maintenance nightmare: Bug fixes must be applied to multiple files
- 🔴 Inconsistency: Different implementations may diverge
- 🔴 Template bloat: Templates contain repeated 30+ line functions
- 🟡 Testing overhead: Same logic tested in multiple places

**DETECTION**: User pointed out duplication after clean-global.sh security fix

## Plan

### Objective
Create DRY shell library system and eliminate all `find_project_root()` duplication

### Scope
**IN SCOPE**:
1. ✅ Create `src/sh/lib-project-root.sh` (DONE)
2. ✅ Update `clean-global.sh` to source library (DONE)
3. Update bash CLI wrapper template (`sh/version-wrapper.sh.template`)
4. Update `source.env` template or generation logic
5. Verify all shell scripts source the library

**OUT OF SCOPE**:
- Other shell libraries (do later if needed)
- TypeScript code (different language)

### Success Criteria
- ✅ All shell scripts source `lib-project-root.sh`
- ✅ No duplication of `find_project_root()` function
- ✅ All scripts work correctly (manual test)
- ✅ Templates updated so new components use library

## Future Work: Migration Strategy for Existing Components

### Problem
We've fixed the FORWARD path (new components get DRY library automatically), but EXISTING components still have:
- Duplicated `find_project_root()` in their bash wrappers
- Old templates without the library
- Potential security issues (like clean-global.sh)

### Affected Components
- **Web4TSComponent 0.3.18.1** itself (test evidence in `test/data/components/TestComp/`)
- **Web4TSComponent 0.3.18.0, 0.3.17.9, 0.3.17.8, etc.** (older versions)
- Any user-created components from older Web4TSComponent versions

### Options for Migration

#### Option A: Create `updateBuildSystem` Enhancement ⭐ RECOMMENDED
**Approach**: Extend existing `web4tscomponent updateBuildSystem` command
- Already handles updating shell scripts from templates
- Could add logic to inject `lib-project-root.sh` if missing
- Updates bash wrappers to source library instead of inline function
- Safe: Tests before/after behavior to ensure no regressions

**Pros**:
- Automated, repeatable
- Safe (validates behavior)
- Users can opt-in when ready
- Already have the command infrastructure

**Cons**:
- Requires careful implementation
- Need comprehensive tests

#### Option B: Manual Migration Checklist
**Approach**: Document steps for manual update
1. Copy `src/sh/lib-project-root.sh` from Web4TSComponent
2. Update bash wrapper to source library
3. Update other scripts (clean-global.sh, etc.)
4. Test thoroughly

**Pros**:
- Simple, no code changes
- Users have full control

**Cons**:
- Error-prone
- Not repeatable
- Most users won't do it

#### Option C: Version Bump + Deprecation
**Approach**: Encourage users to upgrade to 0.3.18.2+
- Document breaking change
- Provide migration guide
- Deprecate older versions

**Pros**:
- Clean break
- Forces users to latest best practices

**Cons**:
- Disruptive
- Users may not upgrade
- Doesn't fix existing components

**Phase 1: Document (NOW)** ✅
