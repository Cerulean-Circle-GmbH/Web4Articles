# PDCA: on() Command Context Path Initialization Bug

**Date:** 2025-10-31  
**Version:** 0.3.17.2  
**Status:** ✅ COMPLETE  
**CMM Level:** CMM3 (Defined Process)  
**Agent:** Claude (Cursor)

## Executive Summary

**Problem:** When using `web4tscomponent on Web4TSComponent 0.3.13.2 test itCase`, the command fails because the loaded component (0.3.13.2) looks for tests in the CLI's directory (0.3.17.2) instead of its own directory.

**Root Cause:** The `loadComponent()` method in `DefaultCLI` only passes 3 paths to the loaded component:
- `componentRoot` (component's own directory) ✅
- `projectRoot` (overall project root) ✅  
- `targetDirectory` (where to create components) ✅

But it's missing:
- `componentsDir` ❌
- `scriptsDir` ❌
- `scriptsVersionDir` ❌
- `testDataDir` ❌

Older versions (0.3.13.2) use `process.cwd()` as fallback, which returns the CLI's directory (0.3.17.2), not the loaded component's directory.

**Impact:** The `on()` command cannot properly delegate test commands to older component versions.

## PLAN

**Current Behavior:**

**Expected Behavior:**

### 2. Root Cause Analysis

**Path Flow Analysis:**

```typescript
// ✅ CORRECT (Current 0.3.17.2):
CLI init() {
  this.model.projectRoot = "/Users/.../Web4Articles"
  this.model.componentsDir = "/Users/.../Web4Articles/components"
  this.model.testDataDir = "/Users/.../Web4Articles/components/Web4TSComponent/0.3.17.2/test/data"
  // ... all paths calculated
}

CLI loadComponent("Web4TSComponent", "0.3.13.2", componentPath) {
  // ❌ INCOMPLETE: Only 3 paths provided
  return new ComponentClass().init({
    model: {
      componentRoot: componentPath,           // ✅ /Users/.../components/Web4TSComponent/0.3.13.2
      projectRoot: this.model.projectRoot,    // ✅ /Users/.../Web4Articles
      targetDirectory: this.model.projectRoot // ✅ /Users/.../Web4Articles
      // ❌ MISSING: componentsDir, scriptsDir, testDataDir, etc.
    }
  });
}

// ❌ PROBLEM (Old 0.3.13.2):
DefaultWeb4TSComponent.testSelective() {
  const testDir = context
    ? path.join(this.resolveComponentPath(context.component, context.version), 'test')
    : path.join(process.cwd(), 'test');  // ← WRONG! Uses CLI's cwd (0.3.17.2)
}
```

**Why This Happens:**
1. CLI (0.3.17.2) calculates all paths in its `init()` and stores them in `this.model`
2. CLI's `on()` loads target component (0.3.13.2) via `loadComponent()`
3. `loadComponent()` only provides 3 paths to the target component
4. Target component (0.3.13.2) has old code that uses `process.cwd()` as fallback
5. `process.cwd()` returns the CLI's directory (0.3.17.2), not the target's directory (0.3.13.2)

**Radical OOP Principle Violated:**
> **Path Authority Principle**: The CLI is the single source of truth for all path calculations. Components should receive ALL path context from the CLI, not calculate or discover paths themselves.

### 3. Solution Design

**Two Options:**

#### Option A: Complete Path Transfer (Recommended)
**Principle:** CLI provides ALL calculated paths to loaded component

```typescript
// DefaultCLI.loadComponent()
private async loadComponent(
  componentName: string, 
  version: string,
  componentPath: string
): Promise<DefaultWeb4TSComponent> {
  const modulePath = join(componentPath, 'dist', 'ts', 'layer2', `Default${componentName}.js`);
  
  if (!existsSync(modulePath)) {
    throw new Error(`Component module not found: ${modulePath}`);
  }
  
  const module = await import(modulePath);
  const ComponentClass = module[`Default${componentName}`];
  
  if (!ComponentClass) {
    throw new Error(`Component class not found: Default${componentName} in ${modulePath}`);
  }
  
  // ✅ CLI is Path Authority - provide ALL paths to component (OOP!)
  const instance = new ComponentClass().init({
    model: {
      // Component-specific paths
      componentRoot: componentPath,           // Component's own directory
      targetDirectory: this.model.projectRoot, // Where to create new components
      
      // ✅ NEW: Transfer ALL path context from CLI
      projectRoot: this.model.projectRoot,
      componentsDir: this.model.componentsDir,
      scriptsDir: this.model.scriptsDir,
      scriptsVersionDir: this.model.scriptsVersionDir,
      testDataDir: join(componentPath, 'test', 'data'), // ← Component-specific test/data
    }
  });
  
  return instance;
}
```

**Pros:**
- ✅ Complete path context for loaded component
- ✅ Works with ANY version (old or new)
- ✅ Follows Path Authority Principle
- ✅ No `process.cwd()` dependencies

**Cons:**
- Requires passing many fields
- Scenario becomes larger

#### Option B: Self-Initialization Fallback
**Principle:** Component calculates its own paths if not provided

```typescript
// DefaultWeb4TSComponent.init()
init(scenario?: Scenario<Web4TSComponentModel>): this {
  // If componentRoot provided but other paths missing, calculate them
  if (scenario?.model?.componentRoot && !scenario?.model?.componentsDir) {
    // Self-calculate missing paths from componentRoot
    const componentRoot = scenario.model.componentRoot;
    const projectRoot = scenario.model.projectRoot || 
                       dirname(dirname(componentRoot)); // ../../ from componentRoot
    
    scenario.model.projectRoot = projectRoot;
    scenario.model.componentsDir = join(projectRoot, 'components');
    scenario.model.scriptsDir = join(projectRoot, 'scripts');
    scenario.model.testDataDir = join(componentRoot, 'test', 'data');
  }
  
  // ... rest of init
}
```

**Pros:**
- Smaller scenario
- Component is self-sufficient

**Cons:**
- ❌ Violates Path Authority Principle (component calculates paths)
- ❌ Duplicates path logic
- ❌ Risk of inconsistency

**Decision:** **Option A (Complete Path Transfer)** - Aligns with Radical OOP and Path Authority Principle.
