## Act

### Findings

**Root Cause:**
Template was created before User service integration pattern was established in Web4TSComponent. The template has not been synchronized with the modern pattern.

**Key Outdated Patterns:**
1. **toScenario() Owner Data:** Hardcoded env vars instead of User service delegation
2. **Missing User Service Integration:** No `getUser()`, no `User` import, no `user` field
3. **No Base64 Encoding:** Owner data not encoded (modern pattern uses base64)

**Architectural Impact:**
- Generated components violate Radical OOP (should delegate to User)
- Generated components cannot leverage User service features
- Inconsistent pattern across Web4 component ecosystem

**Modernization Strategy:**
1. Add `User` interface import to template
2. Add `private user?: User;` field to template class
3. Add `getUser()` method with lazy initialization pattern
4. Update `toScenario()` to use User service with fallback
5. Test-first: Write test for User service integration before implementation

**Next Steps:**
1. Create test for component User service integration
2. Update template with modern patterns
3. Regenerate IdealMinimalComponent to verify
4. Run full test suite to ensure no regressions

## QA Decisions

**Q1:** Should we keep the hardcoded env var pattern as fallback?  
**A1:** YES - Web4TSComponent uses it as fallback when User service unavailable. This is correct pattern for optional dependencies.

**Q2:** Is path calculation in `getWeb4TSComponent()` a Path Authority violation?  
**A2:** NO - Components must discover their own location for dynamic imports. This is an exception to Path Authority (CLI provides operational paths, components discover their own runtime location).

**Q3:** Should we make User a required dependency?  
**A3:** NO - User service is optional. Components should work without it (using fallback). Follows Web4 optional dependency pattern.

**Q4:** Breaking changes to existing components?  
**A4:** NO - Updates are additive. Existing components continue working. User service integration is backwards compatible.
