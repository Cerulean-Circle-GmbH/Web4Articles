**Problem**: After OOP refactoring (0.3.17.8 → 0.3.18.0), component methods stopped executing.


**Root Cause**: Incomplete OOP refactoring
- ✅ Discovery was updated to OOP (`hasMethod()`)
- ❌ Execution was NOT updated (still checked only `cliMethods`)

**The Fix** (`DefaultCLI.ts:executeDynamicCommand()` lines 798-812):
```typescript
// ✅ RADICAL OOP FIX: Check component methods in addition to CLI methods
// @pdca 2025-11-06-UTC-0030.functional-vs-radical-oop-analysis.pdca.md
const isCliMethod = this.cliMethods.has(command);
const isComponentMethod = (this.context && this.context.hasMethod(command)) || 
                           (this.component && this.component.hasMethod(command));

if (!isCliMethod && !isComponentMethod) {
  return false; // Command not found in either CLI or component
}

const signature = isCliMethod 
  ? this.cliMethods.get(command)!
  : (this.context?.getMethodSignature(command) || this.component?.getMethodSignature(command))!;
```

### 2. Philosophical Analysis: Functional vs Radical OOP 📖

**Created**: `2025-11-06-UTC-0030.functional-vs-radical-oop-analysis.pdca.md` (758 lines)

**Key Insights**:

#### Three Stages of Evolution

**Stage 1: Functional (0.3.13.2 - 0.3.17.8)** ✅ Works
```typescript
// Functional pattern - state as parameters
function processComponent(component: string, version: string) {
  // Pass everything as parameters
}
```
- **Pros**: Simple, easy to understand, works reliably
- **Cons**: Parameter hell, no encapsulation, hard to maintain

**Stage 2: Broken OOP (0.3.18.0)** ❌ BROKEN
```typescript
// Discovery: OOP ✅
this.component.hasMethod(command);

// Execution: Functional ❌ (INCONSISTENT!)
if (!this.cliMethods.has(command)) {
  return false;
}
```
- **Problem**: Half-OOP is WORSE than functional
- **Result**: Breaks functionality

**Stage 3: Radical OOP (0.3.18.1+)** ✅ SUCCESS
```typescript
// Discovery: OOP ✅
const isComponentMethod = this.component.hasMethod(command);

// Execution: OOP ✅ (CONSISTENT!)
if (this.component.hasMethod(command)) {
  await this.component[command](...args);
}
```
- **Result**: Clean, maintainable, WORKS

#### The 5 Radical OOP Principles

1. **Empty Constructor** - No logic, ever
2. **Scenario Init** - All config via `init(scenario)`
3. **Model-Driven** - State in `this.model`, not parameters
4. **Method Chaining** - Return `this` always
5. **Context as State** - `this.model.context`, not parameters

#### The "on" Context Pattern

```typescript
// User: web4tscomponent on IdealMinimalComponent 0.3.17.8 links

// 1. Load context
this.model.context = targetComponent;

// 2. Execute on context
const target = this.model.context || this;
await target.links();
```

**This IS Radical OOP** - state in model, no parameters!

#### User Feedback Integration

The user added critical insights directly to the PDCA:
- **`const target = this.model.context || this;`** → DRY violation! Should be `this.on()` method
- **Parameter completion `(web4ts as any)[method]`** → One of rare valid `any` uses (Inversion of Control)
- **Simplicity comment** → "simplexity is the highest art of complexity"
- **"ONE GLOBAL FUNCTIONAL SHIT"** → Warning about single method map confusion

### 3. Multi-Component Development Workflow 📋

**Created**: `2025-11-06-UTC-0050.multi-component-development-workflow.pdca.md` (841 lines)

**Purpose**: Reference guide for MY OWN MEMORY about when to work where and what to build.

#### The Two Codebases

**Web4TSComponent** (Infrastructure):
- Core logic: `DefaultWeb4TSComponent.ts`
- CLI framework: `DefaultCLI.ts`
- Templates: `templates/ts/*.template`
- Shell scripts: `src/sh/*.sh`

**Target Component** (e.g., IdealMinimalComponent):
- Domain logic: `DefaultIdealMinimalComponent.ts`
- Own CLI: `IdealMinimalComponentCLI.ts`
- Copied scripts: `src/sh/*.sh`

#### Decision Tree: Where to Fix?

**Question 1: CLI Framework Issue?**
- Examples: Tab completion, method discovery, command execution
- **Fix in**: `DefaultCLI.ts`
- **Build**: Web4TSComponent only
- **Propagation**: Automatic (inheritance)

**Question 2: Template Issue?**
- Examples: Missing methods in generated components
- **Fix in**: `templates/ts/*.template`
- **Build**: Web4TSComponent
- **Propagation**: ❌ NOT automatic - must remove/recreate

**Question 3: Infrastructure Method?**
- Examples: `test`, `build`, `clean`, `tree`, `links`
- **Fix in**: `DefaultWeb4TSComponent.ts`
- **Build**: Web4TSComponent only
- **Propagation**: Automatic (delegation)

**Question 4: Shell Script?**
- Examples: `build.sh`, `clean-global.sh`
- **Fix in**: BOTH source + template
- **Build**: None (shell not compiled)
- **Propagation**: Use `updateBuildSystem` OR remove/recreate

**Question 5: Domain Logic?**
- Examples: Target component's own methods
- **Fix in**: Target component only
- **Build**: Target component only
- **Propagation**: Not applicable

#### Build Order Matrix

| What Changed | Build Order | Notes |
|--------------|-------------|-------|
| `DefaultCLI.ts` | 1. Web4TSComponent<br>2. DONE | Inheritance auto-applies |
| `DefaultWeb4TSComponent.ts` | 1. Web4TSComponent<br>2. DONE | Delegation auto-applies |
| `*.ts.template` | 1. Web4TSComponent<br>2. Remove/Create Target | Templates don't auto-apply |
| `*.sh.template` | 1. Update template<br>2. `updateBuildSystem` OR Remove/Create | Shell needs explicit sync |
| Target logic | 1. Target Component<br>2. DONE | No Web4TSComponent build needed |

#### The Confusion Matrix

**Scenario A**: "I fixed DefaultCLI.ts but target still broken!"
- **Diagnosis**: Template issue, need remove/recreate

**Scenario B**: "I fixed template but nothing changed!"
- **Diagnosis**: ✅ CORRECT - templates don't auto-apply
- **Fix**: Remove and recreate target

**Scenario B.1**: "The Recreate Pain" ⚠️ **CRITICAL**
- **Problem**: Recreate works for empty components (IdealMinimalComponent)
- **BUT**: DESTROYS production components (PDCA, 100+ hours of work)
- **Solution**: Wait for Web4Programmer

**Scenario C**: "Built twice for no reason"
- **Check**: Compare timestamps of `dist/` vs `src/`

**Scenario D**: "Test where?"
- **Answer**: BOTH Web4TSComponent AND target component

#### Golden Rules

1. **Fix Close to Root** - Most generic place possible
2. **Templates Are NOT Live Code** - Must apply explicitly
3. **Build Only What Changed** - Check timestamps
4. **Test at BOTH Levels** - Direct + delegation
5. **Document for Future Me** - PDCA with verification
