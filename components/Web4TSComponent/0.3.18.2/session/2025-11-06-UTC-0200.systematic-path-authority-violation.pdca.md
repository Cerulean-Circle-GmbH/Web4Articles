**1. Understand Path Authority Principle**

From the `tree` fix (2025-11-06-UTC-0120):
```typescript
// ❌ WRONG: Use target's path (may be undefined in delegated component)

// ✅ CORRECT: Use CLI's path (always defined via Path Authority)
```

**Path Authority Rule:**
- **CLI** (`this.model`): Owns ALL path infrastructure
  - `projectRoot`
  - `componentsDirectory`
  - `componentRoot` (for CLI's own component)
  - `targetDirectory`
  
- **Target** (`target.model`): Owns component-specific DATA
  - `component` (name)
  - `version`
  - Business logic state
  - NOT paths!

**Verification Results:**

**Root Cause Confirmed (🎯 ARCHITECTURAL)**

The issue is NOT:
- ❌ Wrong property names
- ❌ Missing model properties
- ❌ Broken delegation setup

The issue IS:
- ✅ **Methods that need CLI infrastructure live in COMPONENT classes!**
- ✅ **Component has method, but method needs CLI's paths**
- ✅ **Architecture puts infrastructure-dependent methods in wrong class**

**Where Are These Methods?**
All 11 methods are in `DefaultWeb4TSComponent.ts` (component class, not CLI class!)

**Why This Breaks**:
1. Methods need `componentsDirectory` (CLI infrastructure)
2. Methods live in Component (domain logic)
3. When component is used standalone, no CLI attached!
4. When delegated, target component has no paths!

**The Radical OOP Fix**: 
**Option A**: Move infrastructure methods to CLI class
**Option B**: Component methods delegate to their CLI for infrastructure  
**Option C**: Use `this` consistently for BOTH paths and data (works when CLI calls component)

Need to understand: When are these methods called?
- From CLI: `this.component.build()` 
- From delegation: `web4ts.build()` (web4ts is COMPONENT instance!)

**THAT'S THE BUG**: We're calling component methods directly, but components don't have CLIs!

**Deep Analysis: Where Methods Live vs Where They're Called**

Let me trace the actual execution:

1. **Web4TSComponent self-operation**:
   ```typescript
   // User types: web4tscomponent build
   CLI: Web4TSComponentCLI constructor
     → this.init() // Sets CLI.model paths
     → this.component = new DefaultWeb4TSComponent().init()
     → this.component.model.projectRoot = this.model.projectRoot
     → this.component.model.componentsDirectory = ...
     // Component HAS paths!
   
   Execution: CLI.executeDynamicCommand()
     → this.component.build()
     → target = this.model.context || this
     → target.model.componentsDirectory ✅ EXISTS
   ```

2. **IdealMinimalComponent delegation**:
   ```typescript
   // User types: idealminimalcomponent build
   CLI: IdealMinimalComponentCLI
     → this.component = new DefaultIdealMinimalComponent().init()
     → NO path population (domain component!)
   
   Component: delegateToWeb4TS('build')
     → web4ts = new DefaultWeb4TSComponent().init({...})
     → ❌ Component created directly, NO CLI!
     → web4ts.model has SOME paths (passed in init)
     → BUT missing componentsDirectory!
   
   Execution: web4ts.build()
     → target = this.model.context || this
     → target.model.componentsDirectory ❌ UNDEFINED!
   ```

**THE ROOT CAUSE**: `getWeb4TSComponent()` creates component directly, bypassing CLI!

**Radical OOP Solution**:

Web4TSComponentCLI (lines 25-46) shows the pattern:
```typescript
constructor() {
  super();
  this.init();  // ← CLI calculates paths
  this.component = new DefaultWeb4TSComponent().init();
  
  // ✅ CLI populates component with Path Authority
  this.component.model.projectRoot = this.model.projectRoot;
  this.component.model.componentsDirectory = join(this.model.projectRoot, 'components');
  this.component.model.targetDirectory = this.model.projectRoot;
  this.component.model.isTestIsolation = false;
}
```

**Fix**: `getWeb4TSComponent()` must create **CLI**, then use `cli.component`:

```typescript
private async getWeb4TSComponent(): Promise<DefaultWeb4TSComponent> {
  // Import CLI (not component)
  const { Web4TSComponentCLI } = await import('.../Web4TSComponentCLI.js');
  
  // ✅ Create CLI (it creates component with Path Authority)
  const cli = new Web4TSComponentCLI();
  
  // ✅ Override component identity for delegation
  cli.component.model.component = this.model.component;
  cli.component.model.version = ...;
  cli.component.model.componentRoot = this.getComponentContext()?.componentRoot;
  
  // ✅ Component already has ALL paths from CLI!
  return cli.component;
}
```

**Why This is Radical OOP**:
- ✅ CLI owns Path Authority (not duplicated into component models)
- ✅ Component gets paths FROM its CLI during construction
- ✅ No functional parameter passing
- ✅ Model-driven: CLI.model → CLI.component.model
- ✅ DRY: Path calculation happens ONCE (in CLI.init())

**This fixes ALL 11 methods** because the component now has paths!
