## 🥖 Breadcrumb Methodology for Sprint Planning

🎯 Concept: Sprint Planning vs Sprint Execution

**Sprint Planning Phase:**
- Create execution plan with Entry/Exit breadcrumbs
- Entry: Context needed to start this step
- Exit: Verification points to confirm completion
- Plan acts as navigation map through complexity

**Sprint Execution Phase:**
- Each step is a "rabbit hole" - lose surface context while diving
- Cannot observe surface while in depths (focus required)
- Breadcrumbs guide back to surface with correct exit
- Trust the plan - context preserved at entry/exit points

**Breadcrumb Structure:**
```markdown
### **Step N: Task Name**
**🔵 Entry Breadcrumb:**
- Current state from previous step
- Files/paths needed
- Known constraints
- Expected starting point

**📋 Rabbit Hole Task:**
[Detailed work to perform]

**🟢 Exit Breadcrumb (Verification):**
- [ ] Outcome A verified
- [ ] Outcome B verified  
- [ ] Git status clean
- [ ] Ready for next step
```

**Meta-Learning:**
- Cannot hold all context at all times
- Diving requires releasing surface awareness
- Breadcrumbs prevent getting lost
- Exit points have multiple paths - breadcrumbs verify correct one
- Pattern enables future automation (rewritePDCA, createPDCA methods)

**Pattern Source:** 2025-10-29-UTC-1026.pdca.md (Prompt 10)
User introduced concept explicitly, agent integrated systematically
```
