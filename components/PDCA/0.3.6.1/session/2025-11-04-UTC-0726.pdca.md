**Phase 1: TRON Collaboration - Design Decision**

**TRON QA Decision Required:**

**Option A: Optional sessionDirectory Parameter**
```typescript
async createPDCA(
  title: string, 
  objective: string, 
  sessionDirectory?: string,  // NEW optional param
  dryRun?: string
): Promise<this>
```

**Pros:**
- ✅ Explicit control over target directory
- ✅ Backward compatible (existing calls still work)
- ✅ Clear for CLI users: `pdca createPDCA "Title" "Obj" /path/to/session`

**Cons:**
- ❌ CLI gets longer
- ❌ Parameter ordering: sessionDirectory before or after dryRun?

**Option B: Use Current Working Directory Detection**
```typescript
// If current directory has "session" subdirectory, use it
// Otherwise fall back to PDCA component
const sessionDir = fs.existsSync('./session') ? 
  path.resolve('./session') : 
  this.model.sessionDirectory || 
  path.join(projectRoot, 'components/PDCA/0.3.6.1/session');
```

**Pros:**
- ✅ Zero API changes
- ✅ Intuitive: "I'm in Web4TSComponent, it creates PDCAs here"
- ✅ Simpler CLI usage

**Cons:**
- ❌ Implicit behavior (might surprise users)
- ❌ Relies on `session/` subdirectory convention

**My Recommendation: Option A (Explicit Parameter)**
- More predictable
- Better for programmatic use
- Clear intent in CLI commands

**Implementation Strategy:**
1. **Add Parameter**: `sessionDirectory?: string` as 3rd param (before dryRun)
2. **Fallback Logic**: sessionDirectory param → model.sessionDirectory → default PDCA path
3. **Validation**: Verify sessionDirectory exists and is writable
4. **Tests**: 6 new test cases (TC80-TC85)
5. **CLI Integration**: Update CLI parser to accept optional directory
6. **Documentation**: Update trainAI with new usage examples
