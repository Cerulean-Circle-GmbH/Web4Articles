### **My Answer**
I investigated renaming the parameter from `renameCase` to `case` for brevity. However, I discovered that **`case` is a reserved keyword** in JavaScript/TypeScript and cannot be used as a parameter name.

**Attempted:**
1. Changed parameter to `case: 'now' | 'creationDate' | 'strip' | 'feature'`
2. Build failed with TypeScript error: `TS1005: ',' expected`
3. Tried `@cliSyntax case filePath dryRun` annotation
4. Discovered `@cliSyntax` only groups parameters, doesn't rename them

**Conclusion:** Must keep `renameCase` due to language restrictions. This is a JavaScript/TypeScript limitation, not a system limitation.

**Learning Applied:** Reserved keywords are a hard constraint in programming languages. Parameter names must be valid identifiers, and `case` (used in `switch/case` statements) cannot be overridden.

## **📋 PLAN**

**Objective:** ~~Simplify parameter name from renameCase to case~~ **INVESTIGATION: Why `case` cannot be used**

**Requirements Traceability:** User request for `!<case:now|creationDate|strip|feature>` syntax

### **Investigation Findings**

**Problem:** `case` is a reserved keyword in JavaScript/TypeScript
- Used in `switch/case` statements
- Cannot be used as variable, parameter, or function names
- TypeScript compiler rejects it: `TS1005: ',' expected`

**Attempted Solutions:**
1. **Direct rename:** `async rename(case: string)` → Build failed
2. **@cliSyntax annotation:** `@cliSyntax case filePath dryRun` → No effect (only for grouping)
3. **Alternative names:** `caseType`, `renameType` → Less clear than `renameCase`
