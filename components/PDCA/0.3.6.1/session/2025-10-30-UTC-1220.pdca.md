**Solution:** Fix delegation model initialization or implement PDCA-native `links` method.

**Objective:** Fix auto-promotion delegation bug so `pdca test` can successfully promote version after tests pass

**Requirements Traceability:**
- All tests passing ✅ (32 passed)
- Auto-promotion blocked by delegation bug ❌

**Error Details:**
```
❌ CLI Error: Cannot set properties of undefined (setting 'targetDirectory')
❌ CLI Error: Cannot read properties of undefined (reading 'targetDirectory')
```

**Two Possible Solutions:**

**Option A: Fix PDCA Model Initialization**
- Add `projectRoot` and `targetDirectory` to PDCAModel initialization
- Ensure these fields are set when PDCA is instantiated
- Pro: Delegation continues to work
- Con: Requires understanding what values these fields need

**Option B: Implement Native PDCA Links Method**
- Don't delegate `links` to Web4TSComponent
- Implement PDCA-specific `links()` method
- Pro: No dependency on Web4TSComponent fields
- Con: Code duplication

**Recommended: Option A** - Fix model initialization (maintains DRY principle)

**Implementation Strategy:**
1. Find where `links` is called during auto-promotion
2. Trace back to see what fields are missing in PDCA model
3. Add those fields to PDCA constructor
4. Test that `pdca links` works
5. Test that `pdca test` auto-promotion works
