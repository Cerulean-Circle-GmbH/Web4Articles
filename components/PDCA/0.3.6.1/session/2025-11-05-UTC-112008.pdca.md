## **📊 SUMMARY**

**Bug:** `rename creationDate` uses `git log --follow` which follows the file through ALL renames in history, finding an ANCESTOR file's creation date instead of the CURRENT file's creation date.

**User's Experience:**
```
File created: 2025-11-05 at 12:06:43 (TODAY)
Command: pdca rename creationDate
Result: Renamed to 2025-08-23-UTC-143402.pdca.md (WRONG DATE - 3 months ago!)

Git log shows:
- 2025-11-05 12:06:43: File actually created
- But --follow traces back through renames to:
- 2025-08-23 14:34:02: Some ancestor file created
```

**Root Cause:** The `rename` method uses `git log --follow --diff-filter=A` to find the creation date. The `--follow` flag tells git to follow the file through renames, which traces back through the entire rename history and finds when an ANCESTOR file was first added, not when THIS file was created.

**Impact:**
- Files get renamed to incorrect dates (months in the past)
- Chronological ordering broken
- User confusion - "I just created this today!"

**Solution:** Remove `--follow` flag from the git log command so it only looks at the current file's history.
