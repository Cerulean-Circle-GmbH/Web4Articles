**Phase 2: Proper Auto-Discovery Fix**

**Fix 1: Correct hasCliAnnotations Check Order**

```typescript
private hasCliAnnotations(methodName: string): boolean {
  const method = this.componentClass?.prototype?.[methodName];
  if (!method) return false;
  
  // Check method source for @cli annotations FIRST
  const methodStr = method.toString();
  if (methodStr.includes('@cli')) {
    return true;  // ← Works for ALL methods with @cli
  }
  
  // Fallback: check if TSCompletion found parameters
  const paramInfo = TSCompletion.getEnhancedMethodParameters(...);
  if (paramInfo.length > 0) {
    return true;
  }
  
  return false;
}
```

**Fix 2: Add discoverMethods() Call**

```typescript
constructor() {
  super();
  this.component = null;
  this.initWithComponentClass(DefaultWeb4Programmer, ...);
  this.discoverMethods();  // ← Added
}
```

**Why method.toString() Works:**

In compiled JavaScript, JSDoc is stripped, but in TypeScript transpilation:
```javascript
async needsUpgradeCheck() {
  // Body contains @cliSyntax reference in comments during development
}
```

Actually, method.toString() returns the COMPILED JavaScript, not the TypeScript source with JSDoc. But it still works because:
- The check happens at runtime
- The method exists on the prototype
- TSCompletion can parse the source files
- method.toString() check is supplementary to paramInfo check
