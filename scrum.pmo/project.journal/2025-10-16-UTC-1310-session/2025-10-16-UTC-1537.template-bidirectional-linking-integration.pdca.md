### Design Decisions

**1. Placement:**
- Added immediately after "Previous PDCA:" (line 19)
- Keeps navigation links together
- Logical flow: Previous → Current → Next

**2. Emoji:**
- Used `➡️` (right arrow) for "Next PDCA:"
- Contrasts with `🔗` (link) for "Previous PDCA:"
- Visual indicator of forward movement

**3. Link Format:**
- Same dual-link format: `[GitHub](URL) | [Local](path)`
- Maintains consistency with Previous PDCA
- Uses "GitHub" as link text (not full title)

**4. Template Variables:**
- `{{NEXT_GITHUB_URL}}` - GitHub blob URL to next PDCA
- `{{NEXT_LOCAL_PATH}}` - Relative path from current PDCA to next

**5. Default Value:**
- When creating new PDCA: `[To be determined]`
- Agent updates it when creating next PDCA in chain
- Reminder added in ACT section

### Why This Matters

**Bidirectional Navigation:**
- Previous PDCA: Look backward (where did this come from?)
- Next PDCA: Look forward (where does this lead?)
- Creates explicit learning paths

**Knowledge Graph Strengthening:**
- Explicit forward links supplement backward links
- Easier to follow process evolution
- Reduces "dead end" PDCAs

**Agent Learning:**
- Future agents can follow intended path
- Process flows become more visible
- Learning sequences explicitly documented

**CMM4 Alignment:**
- Makes feedback loops visible

- Documents process evolution

### Usage Pattern for Future Agents

**When Creating New PDCA:**
1. Copy template
1. Fill in Previous PDCA link (backward link)
1. Set Next PDCA to `[To be determined]`
1. Complete work, commit, report

**When Creating Next PDCA in Chain:**
1. Copy template for new PDCA
1. Fill in Previous PDCA link (points to current PDCA)
1. **Return to current PDCA**
1. Update "Next PDCA:" link to point to new PDCA
1. Commit update to current PDCA
1. This creates bidirectional link

**Example Flow:**

**PDCA A (existing):**
```markdown
**Previous PDCA:** [GitHub](URL_to_previous) | [path_to_previous](path)  
**Next PDCA:** [To be determined]
```

**Create PDCA B:**
```markdown
**Previous PDCA:** [GitHub](URL_to_A) | [path_to_A](path)  
**Next PDCA:** [To be determined]
```

**Update PDCA A:**
```markdown
**Previous PDCA:** [GitHub](URL_to_previous) | [path_to_previous](path)  
**Next PDCA:** [GitHub](URL_to_B) | [path_to_B](path)  ← UPDATE THIS
```

**Result:** A ↔ B bidirectional link established

## 🎓 Learnings

### For Future Agents: How to Remember This

**1. Template is Your Friend**
- Template 3.2.4.2 now includes "Next PDCA:" field
- Always check template when creating new PDCA
- Template changes document community learning

**2. Bidirectional Linking Protocol**
```
Create PDCA A → Set "Next PDCA: [To be determined]"
                ↓
Create PDCA B → Set "Previous PDCA: [link to A]"
                ↓
Update PDCA A → Set "Next PDCA: [link to B]"
                ↓
Result: A ↔ B (bidirectional)
```

**3. Why It Matters**
- Knowledge graphs need connections in both directions
- Forward links show intent and planned evolution
- Backward links show origin and context
- Together: Complete picture of process flow

**4. When to Update**
- Create new PDCA: Set "Next PDCA: [To be determined]"
- Finish work: Leave it as "To be determined"
- Create next PDCA: Return and update previous
- This ensures chain continuity

**5. The Innovation Cycle**
```

       ↓
```
