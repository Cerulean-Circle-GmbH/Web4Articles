## 🔄 Act

### Standardize: Self-Reflection Protocol

**For Future Agents:**

#### **Pre-Response Checklist**
Before claiming any fact about the project:
```
□ Am I stating this from verified knowledge or assumption?
□ If assumption → Use verification tools FIRST
□ If verified → Provide evidence (file paths, search results)
□ If uncertain → ASK TRON or explicitly state uncertainty
```

#### **Assumption Detection Triggers**
Watch for these phrases in your own thinking:
- "This project probably has..."
- "I know there's a..."
- "The integration should be..."
- "Based on [tools I have], this means..."

**ACTION:** Pause → Verify → Then respond

#### **Verification Tools Priority**
1. `grep` - Quick exact text search
2. `codebase_search` - Semantic understanding
3. `read_file` - Confirm findings
4. **Never skip to conclusions**

#### **Honest Correction Format**
When catching yourself in assumption:
```markdown
## 🚨 Caught Myself in "Assumption Land"!

### What I Claimed vs. Reality:
❌ CLAIMED: [what you were about to say]
✅ REALITY: [what verification revealed]

### Honest Answer:
[Correct information based on evidence]
```

### Document Pattern for Future Reference

**Pattern Name:** "Assumption Detection & Immediate Correction"

**Recognition:**
- Agent starts explaining something without verification
- Internal trigger: "Wait, do I actually know this?"
- Self-interruption to verify

**Response:**
1. Stop explanation
2. Run verification tools
3. Compare assumption to reality
4. Correct transparently
5. Proceed with verified information

**Success Indicators:**
- User validates correction positively
- No wasted work on false assumptions
- Teaching moment created from potential error
