### Why This Is CMM3

**Objective Criteria:**
- ✅ Tests define success, not subjective judgment
- ✅ Reproducible: Same inputs → same outputs
- ✅ Verifiable: Tests prove it works

**Scientific Method:**
- ✅ Hypothesis: These tests define correct behavior
- ✅ Experiment: Implement and run tests
- ✅ Verification: Tests pass/fail objectively
- ✅ Reproducibility: Anyone can run the same tests

**Systematic Quality:**
- ✅ Automated verification (tests)
- ✅ Version control (git)
- ✅ Documentation (trainAI)
- ✅ Knowledge accumulation (RAG loop)

### The Meta-Pattern: RAG-Powered FOR TWO

**Traditional AI agent (TO ONE):**
```
Agent plans → Agent implements → Agent hopes → Agent discovers problems late
```

**RAG-Powered FOR TWO:**
```
Agent queries trainAI → TRON challenges → Agent writes tests → 
Tests fail → Agent implements → Tests pass → 
Agent updates trainAI → TRON validates → Loop closes
```

**Key difference:** External verification at EVERY phase!

1. trainAI verifies planning (RAG)
2. Tests verify implementation (automated)
3. TRON verifies pattern (human-in-loop)

**This is 42 in action:** Never agent alone, always agent + verification

**The CMM3 Feature Development Pattern:**

**Name:** "RAG-Powered Test-First Development"

**When to use:**
- Adding new CLI methods
- Exposing internal functionality
- Creating new features from scratch
- When CMM3 compliance is required

**Prerequisites:**
- trainAI has relevant knowledge
- Test framework exists (vitest)
- Component versioning system works
- TRON available for validation

**Steps:**

**0. RAG Preparation (5 min)**
```bash
pdca trainAI how-to-test-first
pdca trainAI how-to-component
pdca trainAI <domain-specific-topic>
```
Read output, internalize patterns

**1. Problem Analysis with TRON (10 min)**
- TRON states problem/challenge
- Agent queries clarifying questions
- Extract naming, UX, scope requirements
- Document in PDCA (Plan section)

**2. Test-First Design (20 min)**
- Write test file with 5-7 test cases
- Cover happy path, edge cases, errors
- NO implementation code yet
- Tests should compile but fail

**3. Expected Failure (2 min)**
```bash
npm test -- <new-test-file>
# Expected: Tests fail with "method not found"
```
Read output, confirm expectation, DO NOT manually test

**4. Implementation (30 min)**
- Add method to component
- Make it public, add CLI annotations
- Keep internal helpers private
- Add ONLY what's needed for tests

**5. Green Light (2 min)**
```bash
npm test
# Expected: All tests pass
```
If pass → done, no manual verification

**6. trainAI Integration (10 min)**
- Update relevant trainAI topics
- Add new tool to lessons
- Update verification checklist
- Run `npm test` to propagate

**7. Git Commit (5 min)**
```bash
git add -A
git commit -m "feat: <feature> (test-first)"
git push
```

**Total time:** ~90 minutes for CMM3-compliant feature

- [ ] All automated tests pass

- [ ] Git history shows test-first approach
