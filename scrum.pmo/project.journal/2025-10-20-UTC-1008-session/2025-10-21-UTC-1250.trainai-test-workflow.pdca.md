**Key Lessons**:
- 🔗 Semantic links: latest (dev work) → test (testing) → dev (stable) → prod (production)
- 🧪 Workflow: Work on `latest` → run `pdca test` → auto-promotes to `test` on success
- ✅ Auto-promotion: `pdca test` creates `test` symlink when tests pass
- 🔧 Test iteration: `web4tscomponent on PDCA latest test itCase` shows test tree
- 📊 View structure: `web4tscomponent on PDCA latest tree links` shows semantic links
- 🛑 WORKFLOW REMINDER: Always work on dev until test → work on test until success → work on dev after success
- ⚠️ Version promotion: Use component commands, NEVER manual symlinks
- 🎯 Test selection: `web4tscomponent test itCase <token>` to run specific tests
- ❌ Violated pattern: Fixing tests on `latest` instead of `test` version

**Verification Checklist**:
- Understands 4-level semantic versioning (latest, test, dev, prod)
- Knows the test workflow (latest → test → dev → prod)
- Recognizes auto-promotion on test success
- Can use `test itCase` to view and select tests
- Can use `tree links` to view semantic version state
- Knows to obey the WORKFLOW REMINDER
- Understands why manual symlink changes are CMM3 violations
