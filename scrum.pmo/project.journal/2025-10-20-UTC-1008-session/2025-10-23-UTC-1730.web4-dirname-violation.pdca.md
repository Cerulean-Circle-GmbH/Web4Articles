**Title:** 🔄 Web4 vs Node.js: Pattern Migration Guide

**Description:**
Web4 components use modern ES modules and strict naming conventions. This guide covers common Node.js patterns and their Web4-compliant equivalents.

**Key Lessons:**

1. **File Path Resolution**
   ```typescript
   // ❌ Node.js CommonJS (has underscores!)
   const dir = __dirname;
   const file = __filename;
   
   // ✅ Web4 ES Modules (no underscores)
   const currentFileUrl = new URL(import.meta.url);
   const dir = path.dirname(currentFileUrl.pathname);
   const file = currentFileUrl.pathname;
   ```

2. **Why This Matters**
   - Web4 Principle: **NO underscores** in ANY naming (including Node.js globals)
   - ES Modules: `__dirname` and `__filename` don't exist in ES module scope
   - Consistency: All Web4 components use `import.meta.url` pattern

3. **Pattern Source**
   - Reference: `components/Web4TSComponent/latest/src/ts/layer2/DefaultWeb4TSComponent.ts`
   - Line ~19-20: Constructor initialization pattern
   - This pattern is used across ALL Web4 components

4. **When to Use**
   - ✅ Test files that need to find fixtures or test data
   - ✅ CLI files that need to resolve template paths
   - ✅ Any code that needs current file location
   - ❌ Never use `__dirname` or `__filename` (they violate Web4 naming)

5. **RAG Query Hints**
   - Query: "dirname file path test" → Should find this topic
   - Query: "web4 naming conventions underscore" → Should find this topic
