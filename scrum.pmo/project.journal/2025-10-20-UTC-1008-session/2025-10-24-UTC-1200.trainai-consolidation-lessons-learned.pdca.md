### Key Lessons Identified

#### 1. Self-Healing Architectural Pattern
**Lesson:** When a tool breaks files it manages, fix the tool's logic and let it heal the damage.

**Why it matters:**
- Scalable (fixes 400+ files automatically)
- Reproducible (test-first ensures correctness)
- Elegant (root cause > symptoms)
- Self-documenting (code is the fix)

**Previous approach (failed):**
- Manual file fixes using `write` tool
- File persistence issues
- Not scalable
- Didn't address root cause

#### 2. Enhanced Detection Strategies
**Lesson:** Check first 20 lines for shebang, not just line 1.

**Why it matters:**
- Handles cases where tool already broke the file
- Allows detection even with wrong header on line 1
- More resilient than simple line 1 check

**Code pattern:**
```typescript
const lines = content.split('\n').slice(0, 20);
const hasShebang = lines.some(line => line.trim().startsWith('#!'));
```

#### 3. Format Validation in hasValidHeader
**Lesson:** Validating header content is not enough - must validate format too.

**Why it matters:**
- Detects `/**` when `#` expected
- Triggers updates for format mismatches
- Prevents "header exists but wrong format" false positives

**Code pattern:**
```typescript
// Check if header is in the CORRECT FORMAT
if (expectedHeader.startsWith('#') && content.includes('/**')) {
  return false; // Wrong format - needs update
}
```

#### 4. Comprehensive Header Cleanup
**Lesson:** When applying headers, remove ALL old/duplicate headers first.

**Why it matters:**
- Prevents double headers
- Removes wrong-format headers
- Ensures clean state before insertion

**Code pattern:**
```typescript
// Remove any existing /** block comments
restOfContent = restOfContent.replace(/^\/\*\*[\s\S]*?\*\/\n*/gm, '');
// Remove existing # SPDX headers
restOfContent = restOfContent.replace(/^# SPDX-License-Identifier:.*$/gm, '');
// ... remove other header lines ...
```

#### 5. Shebang Preservation Pattern
**Lesson:** Extract shebang from anywhere in first 20 lines, remove it, process content, then prepend it.

**Why it matters:**
- Guarantees shebang on line 1
- Works even if shebang was buried
- Prevents shebang loss

**Code pattern:**
```typescript
let shebang = '';
let restOfContent = content;
const lines = content.split('\n');
const shebangIdx = lines.findIndex(line => line.trim().startsWith('#!'));
if (shebangIdx >= 0) {
  shebang = lines[shebangIdx] + '\n';
  lines.splice(shebangIdx, 1);
  restOfContent = lines.join('\n');
}
// ... process restOfContent ...
return shebang + processedContent;
```

#### 6. Test-First Despite Emergency
**Lesson:** Emergency fixes without tests lead to incomplete solutions.

**Why it matters:**
- RAG explicitly warns against emergency fixes
- Tests prove the bug exists
- Tests prove the fix works
- Tests prevent regression

**Meta-learning:**
- We violated this once → incomplete fix
- Corrected course → complete fix
- Documented in PDCA for future agents

#### 7. .gitmodules and Config Files
**Lesson:** Some files should NEVER have license headers (.gitmodules, package.json, etc.)

**Why it matters:**
- Git config files break with comments
- Need exclusion list in LicenseTool

**TODO:** Add exclusion pattern to LicenseTool.

#### 8. Node.js `fs` Module is the Working Method
**Lesson:** File persistence in WSL2/Docker requires Node.js `fs` module for modifications.

**Why it matters:**
- Cursor's tools don't persist in this environment
- Already documented in `2025-10-24-UTC-0930.root-cause-file-modification-method.pdca.md`
- Must use for all file operations

#### 9. RAG Query Before Reporting
**Lesson:** When approaching context window limits, query RAG before reporting.

**Why it matters:**
- Prevents elaborate summaries (context window symptom)
- Ensures CMM3 compliance
- Follows forcing function checklist
