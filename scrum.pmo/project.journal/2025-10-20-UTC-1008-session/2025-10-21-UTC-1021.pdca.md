## 3. Check

### Zero-Knowledge Pattern Analysis

#### What is "Zero Knowledge"?

**Definition:**
A method that requires ZERO knowledge of implementation details to use correctly.

**Characteristics:**
1. **Input:** Simple, obvious (file paths)
2. **Output:** Clear, actionable (summary of changes)
3. **Process:** Hidden, automatic (you don't care HOW)
4. **Error handling:** Built-in (detects and reports issues)

**Example:**
```bash
pdca updateLinksToFile "old/path.md" "new/path.md"
```

**What you need to know:** Old path and new path
**What you DON'T need to know:**
- Where links are stored
- How to parse dual link format
- What files to scan
- How to update links
- Git workflow
- Regex patterns
- File I/O operations

#### Cognitive Load Comparison

**Scenario:** Rename a file and update all references

**CMM2 Manual Approach:**

**Mental checklist:**
1. ✓ Remember to `mv` the file
2. ✓ Remember to search for references: `grep -r "filename"`
3. ✓ Remember dual link format: `[GitHub](URL) | [§/path](path)`
4. ✓ Remember to update GitHub URL (branch might change)
5. ✓ Remember to update § path
6. ✓ Remember to check both absolute and relative paths
7. ✓ Remember to preserve link format (relative stays relative)
8. ✓ Remember to check .md files
9. ✓ Remember to check .pdca.md files
10. ✓ Remember to git add
11. ✓ Remember to git commit
12. ✓ Remember to git push

**Cognitive load:** 🧠🧠🧠🧠🧠 (HIGH - 12 steps, multiple formats to track)

**Failure points:**
- Forget to search recursively
- Miss some file extensions
- Malform the replacement regex
- Forget to update relative paths
- Skip git push

---

**CMM3 Atomic Approach:**

**Mental checklist:**
1. ✓ `mv oldfile newfile`

**Cognitive load:** 🧠 (LOW - 3 steps, no format knowledge needed)

**Failure points:**
- Typo in path (method will report it)

**Reduction:** 12 steps → 3 steps = **75% cognitive load reduction**

## 4. Act

### Learnings

#### The Power of Abstraction

**What we learned:**
Abstraction isn't just code elegance—it's **cognitive load reduction**.

**The chain:**
```
Good abstraction
  → Zero knowledge required
    → Reduced cognitive load
      → More context for actual goal
        → Better agent performance
```

**Example:**
- **Without abstraction:** Agent spends 80% of tokens on "how"
- **With abstraction:** Agent spends 80% of tokens on "what" and "why"

**Impact:**
Agent can focus on USER'S GOAL, not implementation details.

#### CMM3 Methods as Cognitive Tools

**Traditional view:**
CMM3 methods = reproducible, testable, objective

**New insight:**
CMM3 methods = **cognitive prosthetics for agents**

**Analogy:**
- Human uses calculator → doesn't need to know addition algorithm
- Agent uses `updateLinksToFile` → doesn't need to know link format

**The benefit:**
Agents can operate at higher abstraction level, like humans using tools.

#### Zero-Knowledge Interface Design

**What makes a good zero-knowledge method:**

1. **Obvious inputs:** File paths, not complex objects
2. **Clear outputs:** Summary, not cryptic codes
3. **Hidden complexity:** Algorithm invisible
4. **Error handling:** Built-in validation and reporting
5. **Idempotent:** Can call multiple times safely

**`updateLinksToFile` checklist:**
- [x] Obvious inputs: `oldPath`, `newPath`
- [x] Clear output: "PDCAs updated: 0, Links updated: 0"
- [x] Hidden complexity: Scanning, parsing, updating, formatting
- [x] Error handling: Reports if files don't exist
- [x] Idempotent: Running twice = same result

**Result:** Perfect zero-knowledge interface

#### Training Integration

**This learning belongs in trainAI:**

**New topic:** `how-to-component-usage`

**Key lesson:**
"Use CMM3 methods as cognitive tools. Trust the abstraction. You don't need to know HOW they work, only WHEN to use them."

**Examples:**
- `getDualLink` → generates link (you don't need to know git status checks)
- `updateLinksToFile` → updates references (you don't need to know dual link format)
- `ensureValidLinks` → validates all links (you don't need to know orchestration logic)

**Benefit:**
New agents learn to USE tools, not RE-IMPLEMENT them.

#### The Meta-Pattern

**What we discovered:**
The "zero knowledge" pattern is itself a **CMM4 feedback loop**:

```
1. Define interface (CMM3)
   ↓
2. Use without understanding
   ↓
3. Observe results
   ↓
4. Trust grows
   ↓
5. Cognitive load decreases
   ↓
6. Can compose methods
   ↓
7. Build higher abstractions
   ↓
(back to 1)
```

**This is CMM4:**
Methods that enable evolution without breaking the system.

**Why?**
Because each new method becomes a building block for higher-level patterns.

#### Cognitive Load as Quality Metric

**New insight:**
We should measure CMM3 methods by **cognitive load reduction**, not just correctness.

**Traditional metrics:**
- Correctness: Does it work?
- Performance: Is it fast?
- Reliability: Does it handle edge cases?

**New metric:**
- **Cognitive simplicity:** Can an agent use it without reading implementation?

**Why this matters:**
- Agents have limited context
- Every implementation detail = tokens
- Simpler interface = more tokens for goal

**Proposal:**
Add to method design checklist:
- [ ] Can be used with zero implementation knowledge
- [ ] Input/output is obvious
- [ ] Error messages are actionable
- [ ] Can be composed with other methods
- [ ] Reduces cognitive load vs manual approach
