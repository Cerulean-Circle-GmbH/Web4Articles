### Key Lessons Learned

#### Lesson 1: RAG-Powered Preparation is the Secret Weapon
**Pattern:**
```
Query trainAI BEFORE planning
↓
Read referenced docs to depth 3
↓
Build complete mental model
↓
Plan with full context
↓
Implement once, correctly
```

**Why this works:**
- External knowledge (trainAI) prevents assumption cascade
- Reading depth 3 uncovers hidden patterns
- Complete mental model eliminates trial-and-error

**Counter-intuitive insight:**
- Spending 30 minutes reading feels slow
- But saves 2-3 hours of debugging/refactoring
- Net result: Faster time to CMM3-compliant solution

#### Lesson 2: TRON Challenges are Refinement Opportunities
**Pattern:**
```
Implement with best knowledge
↓
TRON: "Wait, that's not right"
↓
Research correct pattern (not defend current)
↓
Document learning
↓
Update plan
↓
Implement correctly
```

**Why this works:**
- User has knowledge agent doesn't
- Challenges expose knowledge gaps
- Researching teaches pattern to future agents
- Updated plan prevents repeating mistake

**Anti-pattern:**
- Defending current implementation
- "But this is how I thought it should work"
- Proceeding with wrong pattern

#### Lesson 3: Test-First Eliminates "One More Loop"
**Observation:**
- Without tests: Implement → Manual check → "Hmm, let me fix this" → Manual check → "One more thing" → Manual check...
- With tests: Implement → Tests pass → **DONE**

**Why this works:**
- Tests define objective success criteria
- No ambiguity, no second-guessing
- "Did I handle edge cases?" → Tests answer
- "Is output formatted correctly?" → Tests answer

**Time savings:**
- Manual verification: 5-10 minutes per cycle × 3-5 cycles = 15-50 minutes
- Test-first: Run tests once = 30 seconds

#### Lesson 4: DRY at Planning Stage, Not Refactoring Stage
**Observation:**
- Previous pattern: Implement → Notice duplication → Refactor to DRY
- New pattern: **Identify reusable parts in plan** → Extract helpers from start

**Why this works:**
- Planning with DRY prevents duplication from being written
- No refactoring needed later
- Code is cleaner from first commit

**Example:**
- Planned `_getTrainingTopicsInternal()` as DRY helper in UTC-1650
- Implemented it from start
- Avoided writing duplicate topic definitions
- Future work: Refactor `trainAI` to use same helper (true single source of truth)

#### Lesson 5: Web4 Principles Research Pays Exponential Dividends
**Investment:**
- 30 minutes reading Web4TSComponent README (1800+ lines)
- Followed breadcrumbs: README → howto.cmm → tech-stack → etc.

**Return:**
- Learned 7 core principles: DRY, Radical OOP, Method Chaining, Auto-Discovery, Layered Architecture, Semantic Versioning, Positional Parameters
- Applied ALL 7 principles in one implementation
- No trial-and-error with patterns
- No "I didn't know about that" moments

**Compounding value:**
- These principles apply to EVERY future feature
- No need to re-learn for next implementation
- Pattern becomes automatic

#### Lesson 6: "One Loop" is CMM4 Excellence
**Observation:**
- Multiple loops = CMM2 (trial and error)
- One loop = CMM3 (planned, reproducible)
- One loop + documented pattern = **CMM4** (systematic improvement)

**Why one loop matters:**
- Efficiency: 90 minutes vs 3-4 hours
- Quality: Tests define correctness from start
- Confidence: TRON doesn't need to review intermediate steps
- Replicability: Pattern documented for next feature

**TRON feedback confirms:**
- "VERY AWESOME JOB! it works and you did it in one loop. i am impressed!"
- User recognizes efficiency

- Enables higher-level collaboration
