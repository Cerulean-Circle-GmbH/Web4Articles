## 1. Plan

### Trigger (Verbatim User Report)

**User:** "check this log. i wanted to create a dual link from the path i asked for it and then added it into an md file `/var/dev/Workspaces/2cuGitHub/Web4Articles/temp/tpichler/linktest.md` to test the dual link. Git is working but the file itself not as the script needs to be relative"

**Context:**
```bash

# Generated:
[§/scrum.pmo/.../test123.feature.pdca.md](scrum.pmo/project.journal/.../test123.feature.pdca.md)
```

**Problem:** When placed in `temp/tpichler/linktest.md`, the link doesn't work because the path is absolute from project root, not relative to the file's location.

### Response (Root Cause Analysis)

#### Current Behavior (BROKEN):
```typescript
// getDualLink generates:
[§/scrum.pmo/.../file.md](scrum.pmo/.../file.md)
                          ↑ absolute from project root
```

When this link is placed in `temp/tpichler/linktest.md`:
- Link tries to navigate to: `temp/tpichler/scrum.pmo/.../file.md` ❌
- Should navigate to: `../../scrum.pmo/.../file.md` ✅

#### Root Cause:
`getDualLink` method always generates **project-root-relative paths**, not **file-relative paths**.

#### Why This is CMM3 Critical:
1. **Broken Functionality:** Links don't work in markdown viewers
2. **User Experience:** Copy-paste dual link doesn't work
3. **CMM3 Verifiable:** Can't verify links work by clicking them
4. **Design Flaw:** Method doesn't consider where link will be used

### Outcome (Solution Design)

#### Option 1: Add Optional Parameter (CHOSEN)
```typescript
getDualLink(filePath: string, fromDirectory?: string): Promise<this>
```

**If `fromDirectory` provided:**
- Calculate relative path from `fromDirectory` to `filePath`
- Use relative path in `(url)` part of dual link

**If `fromDirectory` NOT provided (backward compatible):**
- Use current working directory (`process.cwd()`)
- Calculate relative path from CWD to target file

#### Option 2: Always Use CWD (Simpler, Less Flexible)
```typescript
// Always calculate relative from process.cwd()
const relativePath = path.relative(process.cwd(), targetPath);
```

**Chosen: Option 1** - More flexible, allows explicit directory specification

## 4. Act

### Learnings

#### Critical Insight: CLI Script State Changes
**Problem:** `process.cwd()` returns where the script runs, NOT where user called it from.

**Root Cause:** The `scripts/pdca` bash script does `cd "$COMPONENT_PATH"` (line 34), changing the working directory to `components/PDCA/latest/`.

**Solution:** Capture `PWD` **BEFORE** any `cd` commands in the bash script:
```bash
export USER_PWD="$PWD"  # Line 9, before any cd
```

Then use it in TypeScript:
```typescript
const userPwd = process.env.USER_PWD || process.env.PWD || process.cwd();
```

#### CLI Optional Parameter Pattern
**Wrong:** `fromDirectory?: string` + `@cliSyntax filePath <?fromDirectory>`
**Right:** `fromDirectory: string = ""` + `@cliSyntax filePath fromDirectory` + `@cliDefault fromDirectory ""`

The CLI auto-discovery requires:
1. Default value in function signature (`= ""`)
2. `@cliDefault` annotation
3. NO `?` in `@cliSyntax`
