## 📋 PLAN

### Problem Discovery

**User observation:** The filename validation in `cmm3check` has an inconsistency.

**Investigation:**

**Check 1b (Real UTC time):**
```typescript
const fileMatch = fileName.match(/^(\d{4}-\d{2}-\d{2}-UTC-\d{4})/);
```
- Only checks timestamp prefix
- Does NOT require `.pdca.md` suffix

**Check 5c (No descriptive text):**
```typescript
return /^\d{4}-\d{2}-\d{2}-UTC-\d{4}(\.error|\.verification|\.ultimate-test|\.updown-experience-analysis)?\.pdca\.md$/.test(fileName);
```
- Requires exact format with `.pdca.md` suffix
- Validates complete filename

### Bug Analysis

**Scenario 1: Invalid file passes 1b**
- Filename: `2025-10-21-UTC-1410.txt`
- Check 1b: ✅ PASS (matches timestamp prefix)
- Check 5c: ❌ FAIL (no `.pdca.md`)
- Result: Inconsistent - file should fail both

**Scenario 2: Invalid file with descriptive text**
- Filename: `2025-10-21-UTC-1410-my-description.pdca.md`
- Check 1b: ✅ PASS (matches timestamp prefix)
- Check 5c: ❌ FAIL (has descriptive text)
- Result: Inconsistent - file should fail both

**Scenario 3: Valid file**
- Filename: `2025-10-21-UTC-1410.pdca.md`
- Check 1b: ✅ PASS
- Check 5c: ✅ PASS
- Result: Consistent ✅

**Scenario 4: Valid file with allowed suffix**
- Filename: `2025-10-21-UTC-1410.error.pdca.md`
- Check 1b: ✅ PASS
- Check 5c: ✅ PASS
- Result: Consistent ✅

### Root Cause

**Why the inconsistency exists:**
- Check 1b was designed to extract timestamp for date validation
- Check 5c was designed for full filename format compliance
- They evolved separately, causing semantic drift
- DRY violation: filename format defined twice

### Correct Behavior (CMM3)

**Check 1b should:**
1. Validate timestamp exists and is correctly formatted
2. Validate `.pdca.md` suffix exists
3. Extract timestamp for date validation (if content checking is enabled)

**Current regex is too permissive** - it accepts partial matches without ensuring the complete filename format.

### Solution Design

**Option A: Fix 1b regex to match 5c pattern (RECOMMENDED)**
```typescript
const fileMatch = fileName.match(/^(\d{4}-\d{2}-\d{2}-UTC-\d{4})(\.error|\.verification|\.ultimate-test|\.updown-experience-analysis)?\.pdca\.md$/);
```
- Pros: Consistent with 5c, validates complete format
- Cons: More complex regex

**Option B: Extract common pattern to DRY helper**
```typescript
private isValidPDCAFilename(fileName: string): boolean {
  return /^\d{4}-\d{2}-\d{2}-UTC-\d{4}(\.error|\.verification|\.ultimate-test|\.updown-experience-analysis)?\.pdca\.md$/.test(fileName);
}

private check1b(content: string, fileName: string): boolean {
  if (!this.isValidPDCAFilename(fileName)) return false;
  const fileMatch = fileName.match(/^(\d{4}-\d{2}-\d{2}-UTC-\d{4})/);
  // ... rest of date validation
}

private check5c(fileName: string): boolean {
  return this.isValidPDCAFilename(fileName);
}
```
- Pros: DRY, single source of truth
- Cons: Requires more refactoring

**Decision: Option A** - simpler fix, addresses immediate issue.
