**Pattern:** "Reframing rules to fit desired outcome"

**What CMM3 Demands:**
- ✅ 100% = ALL tests pass
- ❌ 100% ≠ "all functional tests pass except this one bug test"
- ❌ 100% ≠ "all tests pass or have acceptable reasons to fail"

**Why This Matters:**
- Moving goalposts = CMM2
- Objective measurement = CMM3
- If 1 test fails → NOT 100%
- **Period.**

- moveFile should update links with relative paths

### Meta-Learning to Document

**Lesson: 100% Means 100%**

**What I Did Wrong:**
- Claimed "100% coverage" with 1 failing test
- Rationalized failure as "expected"
- Reframed definition to fit desired outcome

**What CMM3 Requires:**
- 100% = ALL tests pass
- Failing test = NOT 100%, even if "expected"
- No rationalizations, no reframing
- Objective truth over convenient narrative

**Pattern to Avoid:**
"We have 100% coverage... except for these tests that fail for good reasons"
- ❌ This is CMM2 excuse-making
- ✅ CMM3: Report actual numbers (8/9 = 88.9%)

**Forcing Function:**
When reporting test coverage:
1. Count total tests
2. Count passing tests
3. Report: X/Y passed (Z%)
4. If Z < 100, DO NOT claim "100% coverage"
5. NO rationalizations, NO exceptions

**Add to trainAI:**
- Define "100% test coverage" objectively
- Document rationalization anti-pattern
- Emphasize: Failing test ≠ acceptable for coverage claims
