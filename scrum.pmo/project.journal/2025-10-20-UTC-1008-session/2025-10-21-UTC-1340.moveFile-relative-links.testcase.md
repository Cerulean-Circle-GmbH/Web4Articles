## ❌ Actual Results (Bug Documentation)

### Issue 1: Links TO moved file are absolute

**File A after moveFile**:
```markdown
- Link to B: [...](components/PDCA/0.2.3.0/test/data/move-tests/subdir/test-fileB.md)
```

**Problem**: Local link is project-root-relative, not file-relative
- ❌ Has: `components/PDCA/0.2.3.0/test/data/move-tests/subdir/test-fileB.md`
- ✅ Should be: `subdir/test-fileB.md`

**Why this fails**: 
- From File A's perspective, clicking this link tries to navigate to absolute path
- Markdown viewers expect relative paths
- Link doesn't work in IDE or when viewing file locally

### Issue 2: Links FROM moved file are not updated

**File B after moveFile**:
```markdown
- Link to C: [...](test-fileC.md)
```

**Problem**: Relative link was not adjusted for new location
- ❌ Has: `test-fileC.md` (looking in same dir as B)
- ✅ Should be: `../test-fileC.md` (go up one dir)

**Why this fails**:
- File B is now in `move-tests/subdir/`
- File C is still in `move-tests/`
- Old relative path no longer valid from new location

## 🔍 Root Cause Analysis

### Method Call Flow

```
moveFile()
  ↓
1. git mv (moves the file) ✅
  ↓
2. updateLinksToFile() (updates links TO moved file)
   - Finds all files linking to the moved file
   - Updates their dual links
   - Problem: Uses project-root-relative paths instead of file-relative
  ↓
3. [MISSING] refreshRelativeLinks() on moved file
   - Should update links FROM the moved file
   - Should recalculate relative paths based on new location
   - This step is NOT being called!
```

### Code Issue Location

In `DefaultPDCA.ts` `moveFile()` method:
```typescript
// Step 4: Update Links in Other Files (DRY: Reuse updateLinksToFile)
console.log(`🔗 Step 2: Updating links in other files...`);
await this.updateLinksToFile(oldPath, newPath, dryRun);

// MISSING: Should call refreshRelativeLinks here!
// await this.refreshRelativeLinks(newPath, dryRun);
```

### Why `updateLinksToFile` generates absolute paths

In `updateLinksToFile()`:
```typescript
// Current code generates project-root-relative path:
const newLocalLink = newNormalized; // This is project-root-relative!

// Should calculate file-relative path:
const newLocalLink = calculateRelativePath(linkingFile, targetFile);
```

---

## 🔧 Required Fixes

### Fix 1: Make `updateLinksToFile` generate relative paths

**Change**: When updating a link, calculate the relative path from the linking file to the target file.

**Implementation**:
```typescript
// In updateLinksToFile, after finding a link to update:
const linkingFileDir = path.dirname(linkingFilePath);
const targetFileFullPath = path.join(projectRoot, newNormalized);
const relativePathToTarget = path.relative(linkingFileDir, targetFileFullPath);
const newLocalLink = relativePathToTarget;
```

### Fix 2: Add `refreshRelativeLinks` call to `moveFile`

**Change**: After updating links to the moved file, refresh the moved file's own links.

**Implementation**:
```typescript
// In moveFile, after updateLinksToFile:
console.log(`🔗 Step 3: Refreshing relative links in moved file...`);
await this.refreshRelativeLinks(newPath, dryRun);
```
