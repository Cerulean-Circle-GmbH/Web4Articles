### Research: Web4 CLI Syntax Patterns

**Observed patterns from `web4tscomponent` and `pdca` CLIs:**

### Pattern 1: Positional Parameters (Not Flags!)

**web4tscomponent examples:**
```bash
web4tscomponent on <component> <?version>
web4tscomponent create <component> <?version> <?options>
web4tscomponent removeVersion <?component> <?version>
```

**pdca examples:**
```bash
pdca trainAI <topic>
pdca getDualLinkRelativePath <fromFile> <toFile>
pdca updateLinksToFile <oldPath> <newPath> <?dryRun>
pdca moveFile <oldPath> <newPath> <?dryRun>
```

**Key insight:** Web4 uses **positional parameters**, NOT flags!
- ❌ `--topic <value>` (flag syntax)
- ✅ `<topic>` (positional parameter)

### Pattern 2: Required vs Optional Parameters

**Notation:**
- `!<param>` or `<param>` = Required
- `<?param>` = Optional
- `<?param:'default'>` = Optional with default value

**Examples:**
```bash
pdca trainAI !<topic>                    # topic is required
pdca moveFile !<oldPath> !<newPath> !<?dryRun:'false'>  # dryRun is optional with default
web4tscomponent on <component> <?version:'current'>     # version optional, defaults to 'current'
```

### Pattern 3: Method + Positional Parameters

**Web4 method signature pattern:**
```typescript
async methodName(param1: type1, param2?: type2): Promise<this>
```

**CLI translation:**
```bash
command methodName <param1> <?param2>
```

**NOT:**
```bash
command methodName <param1> --param2 <value>  # ❌ Wrong! Unix-style flags
```

### Pattern 4: CLI Annotations

**From DefaultPDCA.ts examples:**

```typescript
/**
 * Train AI agents on specific topics
 * @param topic Training topic identifier
 * @cliSyntax topic
 * @cliValues topic how-to-start how-to-pdca ... 1 2 3 ...
 */
async trainAI(topic: string): Promise<this>
```

**For multiple parameters:**
```typescript
/**
 * Calculate relative path from one file to another
 * @param fromFile Source file path
 * @param toFile Target file path
 * @cliSyntax fromFile toFile
 */
async getDualLinkRelativePath(fromFile: string, toFile: string): Promise<this>
```

**For optional parameters:**
```typescript
/**
 * Move file and update links
 * @param oldPath Source path
 * @param newPath Destination path
 * @param dryRun Preview without writing
 * @cliSyntax oldPath newPath dryRun
 * @cliDefault dryRun "false"
 */
async moveFile(oldPath: string, newPath: string, dryRun?: string): Promise<this>
```

### Corrected Design for queryTrainAI

**My incorrect design (UTC-1620):**
```bash
pdca trainAI query <question> --topic <topic>  # ❌ Wrong! Flag syntax
```

**Correct Web4 design:**
```bash
pdca queryTrainAI <query> <?topic>
```

**Method signature:**
```typescript
/**
 * Query trainAI knowledge base with natural language questions
 * 
 * @param query Natural language question
 * @param topic Optional: limit search to specific topic
 * @cliSyntax query topic
 * @cliDefault topic ""
 */
async queryTrainAI(query: string, topic?: string): Promise<this>
```

**Usage examples:**
```bash
# Cross-topic search (no topic specified)
pdca queryTrainAI "How do I calculate relative paths?"

# Scoped search (topic specified as positional parameter)
pdca queryTrainAI "links" how-to-dual-links

# Also valid (empty string for cross-topic)
pdca queryTrainAI "test first" ""
```

### Key Web4 CLI Principles

1. **Positional Parameters Only**
   - No flags (`--flag`)
   - No options (`-o`)
   - Parameters in order

2. **Optional Parameters = Trailing**
   - Required first
   - Optional after
   - Can omit trailing optionals

3. **@cliSyntax Defines Order**
   - Order matters!
   - `@cliSyntax query topic` means `<query>` then `<?topic>`

4. **@cliDefault for Optionals**
   - Provides default value
   - User can omit parameter
   - System uses default

5. **@cliValues for Completion**
   - Tab completion values
   - Helps user discovery
   - Not validation (just hints)

### Why This Matters

**Unix-style (what I incorrectly suggested):**
```bash
pdca trainAI query "test" --topic how-to-test-first --format json
```
- Flexible order
- Explicit parameter names
- Common in many CLIs

**Web4 style (correct):**
```bash
pdca queryTrainAI "test" how-to-test-first
```
- Simple, clean
- Positional order
- No flag parsing needed
- Consistent across all Web4 components

### Comparison Table

| Aspect | Unix Style (❌) | Web4 Style (✅) |
|--------|----------------|----------------|
| Syntax | `--param value` | `<param>` positional |
| Order | Flexible | Fixed by @cliSyntax |
| Optionals | `--opt value` or omit | Trailing, omit from end |
| Discovery | `--help` flag | Auto-discovery from annotations |
| Consistency | Varies by tool | Uniform across Web4 |
| Complexity | Flag parsing logic | Simple positional args |
