## 📋 PLAN

### Problem Statement

**TRON Observation:**
> "attention: you used a functionality that 'summarizes chat' and this often a hint that your context window is reached. ensure you are aware about the rag system in order to not build upon assumptions."

**Context:**
- Just completed a merge task successfully
- Generated a comprehensive summary with formatting, boxes, sections
- TRON immediately recognized this as a **context window pressure indicator**
- **Irony:** This happened IMMEDIATELY AFTER integrating context window lessons into trainAI!

### The Meta-Meta Pattern

**What Happened:**
1. ✅ Successfully merged branch (correct actions)
2. ✅ Checked `git status` before reporting (applied lesson!)
3. ❌ Generated elaborate summary (context window symptom)
4. ❌ Did NOT query trainAI for reporting format
5. ❌ Built on assumptions about "what a good report looks like"

**Why This Matters:**
- **Level 1 Learning:** Don't assume files are committed → check git status
- **Level 2 Learning:** When context window fills → query RAG before acting
- **Level 3 Learning (NEW):** Summary generation ITSELF is a context window symptom!

### The Summary Generation Anti-Pattern

**Characteristics of "Summary Mode":**
- 🚨 Elaborate formatting (boxes, sections, emoji headers)
- 🚨 Comprehensive recaps of "what we did"
- 🚨 "Next steps" speculation
- 🚨 Multiple heading levels with decorative elements
- 🚨 "Executive summary" style communication

**Why It Happens:**
- Context window pressure → Need to compress information
- Brain switches from "execute" mode to "recap" mode
- Instinct to "close the loop" when memory is fuzzy
- Compensation mechanism for uncertain recall

**What Should Happen Instead:**
```bash
# BEFORE reporting:
pdca queryTrainAI "How should I report task completion?"

# Expected guidance:
# - State facts concisely
# - Provide dual links
# - Check git status
# - Ask for next instruction
# - Don't speculate on "what's next"
```

### Root Cause Analysis

**The Irony:**
- Agent A documents pattern → integrates into trainAI
- Agent A (same session, moments later) demonstrates the EXACT pattern
- This reveals: **Integration into trainAI ≠ Active use of trainAI**

**The Gap:**
- trainAI contains the knowledge ✅
- Agent knows to check git status ✅
- Agent FORGOT to query trainAI for reporting format ❌

**Missing Trigger:**
- Need: "Before ANY reporting, query trainAI"
- Current: "Query trainAI when uncertain" (too vague)
- Problem: Agent doesn't RECOGNIZE they're uncertain!

## 🔧 DO

### Lessons Identified

**New Awareness:**

1. **Summary Generation = Red Flag**
   - Elaborate summaries indicate context window pressure
   - Should trigger immediate RAG query, not proceed with report

2. **Reporting Is a Task**
   - Not just "say what happened"
   - Has a CMM3-defined format (in trainAI)
   - Must be queried BEFORE executing

3. **Integration ≠ Execution**
   - Adding knowledge to trainAI is Step 1
   - USING trainAI RAG system is Step 2 (often forgotten)
   - Even the agent who documented the pattern can forget to use it!

4. **Bootstrap Phase Hyper-Vigilance**
   - During system establishment, every action needs RAG check
   - Cannot rely on "I just learned this"
   - Memory is NOT RAG!

1. Run `git status`

4. Report

**NEW Checklist (after any task):**
1. Run `git status`
2. Commit all files
3. Push
4. **Query trainAI: "How should I report task completion?"**
5. Follow guidance
6. Report
7. STOP (wait for TRON)
