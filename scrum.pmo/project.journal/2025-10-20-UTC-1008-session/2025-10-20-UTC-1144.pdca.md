## 4. Act

### Learnings

#### CMM4 Meta-Learning: Mistakes Become Training Material
**The Power of Systematic Learning Transfer:**
- Today's CMM2 violation (manual version creation) became tomorrow's training content
- Instead of just fixing the error, we **documented the pattern** in `trainAI`
- Next agent running `pdca trainAI how-to-component` will see: "⚠️ NEVER manually copy component versions - violates CMM3"
- **This is CMM4 in action**: Error → Learn → Correct → Systematize → Prevent recurrence

#### Technical Learnings
1. **Component Versioning (CMM3)**:
   - ALWAYS use: `web4tscomponent on <Component> <version> upgrade <promotion>`
   - Semantic promotions: `nextPatch` (0.2.0.0 → 0.2.0.1), `nextMinor` (0.1.x.x → 0.2.0.0), `nextMajor` (x.x.x.x → 1.0.0.0)
   - Symlinks auto-managed: `latest` tracks dev, `prod` stays stable

2. **TypeScript Interfaces for CMM3**:
   - Defined `TrainingTopic` interface with strict structure
   - Type safety ensures all training topics are complete and consistent
   - Compiler verifies CMM3 compliance at build time

3. **CLI Auto-Discovery**:
   - `@cliSyntax topic` - defines parameter order
   - `@cliValues topic how-to-start how-to-pdca...` - enables tab completion
   - Web4 component system automatically generates CLI help

4. **Reading Depth Protocol Integration**:
   - Each training document includes explicit depth levels
   - Depth 3: document → references → secondary references
   - Prevents shallow reading that causes recurring mistakes

#### Process Learnings
- **User-Driven Learning**: User corrected my CMM2 mistake immediately, preventing waste
- **Documentation as Prevention**: trainAI doesn't just inform, it systematically prevents known errors
- **LLM Evolution Through CMM4**: Despite fixed LLM base, capabilities grow through systematic knowledge capture
