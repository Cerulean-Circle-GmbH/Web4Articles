### Component Design

**Component Name:** `LicenseTool`  
**Layer Architecture:**
- **Layer 5 (CLI):** `LicenseToolCLI.ts` - Auto-discovered CLI entry point
- **Layer 2 (Implementation):** `DefaultLicenseTool.ts` - Core logic
- **Layer 3 (Interfaces):** `LicenseTool.interface.ts`, `LicenseToolModel.interface.ts`
- **Layer 4 (Utils):** File discovery, comment style mapping, header builder

**Core Methods (Public, CLI-Exposed):**
1. `check(path: string = '.'): Promise<this>`
   - @cliSyntax: `path`
   - @cliDefault: `path "."` (current directory)
   - Scans files, reports missing/incorrect headers
   - Exit code 0 = all good, 1 = issues found

2. `apply(path: string = '.', dryRun: string = 'false'): Promise<this>`
   - @cliSyntax: `path dryRun`
   - @cliDefault: `path ".", dryRun "false"`
   - Adds/updates headers in files
   - Dry-run mode: report what would be done without modifying

**Internal Methods (Private, @cliHide):**
- `_discoverFiles(path: string): Promise<string[]>` - Find relevant files (respect .gitignore)
- `_getCommentStyle(filePath: string): CommentStyle` - Map extension to comment syntax
- `_buildHeader(filePath: string, commentStyle: CommentStyle): string` - Generate header
- `_hasValidHeader(content: string, expectedHeader: string): boolean` - Check if header present
- `_insertHeader(content: string, header: string): string` - Prepend header to file
- `_shouldSkipFile(filePath: string): boolean` - Exclude node_modules, dist, etc.

### Test-First Design (Phase 2)

**Planned Test Cases (TC1-TC7):**

**TC1: Comment Style Detection**
- Input: File paths with various extensions
- Expected: Correct comment style returned for each
- Files: `.ts` → C-style, `.md` → HTML, `.puml` → single-quote, `.sh` → hash

**TC2: Header Generation**
- Input: File path, comment style
- Expected: Properly formatted header with correct comment syntax
- Verify: SPDX line, copyright, backlinks present

**TC3: scrum.pmo Special Case**
- Input: File path containing `/scrum.pmo/`
- Expected: Header includes AI-GPL note for process artifacts
- Verify: Additional line present only for scrum.pmo files

**TC4: Header Detection - Valid**
- Input: File content with valid header
- Expected: `_hasValidHeader()` returns `true`
- No changes needed

**TC5: Header Detection - Missing**
- Input: File content without header
- Expected: `_hasValidHeader()` returns `false`
- Should trigger insertion

**TC6: Header Insertion**
- Input: File content without header
- Expected: Header prepended, original content preserved
- Verify: No content lost, proper line breaks

**TC7: check() Method - Report**
- Input: Directory with mixed files (some with headers, some without)
- Expected: Console output lists files needing headers
- Exit code: 1 if issues found

**TC8: apply() Dry-Run**
- Input: Directory with files missing headers, dryRun = 'true'
- Expected: Reports what would be done, NO files modified
- Verify: File system unchanged

**TC9: apply() Real Run**
- Input: Directory with files missing headers, dryRun = 'false'
- Expected: Headers added to all files
- Verify: Files modified correctly

**TC10: File Discovery - Respect .gitignore**
- Input: Directory with node_modules, dist
- Expected: Excluded directories not scanned
- Verify: Only tracked files processed
