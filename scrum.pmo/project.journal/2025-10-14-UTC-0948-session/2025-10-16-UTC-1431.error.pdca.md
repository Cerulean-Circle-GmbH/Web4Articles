## **📋 PLAN**

**Objective:** Restore tab completion by creating filterParameterCompletion callback that delegates to shared logic

**Root Cause (REVISED after investigation):**

TSCompletion uses **convention-based naming**, NOT `@cliCompletion` tags!

**TSCompletion Logic (layer4/TSCompletion.ts:432):**
```typescript
const completionMethodName = `${params[paramIndex]}ParameterCompletion`;
```

For parameter named `filter`, it looks for `filterParameterCompletion`.
The `@cliCompletion filter completionNameParameterCompletion` tag is **IGNORED by TSCompletion**!

**Why Tab Completion Broke:**
1. Renamed parameter: `completionName` → `filter`
1. TSCompletion looked for: `filterParameterCompletion` (by convention)
1. Only exists: `completionNameParameterCompletion`
1. No match → Falls back to file completion ❌

**Fix Strategy:**
1. Create `filterParameterCompletion` callback in DefaultCLI
1. Delegate to `completionNameParameterCompletion` for shared logic
1. Remove unused `@cliCompletion filter` tag (clarifies convention)
1. Document: TSCompletion uses naming convention, not tags

**Critical Learning:** TSCompletion parameter completion is **convention-based**: `{parameterName}ParameterCompletion`. Tags like `@cliCompletion` are NOT used by TSCompletion's completion lookup!

## **🎯 ACT**

### **Regression Analysis (REVISED after deep investigation)**

**What ACTUALLY Went Wrong:**
1. Changed parameter name: `completionName` → `filter`
1. **MISUNDERSTOOD** TSCompletion architecture: Thought `@cliCompletion` tags controlled lookup
1. **REALITY:** TSCompletion uses **convention-based naming** (`{parameterName}ParameterCompletion`)
1. No `filterParameterCompletion` callback → Fell back to file completion ❌

**Why It Happened:**
- Assumed `@cliCompletion` tags defined completion callback mappings
- Verified direct call works (which doesn't use TSCompletion)
- Did NOT understand TSCompletion's convention-based lookup logic (layer4/TSCompletion.ts:432)

**Critical Architecture Misunderstanding:**
> TSCompletion's parameter completion uses **naming convention**, NOT tags:
> ```typescript
> const completionMethodName = `${params[paramIndex]}ParameterCompletion`;
> ```
> Parameter named `filter` REQUIRES callback named `filterParameterCompletion`.
> Tags like `@cliCompletion filter someCallback` are IGNORED by TSCompletion!

### **Prevention Strategy**

**Checklist for CLI Method Parameter Rename:**
- [ ] Update `@param` tags
- [ ] Update `@cliSyntax` tag  
- [ ] Create `{newParameterName}ParameterCompletion` callback (convention-based!)
- [ ] Consider delegation if completion logic is shared
- [ ] Update `@cliExample` tags
- [ ] Test direct call
- [ ] **Test tab completion in bash shell**
- [ ] **Re-source `source.env` to reload completion functions**

**CMM4 Learning:**
> Understanding the architecture is crucial. TSCompletion's convention-based approach means parameter renames require creating matching completion callbacks, not just updating tags. **Convention over configuration!**
