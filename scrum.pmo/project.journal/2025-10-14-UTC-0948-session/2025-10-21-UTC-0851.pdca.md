
2. **Why .d.ts files don't have defaults:**
   ```typescript
   // Source file (src/ts/layer2/DefaultWeb4TSComponent.ts):

   ```

3. **Correct Path Resolution:**
   ```typescript
   // Current: dist/ts/layer4 → ../layer2 → dist/ts/layer2
   // Needed:  dist/ts/layer4 → ../../src/ts/layer2
   ```

## Do

### Implementation

```typescript
// components/Web4TSComponent/0.3.14.1/src/ts/layer4/TSCompletion.ts
// Lines 46-65

static getProjectSourceFiles(): string[] {
  const __dirname = path.dirname(new URL(import.meta.url).pathname);
  
  // ✅ FIX: Resolve to src/ts/ directory, not dist/ts/
  // When running from dist/ts/layer4/, we need to go: ../../../src/ts/
  // When running from src/ts/layer4/, we need to go: ../
  // Solution: Detect if we're in dist/ or src/ and adjust accordingly
  
  let srcBase: string;
  if (__dirname.includes('/dist/ts/')) {
    // Running from compiled code: dist/ts/layer4 → ../../../src/ts
    srcBase = path.resolve(__dirname, '../../../src/ts');
  } else {
    // Running directly from source: src/ts/layer4 → ../
    srcBase = path.resolve(__dirname, '..');
  }
  
  const dirs = [
    path.join(srcBase, 'layer1'),
    path.join(srcBase, 'layer2'),
    path.join(srcBase, 'layer3'),
    path.join(srcBase, 'layer5'),  // Scan CLI layer for component-specific completion methods
  ];
  
  let files: string[] = [];
  for (const dir of dirs) {
    if (existsSync(dir)) {
      files = files.concat(
        readdirSync(dir)
          .filter(f => f.endsWith('.ts'))
          .map(f => path.join(dir, f))
      );
    }
  }
  return files;
}
```

## Act

### Lessons Learned

1. **CMM1 Violation:** I made a false claim ("@cliDefault is a placebo") without verifying the complete data flow. The annotation WAS used in `extractDefaultValue()` for CLI syntax display.

2. **Incomplete Analysis:** I verified that `TSCompletion` prioritized TypeScript defaults but didn't verify that it was SUCCESSFULLY EXTRACTING them from source files.

3. **Path Resolution Complexity:** ESM `import.meta.url` resolution differs between source and compiled code. Must handle both cases explicitly.

4. **Declaration Files Are Lossy:** TypeScript `.d.ts` files strip parameter initializers, making them unsuitable for CLI metadata extraction.

5. **DRY Principle Restoration:** By fixing TSCompletion to read source files correctly, we eliminate the need for `@cliDefault` annotations entirely - TypeScript native defaults become the single source of truth.
