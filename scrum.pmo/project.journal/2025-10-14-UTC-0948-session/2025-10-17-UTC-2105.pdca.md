### **Root Cause Analysis**

The `completion()` method was trying to call `completeParameter` on ITSELF via shell, when it should just call it directly on the CLI instance or delegate to `web4ts.completeParameter()`.

But wait - `completeParameter` is on `DefaultCLI`, not `DefaultWeb4TSComponent`! So we need to call it on the CLI layer.

**Better Design:**
Since generated components extend `DefaultCLI` via their CLI layer, and `completion()` method needs to call `completeParameter`, it should just call `this.completeParameter()` if it's in the CLI, or delegate properly.

Actually, looking at the code structure:
- `completion()` is in `DefaultComponent` (template)
- `completeParameter()` is in `DefaultCLI`
- Generated component delegates to `web4ts` for non-CLI methods

**Solution:** The `completion()` method should delegate to `web4ts.completion()` which then calls its own CLI's `completeParameter`.

- Need to respect their version-specific implementation
- Shell isolation ensures clean execution context

- CLI is stateless for completion operations
- Clean instance ensures no state pollution
- Dynamic import allows lazy loading

- Context mode delegates to `web4ts.completion()` (DRY)
