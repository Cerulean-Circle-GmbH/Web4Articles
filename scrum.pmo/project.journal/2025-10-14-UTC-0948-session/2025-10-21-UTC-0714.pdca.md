## 📋 Plan

### Context
From [feature.oop.context.aware.completion.ideas.md](feature.oop.context.aware.completion.ideas.md):

**The Deterioration Problem:**
```typescript
/**
 * @cliDefault version current    // ← WTF? TypeScript already has = 'current'!
 */
async setCICDVersion(
  targetVersion: string,
  version: string = 'current'  // ← TypeScript native default
)
```

**What's Wrong:**
1. **Duplication:** `@cliDefault version current` duplicates TypeScript's `= 'current'`
2. **Two Sources of Truth:** Maintain both TS signature AND JSDoc
3. **Functional over OOP:** Annotations are stateless metadata, not context-aware code

**Current State:**
- `latest` → 0.3.14.1 (has all fixes)
- Working on 0.3.14.1 for continued development
- All @cliDefault annotations create duplication

### Objective
Change all `@cliDefault` to `@TODO cliDefault` to:
1. Disable the functional annotation pattern
2. Force reliance on TypeScript native defaults
3. Report changes in usage dialogue (make TODO visible)

### Approach
1. Find all @cliDefault annotations in 0.3.14.1
2. Change to @TODO cliDefault
3. Verify usage output shows the change
4. Document as step toward P0 (pure TypeScript native)

 */

  targetVersion: string,

**After:**
```typescript

 * @TODO cliDefault version current    // Disabled, marked as TODO
 */

  targetVersion: string,
  version: string = 'current'   // Single source of truth ✅
): Promise<this>
```

### Impact Analysis

**@TODO Prefix Effect:**
1. TSCompletion parser will NOT recognize `@TODO cliDefault` as `@cliDefault`
2. System will fall back to TypeScript native defaults (`= 'current'`)
3. Marks these annotations as technical debt to remove

**Duplication Eliminated:**
- Before: Default value in TWO places (annotation + TS signature)
- After: Default value in ONE place (TS signature only) ✅

**Consistency with OOP Principles:**
- Before: Stateless functional metadata
- After: Rely on TypeScript's native default system
