./web4tscomponent on Web4Programmer 0.1.0.1 completeParameter referencesParameterCompletion test itCase
```

**Error:**
```

- Method `resolveComponentPath` was added to master DefaultCLI after Web4Programmer creation

**Impact:**
- Cannot use `completeParameter referencesParameterCompletion test itCase` for listing
- Discovery workflow incomplete
- Users must use alternative: `test itCase <fileRef>` with argument

**Files Affected:**
- `src/ts/layer2/DefaultCLI.ts` (master has it)
- `components/Web4Programmer/0.1.0.1/src/ts/layer2/DefaultCLI.ts` (missing)

**Fix Strategy:**
1. Verify `resolveComponentPath` exists in master DefaultCLI
1. Add method to DefaultCLI if missing
1. Update templates with this method
1. Upgrade Web4Programmer to get latest

**Workaround:**
```bash

./web4tscomponent completeParameter referencesParameterCompletion test itCase

# Use:
./web4tscomponent test itCase 1a  # Requires file reference
```

## **Bug 2: `test itCase` Listing Mode Missing**

**Discovery Context:**
```bash
./web4tscomponent on Web4Programmer 0.1.0.1 test itCase
```

**Error:**
```
❌ Missing it case reference
💡 Usage: web4tscomponent test itCase <token> (e.g., 5a1)
❌ CLI Error: Missing references
```

**Expected Behavior:**
- `test file` without args → lists all files ✅
- `test describe` without args → lists all describe blocks ✅
- `test itCase` without args → should list all test cases ❌

**Current Behavior:**
- `test itCase` requires argument (e.g., `1a` or `1a1`)
- No listing mode available

**Impact:**
- Inconsistent UX - users expect listing mode
- Must provide file reference to see test cases
- Discovery workflow less intuitive

**Workaround:**
```bash
# Must provide file reference:
./web4tscomponent test itCase 1a  # Lists tests in file 1, describe a
```

**Fix Strategy:**
1. Add listing mode to `test itCase` method
1. When no args provided, list ALL test cases (like `test file` and `test describe`)
1. Maintain backward compatibility with `test itCase 1a` format

**Implementation Notes:**
- Check if `references` parameter is empty
- If empty, call `getTestItCaseReferences()` for all files
- Format output with proper hierarchy
