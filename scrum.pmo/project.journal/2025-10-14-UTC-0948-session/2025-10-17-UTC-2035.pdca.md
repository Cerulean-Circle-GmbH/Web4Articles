## **🎯 PLAN**

### **Context**

**User Observation:** After fixing the prod overwrite bug, user noticed:
1. `setCICDVersion` is `@cliHide` (correct)
1. `setLatest`, `setProd`, `setDev`, `setTest` are still CLI-exposed (wrong)
1. Should use `removeComponent` instead of manual `rm -rf`

**Current State:**
```bash
$ web4tscomponent completion method set
1: set <component> !<property> <version>
2: setCICDVersion    # ✅ Hidden (should not appear, but does in completion)
3: setDependencies !<dependencies>
4: setDev !<?targetVersion:'current'>      # ❌ Should be hidden
5: setLatest !<?targetVersion:'current'>   # ❌ Should be hidden
6: setProd !<?targetVersion:'current'>     # ❌ Should be hidden
7: setTargetDirectory !<directory>
8: setTest !<?targetVersion:'current'>     # ❌ Should be hidden
```

**Design Intent:**
- `setCICDVersion` is the intelligent, unified method (internal use only)
- Individual `set*` methods are deprecated in favor of smart CI/CD workflow
- Users should use `test` command for automatic intelligent promotion

### **Root Cause Analysis**

**Why are set* methods exposed?**
1. Lines 1257, 1309, 1330, 1351: All have `@cliSyntax` tags
1. `@cliSyntax` makes methods CLI-discoverable
1. These were needed before `setCICDVersion` existed
1. Now they create confusion and bypass build number semantics

### **Solution**

1. Add `@cliHide` to `setLatest`, `setProd`, `setDev`, `setTest`
1. Keep methods for backward compatibility (internal/programmatic use)
1. Document deprecation in TSDoc
1. Update tests that explicitly use these methods
1. Verify affected tests still pass
