private extractDefaultValue(param: any, methodName?: string): string | null {

  if (methodName) {

    if (cliAnnotations.default) {
      return cliAnnotations.default;
    }

  // ✅ CONVENTION: Common default values based on parameter type
  const description = param.description || '';
  
  if (description.includes('boolean')) {
    return 'false';

  if (description.includes('copy tracking') || description.includes('optional')) {
    return null; // Show as <?optional> rather than default
  }
  
  // No default value detected
  return null;
}

## 🎬 Act

### Conclusions

1. **TSCompletion Priority is CORRECT:** The core parameter extraction in `TSCompletion.ts` (Line 621) correctly prioritizes TypeScript signature defaults FIRST, using `@cliDefault` only as fallback.

1. **Most Code Uses Correct Values:** 5 out of 6 locations in `DefaultCLI.ts` correctly use `param.default` (which was populated by TSCompletion with correct priority).

1. **ONE LATENT BUG FOUND:** `generateParameterSyntax` (Line 1057) calls `extractDefaultValue` which re-evaluates `@cliDefault` directly, bypassing the correct `param.default` value. This could show WRONG defaults in CLI syntax if `@cliDefault` annotations were active.

1. **Currently Safe:** The bug is dormant because all `@cliDefault` annotations were changed to `@TODO cliDefault` (disabled), so `extractDefaultValue` returns `null`.

1. **DRY Violation:** `extractDefaultValue` duplicates the default value detection logic that TSCompletion already performs correctly. This violates the DRY principle.

### Recommendations

1. **P2 Fix (Low Priority):** Replace `this.extractDefaultValue(param, methodName)` with `param.default` in `generateParameterSyntax` (Line 1057). This would:
   - Eliminate the latent bug
   - Enforce DRY principle
   - Ensure consistent priority logic everywhere

1. **Document as Technical Debt:** Add to `feature.oop.context.aware.completion.ideas.md` as P2 cleanup item.

1. **Keep @TODO Annotations:** Don't remove `@TODO cliDefault` annotations yet - they serve as markers of eliminated technical debt.
