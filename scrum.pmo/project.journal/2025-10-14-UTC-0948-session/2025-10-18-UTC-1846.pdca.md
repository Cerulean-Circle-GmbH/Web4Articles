### **My Answer**
Understood. The issue was that TSCompletion was extracting `@cliDefault` annotations incorrectly by not passing the parameter name, causing it to extract the parameter name instead of the default value. Fixed by using `extractEnhancedJsDocText()` to get full JSDoc and passing `paramName` to `parseCliAnnotations()`. Also unified defaults across methods (both `upgrade()` and `releaseTest()` now use 'nextPatch') and added missing `@cliValues` annotations.

**Learning Applied:** Simple dynamic rules (if default is in enum, color it yellow) are better than complex hardcoded logic. TSDoc annotations must be read from source files, not compiled output. Consistency in defaults across methods prevents confusion.

## **🔧 DO**

**1. Fixed TSCompletion Default Value Extraction**

Changed line 519 in `TSCompletion.ts`:
```typescript
// OLD: const jsDoc = ts.getJSDocTags(m).map(tag => tag.comment).join(' ');
// NEW:
const jsDoc = TSCompletion.extractEnhancedJsDocText(m);
const cliAnnotations = TSCompletion.parseCliAnnotations(jsDoc, paramName);
```

**Reason:** `ts.getJSDocTags()` only returns tag comments, not full JSDoc text with `@cliDefault` annotations. `extractEnhancedJsDocText()` gets the complete JSDoc including all annotations.

**2. Fixed Quote Stripping from Default Values**

Added lines 525-530 in `TSCompletion.ts`:
```typescript
// Extract default value and strip quotes if present
let defaultValue = hasInitializer ? param.initializer.getText() : cliAnnotations.default;
if (defaultValue && typeof defaultValue === 'string') {
  // Strip surrounding quotes: 'value' or "value" → value
  defaultValue = defaultValue.replace(/^['"]|['"]$/g, '');
}
```

**Reason:** TypeScript AST returns `'nextPatch'` (with quotes) from source code, but we need `nextPatch` for comparison.

**3. Fixed Parameter Collection to Prefer Defaults**

Changed lines 786-795 in `DefaultCLI.ts`:
```typescript
if (!allParams.has(param.name)) {
  allParams.set(param.name, param);
} else {
  // ✅ FIX: If we already have this parameter, prefer the one WITH a default value
  const existing = allParams.get(param.name);
  if (param.default && !existing.default) {
    allParams.set(param.name, param);
  }
}
```

**Reason:** When multiple methods use same parameter (like `versionPromotion`), prefer the one with a default for documentation.

**4. Unified Method Defaults**

Added `@cliDefault` to `upgrade()` method (line 1173 in `DefaultWeb4TSComponent.ts`):
```typescript
* @cliSyntax versionPromotion
* @cliDefault versionPromotion nextPatch
* @cliValues versionPromotion nextPatch nextMinor nextMajor nextBuild
```

And signature (line 1176):
```typescript
async upgrade(versionPromotion: string = 'nextPatch'): Promise<this> {
```

**Reason:** Both `upgrade()` and `releaseTest()` now share the same default, eliminating ambiguity.

**5. Added Missing `@cliValues` Annotation**

Added to `create()` method (line 874 in `DefaultWeb4TSComponent.ts`):
```typescript
* @cliValues options all cli spec vitest layers
```

**Reason:** Without `@cliValues`, the system showed "Discovery Command" instead of actual enum values.

**6. Removed Test Scope Invalid Values**

Changed line 1596 in `DefaultWeb4TSComponent.ts`:
```typescript
// OLD: * @cliValues scope all file describe itCase
// NEW:
* @cliValues file describe itCase
```

**Reason:** User feedback: "should be only Possible Values: 'file', 'describe', 'itCase'"

**7. Fixed Wrong Enum Values for Multi-Parameter Methods**

Added check in `TSCompletion.ts` lines 673-682:
```typescript
// ✅ FIX: Check if first part is a DIFFERENT parameter name
const firstPartIsOtherParam = member.parameters.some(p => 
  p.name && ts.isIdentifier(p.name) && p.name.text === parts[0]
);

if (firstPartIsOtherParam) {
  // This @cliValues is for a different parameter, skip it
  continue;
}
```

**Reason:** For `tree(depth, showHidden)`, `@cliValues showHidden false true` was incorrectly being returned for `depth` parameter.
