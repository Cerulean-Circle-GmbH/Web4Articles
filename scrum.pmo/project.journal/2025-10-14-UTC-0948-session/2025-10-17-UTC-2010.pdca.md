**Current links() Method:**

**Current Behavior:**

async links(action: string = ''): Promise<this> {

**Enhanced Behavior:**
```typescript
async links(action: string = ''): Promise<this> {
  const context = this.getComponentContext();
  const componentName = context?.component || 'Web4TSComponent';
  
  if (action === 'repair') {
    await this.repairLinks(componentName);
  }
  
  // ✅ NEW: Verify prod link exists, create if missing
  if (action === 'verify' || action === 'fix' || action === 'verifyAndFix') {
    await this.verifyAndFixProdLink(componentName);
  }
  
  // Display links status
  // ...
}

/**
 * Verify prod link exists and points to valid version
 * Create if missing
 */
private async verifyAndFixProdLink(componentName: string): Promise<void> {
  const componentDir = this.resolveComponentDirectory(componentName);
  const prodLink = path.join(componentDir, 'prod');
  
  // Check if prod link exists
  if (!existsSync(prodLink)) {
    console.log(`⚠️  prod link missing for ${componentName}`);
    
    // Find highest stable version (not dev)
    const versions = readdirSync(componentDir)
      .filter(v => /^\d+\.\d+\.\d+\.\d+$/.test(v))
      .sort((a, b) => b.localeCompare(a, undefined, { numeric: true }));
    
    if (versions.length > 0) {
      const latestStableVersion = versions[0];
      console.log(`✅ Creating prod link → ${latestStableVersion}`);
      await this.on(componentName, latestStableVersion);
      await this.setProd();
    } else {
      console.log(`❌ No versions found for ${componentName}`);
    }
    return;
  }
  
  // Verify prod points to valid version
  const target = readlinkSync(prodLink);
  const targetPath = path.join(componentDir, target);
  
  if (!existsSync(targetPath)) {
    console.log(`❌ prod link broken: ${target} does not exist`);
    console.log(`🔧 Removing broken link...`);
    unlinkSync(prodLink);
    await this.verifyAndFixProdLink(componentName); // Recursive fix
  } else {
    console.log(`✅ prod link valid → ${target}`);
  }
}
```

**New Actions:**
- `links` - Show status (existing)
- `links repair` - Repair all broken links (existing)
- `links verify` - Check prod exists (NEW)
- `links fix` - Create prod if missing (NEW)
- `links verifyAndFix` - Both (NEW)

## **🎯 ACT**

### **QA Decisions**

1. **Q:** Should template use `prod/` or `latest/` for delegation?
   **A:** **PROD** - Latest can point to unstable dev version. Prod is always stable, tested, production-ready.

1. **Q:** When should prod link be created?
   **A:** **On component creation** - First version should be prod. Also verify/fix on `links verifyAndFix`.

1. **Q:** Should we always push after commit?
   **A:** **YES** - GitHub links in dual link format require push. Without push, documentation breaks.

1. **Q:** What if prod doesn't exist when template tries to import?
   **A:** **Component creation sets it** - New components get prod link immediately. Old components: `links verifyAndFix`.

1. **Q:** Should links() auto-fix by default or require action?
   **A:** **Require action** - `links` shows status, `links verifyAndFix` fixes. Explicit is better than implicit.

### **Lessons Learned**

1. **Dual Links Need Push:** GitHub URLs in documentation require pushed commits
1. **Stable Delegation:** Templates should use prod versions, not latest
1. **Complete Initialization:** Component creation must set all semantic links
1. **Verify Before Use:** Links method should check integrity
1. **Explicit Actions:** Auto-fix is dangerous, require explicit action
