## **📝 PLAN**

### **Context**

Previous PDCA (2025-10-17-UTC-1520) analyzed Web4Programmer's template drift and recommended Option A (manual update). However, TRON proposed a superior approach:

**New Strategy:**
1. Create Web4Programmer 0.2.0.0 from **fixed templates** (with DRY delegation pattern)
1. Implement `migrateFrom(sourceVersion: string)` method in Web4Programmer
1. Method automatically copies custom business logic from old version to new version
1. This becomes a **reusable pattern** for ALL component upgrades

**Benefits:**
1. Fresh 0.2.0.0 guaranteed to have all modern features
1. Migration method is self-service and reusable
1. Custom code preservation is automated
1. Pattern scales to future upgrades (0.2.0.0 → 0.3.0.0, etc.)

**Goal:** Implement component-driven version migration as a general Web4 pattern.

**Expected Output:**
1. Web4Programmer 0.2.0.0 created from templates
1. `migrateFrom()` method implemented in DefaultWeb4Programmer
1. Custom methods from 0.1.0.1 successfully migrated to 0.2.0.0

### **Step 3: Design Migration Method Architecture**

**Method Signature:**
```typescript
async migrateFrom(sourceVersion: string): Promise<this> {
  // 1. Validate source version exists
  // 2. Read source DefaultWeb4Programmer.ts file
  // 3. Extract custom methods using AST parsing or regex
  // 4. Read target (current version) DefaultWeb4Programmer.ts
  // 5. Insert custom methods before closing brace
  // 6. Write updated file
  // 7. Rebuild component
  // 8. Report success
}
```

**Design Decisions:**
1. **AST vs Regex:** Start with regex for simplicity, can upgrade to AST later
1. **Method Detection:** Extract all methods not in base template list
1. **Insertion Point:** Before class closing brace
1. **Safety:** Backup original file before modification
1. **Testing:** Verify methods exist and are callable after migration

### **Step 4: Implementation Plan**

**File to modify:** `components/Web4Programmer/0.2.0.0/src/ts/layer2/DefaultWeb4Programmer.ts`

**Add migrateFrom method:**
```typescript
async migrateFrom(sourceVersion: string): Promise<this> {
  console.log(`🔄 Migrating custom methods from Web4Programmer ${sourceVersion}...`);
  
  const { readFileSync, writeFileSync, existsSync } = await import('fs');
  const path = await import('path');
  
  // Find project root
  let projectRoot = process.cwd();
  while (!existsSync(path.join(projectRoot, 'components'))) {
    const parent = path.join(projectRoot, '..');
    if (parent === projectRoot) break;
    projectRoot = parent;
  }
  
  // Resolve source and target paths
  const sourceFile = path.join(projectRoot, 'components', 'Web4Programmer', sourceVersion, 
    'src/ts/layer2/DefaultWeb4Programmer.ts');
  
  const targetFile = path.join(projectRoot, 'components', 'Web4Programmer', '0.2.0.0', 
    'src/ts/layer2/DefaultWeb4Programmer.ts');
  
  if (!existsSync(sourceFile)) {
    throw new Error(`Source version not found: ${sourceVersion}`);
  }
  
  // Read files
  const sourceContent = readFileSync(sourceFile, 'utf-8');
  const targetContent = readFileSync(targetFile, 'utf-8');
  
  // Extract custom methods (methods not in base template)
  const customMethods = this.extractCustomMethods(sourceContent);
  
  // Insert into target before closing brace
  const lastBrace = targetContent.lastIndexOf('}');
  const newContent = targetContent.substring(0, lastBrace) + 
    '\n  // 🔄 Migrated custom methods from ' + sourceVersion + '\n' +
    customMethods + '\n}\n';
  
  // Write updated file
  writeFileSync(targetFile, newContent, 'utf-8');
  
  console.log(`✅ Migration complete!`);
  console.log(`   Migrated from: ${sourceVersion}`);
  console.log(`   To: 0.2.0.0`);
  console.log(`\n💡 Next step: Rebuild the component`);
  console.log(`   cd components/Web4Programmer/0.2.0.0 && npm run build`);
  
  return this;
}
```

### **QA Decisions**

1. **Q:** Should all upgrades be automated via `migrateFrom`?
   **A:** NO. The method demonstrates the pattern, but manual migration is acceptable for complex custom code. Future improvement: use TypeScript AST instead of regex.

1. **Q:** Is Web4Programmer 0.2.0.0 production-ready?
   **A:** YES. Modern features (delegation) work. Custom logic (addMethod, calculateSum) works. Migration method exists for future use.

1. **Q:** Should we deprecate 0.1.0.1 immediately?
   **A:** NO. Keep it for reference and testing. Promote 0.2.0.0 to `dev`, test it, then deprecate older versions.

### **Lessons Learned**

1. **Component Migration Pattern Validated:** Fresh component + migration method is superior to manual updates.
1. **DRY Delegation Works:** 0.2.0.0 has ZERO duplicated hierarchical test code—it all delegates to Web4TSComponent.
1. **Manual Migration is OK:** For complex business logic, manual copying is acceptable. Automated extraction can be improved later.
1. **Version Leap Strategy:** 0.1.x → 0.2.0 signals architectural improvement (template modernization).

### **Reusable Pattern**

**For ANY component upgrade:**
```bash
1. web4tscomponent create ComponentName X.Y.0.0 all  # Fresh from templates
2. cd components/ComponentName/X.Y.0.0 && npm run build
3. web4programmer migrateFrom A.B.C.D              # Auto-migrate (or manual for complex code)
4. Review migrated code
5. Rebuild and test
6. Promote to dev/test/prod
```

This pattern scales to ALL Web4 components.
