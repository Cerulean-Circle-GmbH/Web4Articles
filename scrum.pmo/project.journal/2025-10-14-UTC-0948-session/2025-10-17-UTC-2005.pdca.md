### **Step 1: TypeScript Import Feasibility**

**Question:** Can we import the same class twice with different aliases?

**Proposed Syntax:**
```typescript
import { DefaultWeb4TSComponent as Web4TSProd } from '../../../../../Web4TSComponent/prod/dist/ts/layer2/DefaultWeb4TSComponent.js';
import { DefaultWeb4TSComponent as Web4TSLatest } from '../../../../../Web4TSComponent/latest/dist/ts/layer2/DefaultWeb4TSComponent.js';
```

**Or:**
```typescript
import * as Web4TSProd from '../../../../../Web4TSComponent/prod/dist/ts/layer2/DefaultWeb4TSComponent.js';
import * as Web4TSLatest from '../../../../../Web4TSComponent/latest/dist/ts/layer2/DefaultWeb4TSComponent.js';
```

**TypeScript Answer:** ✅ **YES!** TypeScript allows this!

**Why it works:**
1. Each import is from a DIFFERENT file path
1. Aliases prevent naming conflicts
1. Each version compiles to separate JavaScript modules
1. Node.js module cache uses full path as key

### **Step 2: Design Proof-of-Concept**

**Test Component:** Create a test class that uses both versions

```typescript
import { DefaultWeb4TSComponent as Web4TSProd } from '../../../../../Web4TSComponent/prod/dist/ts/layer2/DefaultWeb4TSComponent.js';
import { DefaultWeb4TSComponent as Web4TSLatest } from '../../../../../Web4TSComponent/latest/dist/ts/layer2/DefaultWeb4TSComponent.js';

export class MultiVersionTest {
  private web4tsProd: Web4TSProd;
  private web4tsLatest: Web4TSLatest;
  
  constructor() {
    this.web4tsProd = new Web4TSProd();
    this.web4tsLatest = new Web4TSLatest();
  }
  
  async compareVersions(): Promise<void> {
    // Get versions
    const prodVersion = await this.getProdVersion();
    const latestVersion = await this.getLatestVersion();
    
    console.log(`🚀 Prod version:   ${prodVersion}`);
    console.log(`📦 Latest version: ${latestVersion}`);
    
    // Compare APIs
    const prodMethods = this.getPublicMethods(this.web4tsProd);
    const latestMethods = this.getPublicMethods(this.web4tsLatest);
    
    const newMethods = latestMethods.filter(m => !prodMethods.includes(m));
    const removedMethods = prodMethods.filter(m => !latestMethods.includes(m));
    
    console.log(`\n✨ New methods in latest: ${newMethods.length}`);
    if (newMethods.length > 0) {
      newMethods.forEach(m => console.log(`  + ${m}`));
    }
    
    console.log(`\n❌ Removed methods from prod: ${removedMethods.length}`);
    if (removedMethods.length > 0) {
      removedMethods.forEach(m => console.log(`  - ${m}`));
    }
  }
  
  async testBothVersions(): Promise<void> {
    console.log('🧪 Testing prod version...');
    await this.web4tsProd.tree('2');
    
    console.log('\n🧪 Testing latest version...');
    await this.web4tsLatest.tree('2');
    
    // Test method that might only exist in latest
    if (typeof this.web4tsLatest.links === 'function') {
      console.log('\n✅ Latest has links() method');
      await this.web4tsLatest.links();
    }
    
    // Check if prod has it
    if (typeof this.web4tsProd.links === 'function') {
      console.log('✅ Prod also has links() method');
    } else {
      console.log('⚠️  Prod does NOT have links() method');
    }
  }
  
  private getPublicMethods(obj: any): string[] {
    const methods: string[] = [];
    let current = obj;
    
    while (current) {
      Object.getOwnPropertyNames(current).forEach(name => {
        if (name !== 'constructor' && 
            typeof obj[name] === 'function' &&
            !name.startsWith('_') &&
            !methods.includes(name)) {
          methods.push(name);
        }
      });
      current = Object.getPrototypeOf(current);
    }
    
    return methods.sort();
  }
  
  private async getProdVersion(): Promise<string> {
    // Read version from prod's package.json
    return '0.3.13.0'; // Placeholder
  }
  
  private async getLatestVersion(): Promise<string> {
    return '0.3.13.2'; // Placeholder
  }
}
```

### **Step 3: Identify Potential Issues**

**Potential Conflicts:**

**1. Shared Dependencies:**
- ❓ If both versions use different versions of same dependency?
- ❓ Node.js will load both (different paths = different modules)
- ⚠️ Could cause version conflicts in shared state

**2. Type Compatibility:**
- ❓ Are `Web4TSProd` and `Web4TSLatest` compatible types?
- ❌ NO - TypeScript treats them as different types
- ⚠️ Cannot assign `Web4TSProd` to `Web4TSLatest` variable

**3. Memory Usage:**
- ⚠️ Two copies of similar code in memory
- ⚠️ Double the memory footprint
- ✅ Usually acceptable for testing/comparison

**4. Singleton Patterns:**
- ❌ Any singletons will exist twice (one per version)
- ⚠️ Could cause unexpected behavior
- ⚠️ Static properties are NOT shared

**5. File System Operations:**
- ✅ Each version operates independently
- ⚠️ Could conflict if both modify same files
- ⚠️ Need careful coordination

### **Step 5: Create Actual Test**

**Test File:** `components/Web4TSComponent/0.3.13.2/test/multi-version.test.ts`

```typescript
import { describe, it, expect } from 'vitest';
import { DefaultWeb4TSComponent as Web4TSProd } from '../../prod/dist/ts/layer2/DefaultWeb4TSComponent.js';
import { DefaultWeb4TSComponent as Web4TSLatest } from '../../latest/dist/ts/layer2/DefaultWeb4TSComponent.js';

describe('🔬 Multi-Version Instance Experiment', () => {
  it('should create two instances from different versions', async () => {
    const prod = new Web4TSProd();
    const latest = new Web4TSLatest();
    
    expect(prod).toBeInstanceOf(Web4TSProd);
    expect(latest).toBeInstanceOf(Web4TSLatest);
    expect(prod).not.toBe(latest);
  });
  
  it('should have different method availability', async () => {
    const prod = new Web4TSProd();
    const latest = new Web4TSLatest();
    
    // Both should have basic methods
    expect(typeof prod.build).toBe('function');
    expect(typeof latest.build).toBe('function');
    
    // Latest might have new methods
    const latestHasLinks = typeof latest.links === 'function';
    const prodHasLinks = typeof prod.links === 'function';
    
    if (latestHasLinks && !prodHasLinks) {
      console.log('✅ Latest has links(), prod does not - version difference detected!');
    }
  });
  
  it('should execute methods independently', async () => {
    const prod = new Web4TSProd();
    const latest = new Web4TSLatest();
    
    // Both should work independently
    await expect(async () => {
      await prod.on('Web4TSComponent', '0.3.13.0');
      await latest.on('Web4TSComponent', '0.3.13.2');
    }).not.toThrow();
  });
  
  it('should not share instance state', async () => {
    const prod = new Web4TSProd();
    const latest = new Web4TSLatest();
    
    await prod.on('ComponentA', '1.0.0.0');
    await latest.on('ComponentB', '2.0.0.0');
    
    // Each should maintain its own context
    const prodContext = (prod as any).model?.contextComponent;
    const latestContext = (latest as any).model?.contextComponent;
    
    expect(prodContext).not.toBe(latestContext);
  });
});
```

### **Step 6: Implementation in Template**

**Should we use multi-version in template?**

**Option A: Dual Version (Experimental):**
```typescript
import { DefaultWeb4TSComponent as Web4TSProd } from '../../../../../Web4TSComponent/prod/dist/ts/layer2/DefaultWeb4TSComponent.js';
import { DefaultWeb4TSComponent as Web4TSLatest } from '../../../../../Web4TSComponent/latest/dist/ts/layer2/DefaultWeb4TSComponent.js';

export class Default{{COMPONENT_NAME}} {
  private web4tsProd: Web4TSProd;
  private web4tsLatest: Web4TSLatest;
  
  constructor() {
    super();
    this.web4tsProd = new Web4TSProd();
    this.web4tsLatest = new Web4TSLatest();
  }
  
  async build(): Promise<this> {
    // Use stable prod version for critical operations
    await this.web4tsProd.build();
    return this;
  }
  
  async links(action: string = ''): Promise<this> {
    // Use latest for new features
    if (this.web4tsLatest.links) {
      await this.web4tsLatest.links(action);
    } else {
      console.log('⚠️  links() not available in latest version');
    }
    return this;
  }
}
```

**Option B: Single Version with Fallback:**
```typescript
import { DefaultWeb4TSComponent as Web4TSLatest } from '../../../../../Web4TSComponent/latest/dist/ts/layer2/DefaultWeb4TSComponent.js';

export class Default{{COMPONENT_NAME}} {
  private web4ts: Web4TSLatest;
  
  constructor() {
    super();
    this.web4ts = new Web4TSLatest();
  }
  
  async build(): Promise<this> {
    await this.web4ts.build();
    return this;
  }
}
```

**Recommendation:** **Option B** (single version) for production template

**Why?**
1. Simpler - no version management needed
1. Latest is symlink to prod after promotion
1. Only use multi-version for testing/comparison
1. Production should use stable version

### **QA Decisions**

1. **Q:** Is multi-version instance pattern viable in TypeScript?
   **A:** YES - TypeScript and Node.js fully support this via import aliasing and path-based module caching.

1. **Q:** Should we use dual-version in production template?
   **A:** NO - Use single version (latest). Multi-version is for testing/comparison only.

1. **Q:** What are the best use cases?
   **A:** Version comparison, migration testing, feature detection, gradual rollouts, A/B testing.

1. **Q:** What are the main risks?
   **A:** Memory overhead, dependency conflicts, type incompatibility, coordination complexity.

1. **Q:** Should we create the test file?
   **A:** YES - Add to test suite to document and verify the pattern works.

### **Lessons Learned**

1. **Import Aliasing is Powerful:** TypeScript's `as` syntax enables version coexistence
1. **Module Path = Module Identity:** Different paths = different modules in Node.js cache
1. **Type System Enforces Isolation:** TypeScript treats aliased versions as distinct types
1. **Use Case is Testing:** Multi-version is powerful for comparison, not production use
1. **Simplicity Wins:** Production should use single version (latest = prod after promotion)
