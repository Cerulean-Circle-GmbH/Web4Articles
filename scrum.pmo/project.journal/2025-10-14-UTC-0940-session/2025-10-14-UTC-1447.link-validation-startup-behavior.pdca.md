**Step 1: Agent reads README or startup instructions**
```

```

**Current Behavior:**
- Agent MAY click/read the link

- Agent ASSUMES link content is correct
- Agent DOES NOT verify link works
- Agent PROCEEDS with startup

**Step 2: Checklist references more documents**
```
Checklist says: "Template version 3.2.4.2: [link to template.md]"
Checklist says: "Read howto.PDCA.md: [link]"
```

**Current Behavior:**

- Agent RARELY reads second-level links
- Agent ALMOST NEVER reads third-level links
- Agent ASSUMES all links are valid
- Agent DOES NOT test if links work

**Critical Gap Identified:**
❌ **No systematic link validation during startup**
❌ **No verification that instruction links are accessible**
❌ **No reporting when links are broken**
❌ **No depth strategy for recursive document reading**

### **4. Reading Depth Strategy Analysis**

**Question: How deep should an agent read linked documents?**

**Current Reality (Shallow Reading):**
```
Level 0: Startup document (README)
  → Level 1: CMM3 Checklist [reads surface]
    → Level 2: Template.md [MAY read]
      → Level 3: Template references [RARELY reads]
        → Level 4: Deep references [NEVER reads]
```

**Agent Behavior Pattern:**
- **Depth 0 (Start):** Always reads (entry point)
- **Depth 1:** Usually reads (direct references)
- **Depth 2:** Sometimes reads (secondary references)
- **Depth 3+:** Rarely reads (too deep, assumes)

**Problem with Shallow Reading:**
- Critical information may be at depth 2-3
- Agent misses important context
- Broken links at depth 2+ never detected
- Knowledge gaps emerge as violations later

**Ideal Reading Depth:**
- **Mission-critical docs:** Read fully, all levels
- **Referenced protocols:** Read at least depth 2
- **Optional references:** Read depth 1, note for later
- **All links:** VALIDATE work, report broken ones

### **5. Link Validation Protocol Design**

**Proposed: Startup Link Validation Protocol**

**Phase 1: Instruction Document Link Validation**
```bash
For each instruction document (README, Checklist, etc.):
  1. Extract all links from document
  2. Test each link (file exists? accessible?)
  3. Report broken links immediately
  4. STOP if critical links are broken
  5. WAIT for TRON to fix before proceeding
```

**Phase 2: Recursive Reading with Validation**
```bash
For each working link (up to depth N):
  1. Read linked document
  2. Extract links from that document
  3. Test those links (next level)
  4. Report broken links immediately
  5. Continue or stop based on criticality
```

**Phase 3: Validation Report**
```bash
At startup completion:
  Report:
  - Total links found: X
  - Working links: Y
  - Broken links: Z (list them)
  - Reading depth achieved: N
  - Knowledge gaps: (docs not accessible)
```

When a new agent starts and reads instruction documents:
1. **No link validation** - agent doesn't test if links work

3. **Silent failure** - broken links don't trigger error reports
4. **Hallucinated knowledge** - agent assumes broken doc content
5. **Delayed violations** - problems emerge during work, not startup

**TRON's Insight Applied:**
- **Broken link = immediate error signal** ✅
- **Should trigger: "Cannot access X, link broken"** ✅
- **Should NOT trigger: silent assumption** ❌ (current behavior)
- **Correct response: STOP and ASK** ✅

**The Startup Protocol Should Be:**
```
1. Read instruction document
2. Extract all links
3. TEST each link (file exists?)
4. IF broken → REPORT immediately and STOP
5. IF working → Read and validate recursively
6. Continue only when all critical links validated
```

**Option C: Recursive Reading with Depth Limit (Comprehensive)**

### **🎯 Root Cause of Violation 4b (Revealed):**

**Why Links Are Broken:**
- Instruction documents reference other docs
- Those docs moved/renamed/restructured
- Links not updated (no validation at commit)
- New agents read instructions with broken links
- Agents don't validate, so break propagates
- Violations emerge during work

**Why This Wasn't Caught:**
- **No startup link validation** (agents don't test)
- **No commit-time link validation** (no CI check)
- **No systematic link maintenance** (drift over time)

**Systemic Fix Required:**
1. **Startup:** Validate links before work (detect)
2. **Commit:** Validate links before push (prevent)
3. **Maintenance:** Regular link audit (sustain)
