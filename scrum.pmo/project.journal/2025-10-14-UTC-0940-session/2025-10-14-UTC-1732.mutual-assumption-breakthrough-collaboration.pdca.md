**MANDATORY IMPROVEMENTS TO STARTUP PROCESS:**

**A) Link Format Verification Protocol (MUST DO)**

Add to CMM3 Checklist Section 7c or create new 7d:

```markdown
**7d) Link Format Requirement (MANDATORY):**

When reading documents to depth 3, ALL file references must use proper dual link format:
- GitHub link: Full URL to file
- Local link: Relative path in [text](path) markdown syntax

VERIFICATION STEPS (MANDATORY):
1. Read document completely
2. Identify ALL file references (grep for filenames)
3. For EACH reference, verify:
   a) Has proper [text](path) markdown link syntax
   b) Path is correct from document's location
   c) File exists at that path (ls -la test)
   d) Is wrapped in dual link format when appropriate

NEVER accept plain text filenames as "references":
❌ BAD: "PDCA.understanding.CMMI.md (193 lines)"
✅ GOOD: "[PDCA.understanding.CMMI.md](../../path/to/file.md) (193 lines)"

If document has plain text filenames: Convert to proper markdown links before marking as "read"
```

**B) Document Format Compliance Check (MUST DO)**

Add to startup reading checklist:

```bash
# After reading each document, run:
cd $(dirname document.md)
grep -n '\.md\|\.sh' document.md | grep -v '\[.*\](.*\.' | grep -v 'GitHub' > /tmp/plain_filenames.txt

if [ -s /tmp/plain_filenames.txt ]; then
    echo "❌ Found plain text filenames - need markdown link conversion:"
    cat /tmp/plain_filenames.txt
    exit 1
else
    echo "✅ All filenames properly formatted as markdown links"
fi
```
