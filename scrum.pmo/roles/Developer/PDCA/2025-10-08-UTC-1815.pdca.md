## 🎯 Problem

### ❌ What Went Wrong
Generated components (`DemoComponent`, etc.) experienced infinite recursion when running `npm test`:
1. `npm test` → `test.sh` → `./democomponent test` (TypeScript)
2. TypeScript `test()` → delegates to `web4tscomponent on DemoComponent 0.1.0.0 test`
3. `web4tscomponent` → calls `test()` on the component
4. **INFINITE LOOP** - no recursion prevention

### 🔍 Root Cause
**MISUNDERSTANDING OF REQUIREMENTS:**
- I incorrectly thought generated components should be "simple" (just run vitest)
- I incorrectly thought only Web4TSComponent should have promotion logic
- **WRONG!** Generated components ARE Web4 components and MUST auto-promote

**TECHNICAL ROOT CAUSE (PROVEN BY AUTOMATED TEST):**
- Generated component CLI scripts have HARDCODED absolute paths
- Example: `COMPONENT_PATH="$PROJECT_ROOT/components/ComponentName/0.1.0.0"`
- This breaks in `test/data` directory (test isolation)
- Web4TSComponent itself is location-resilient, but generated components are NOT
- **FIX 1:** Generated components need location-resilient CLI scripts like Web4TSComponent ✅
- **FIX 2:** Generated components call `web4tscomponent` but it works in wrong directory
- **WRONG SOLUTION:** Use environment variables (violates Web4 OOP principles)
- **CORRECT SOLUTION:** Generated components need to instantiate Web4TSComponent programmatically with `setTargetDirectory()`
- **PRINCIPLE:** Web4 is OOP - use objects, methods, and scenarios, NOT environment variables or global state

### 📋 Requirements (FINAL TRUTH)
1. **ALL Web4 components auto-promote** (Web4TSComponent, DemoComponent, any generated component)
2. **`npm test` ALWAYS triggers promotion** for ANY component
3. Generated components have THE SAME promotion feature as Web4TSComponent
4. Web4TSComponent creates components that test themselves and promote themselves
5. **NO RECURSION** - must detect and prevent infinite loops
6. **NO ENVIRONMENT VARIABLES** - Web4 is OOP, not procedural! Use model/scenario configuration ONLY
7. **NO GLOBAL STATE** - All configuration via object methods (chainable)
8. **NO PROCEDURAL PATTERNS** - Everything is object-oriented, scenario-based
9. **NEVER ASSUME - PROVE OR ASK** (CMM3) - No assumptions about test success, verify with test-results.json
10. **Generated components MUST have SAME config as Web4TSComponent** - vitest.config.ts with reporters

### 🔄 Recursion Prevention Strategy

**The Problem:**
- Component's `test()` method needs to run vitest AND handle promotion
- But vitest runs the component's tests which may call `test()` again
- Need to break the cycle

**The Solution:**
1. **Detect test environment:** Check if already running under vitest (`process.env.VITEST`)
2. **Split responsibilities:**
   - If NOT in vitest: Handle promotion workflow, then run vitest
   - If IN vitest: Just run vitest (test code path)

**Implementation Pattern:**
```typescript
async test(): Promise<this> {
  // Recursion prevention: If already in vitest, just run tests
  if (process.env.VITEST) {
    console.log(`🧪 Running {{COMPONENT_NAME}} tests (via vitest)...`);
    const { execSync } = await import('child_process');
    execSync('npx vitest run', { stdio: 'inherit' });
    return this;
  }
  
  // NOT in vitest: Handle promotion workflow
  console.log(`🧪 Running {{COMPONENT_NAME}} test with promotion workflow...`);
  
  // 1. Determine promotion stage based on semantic links
  // 2. Execute promotion logic
  // 3. Run vitest (which sets VITEST env var, preventing recursion)
  // 4. Verify test results
  // 5. Update symlinks if needed
  
  return this;
}
```

## 🔧 Act: Implementation

### 📝 Fix 1: Update Generated Component Template

**File:** `templates/ts/DefaultComponent.ts.template`

```typescript
async test(): Promise<this> {
  // Recursion prevention
  if (process.env.VITEST) {
    console.log(`🧪 Running {{COMPONENT_NAME}} tests (via vitest)...`);
    const { execSync } = await import('child_process');
    execSync('npx vitest run', { stdio: 'inherit' });
    return this;
  }

  console.log(`🧪 Running {{COMPONENT_NAME}} test with auto-promotion...`);
  
  // Get current version and semantic links
  const packageJson = JSON.parse(readFileSync('./package.json', 'utf-8'));
  const currentVersion = packageJson.version;
  const semanticLinks = await this.getSemanticLinks();
  
  // Determine and execute promotion stage
  await this.determinePromotionStage(currentVersion, semanticLinks);
  
  // Run vitest (VITEST env var prevents recursion)
  execSync('npx vitest run', { stdio: 'inherit' });
  
  return this;
}
```
